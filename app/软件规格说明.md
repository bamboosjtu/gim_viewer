# GIM Viewer Mobile（线路版）软件规格说明书 v1.0

**状态：开发基线**
**目标平台：Android**
**首要真机：vivo X Fold5**
**测试补充：Android Studio Emulator**
**产品范围：输电线路 GIM，不包含变电站**

# 1. 产品定位

GIM Viewer Mobile 不是桌面版 GIM Viewer 的简单缩屏版本，而是面向输电线路现场使用的轻量工程空间工具。

核心目标是：

> 打开线路 GIM 后，将工程结构、杆塔、档、跨越物和当前位置统一投影到地图，使用户能够在现场快速完成“找对象—看位置—看属性—看塔形—判断距离”。

v1 的核心价值不是三维浏览，而是：

**GIM 工程对象 + GIS 空间位置 + 现场人员位置。**

未来再通过插件接入施工进度、站班会、项目部等外部业务数据。

# 2. v1 产品边界

## 2.1 支持范围

v1 正式支持：

- Android 10 及以上；
- `GIMPKGT` 输电线路包；
- 已验证的道亨系线路 GIM 方言；
- 220kV、500kV；
- 单回、双回、单双回混合；
- 整线工程；
- π 接、改接、短线段工程；
- 在线天地图；
- OSM 在线 fallback；
- 无底图 Canvas 工程图 fallback；
- Android 当前定位；
- HNum 杆塔二维骨架预览。

六个现有样本覆盖不同规模和工程形态，且容器、层级和核心挂接机制保持一致。

F2～F4 的业务键和结构在六个样本中高度稳定，可以作为当前线路 Domain Model 的直接依据。

## 2.2 不属于 v1

v1 不实现：

- 变电站 `GIMPKGS`；
- IFC；
- 线路全三维场景；
- STL 杆塔三维浏览；
- 导线真实悬链线；
- 离线地图下载；
- 路线导航；
- 后台持续定位；
- 用户账号；
- 云同步；
- 服务端；
- 遥测；
- DCP 数据接入；
- 站班会、进度、项目部信息。

这些不是删除，而是明确留到后续插件阶段。

# 4. Android Native 边界

移动版继续使用 Tauri，但 Android 特有能力通过薄 Native Plugin 实现。

## 4.1 GIM 文件导入插件

Android 文件选择结果是 `content://` URI，不能沿用桌面版“得到路径以后直接 `fs::open()`”的模型。

新增：

```
gim-import Android Plugin
```

职责：

```
Android SAF
   ↓
content:// URI
   ↓
ContentResolver InputStream
   ↓
流式复制
   ↓
App private storage
   ↓
返回：
localPath
displayName
size
sha256
```

不得：

- 将整个 GIM 文件读入 JS ArrayBuffer 后再传给 Rust；
- 为了导入文件申请整个存储空间访问权限；
- 将文件复制到公共目录。

这样可以减少 WebView 内存占用，并服务于 10 秒冷导入目标。

## 4.2 定位

采用 Tauri Geolocation Plugin。

只申请：

- `ACCESS_COARSE_LOCATION`
- `ACCESS_FINE_LOCATION`

v1 使用**前台主动定位**：

```
用户点击定位
   ↓
检查权限
   ↓
请求当前位置
   ↓
显示用户位置
   ↓
若已有目标塔
   ↓
计算当前位置 ↔ 目标塔距离
```

不做后台定位，不保存位置历史，不上传位置。

## 4.3 窗口、安全区与沉浸地图

普通页面使用 edge-to-edge：Android content/WebView 不设置系统栏 padding，页面背景
铺满窗口。Android 原生提供单一 WindowInsets 来源，转换为 CSS 像素；Header 内容、底部
导航内容、浮动控件和对话框避让状态栏、导航栏/任务栏与刘海，`#app` 不设置全局安全区 padding。
Header 内容区为 52 CSS px，蓝色背景覆盖状态栏区域，控件仍避让状态栏。

地图工具栏将“显示完整工程”（范围/相机）与“进入/退出沉浸地图”（窗口模式）分开。
沉浸地图占据整个窗口，临时隐藏树、属性面板、底部导航，保留项目标题与设置/退出控件；
使用 `WindowInsetsControllerCompat` 隐藏 systemBars，允许边缘滑动临时唤回系统栏。
返回键退出全屏；进入设置、工程管理/导入或离开前台恢复普通系统栏。折叠/旋转保留地图
视角、选择和面板偏好，全屏状态不写入工程偏好。普通页面不自动启用沉浸模式。

Android 当前最小屏宽小于 600dp 时固定竖屏，覆盖手机与折叠外屏；展开屏/平板解除方向限制。
沉浸地图选择对象后，左下方显示可关闭的概览浮层，沿用详情页同一字段来源并随选择更新，
不挤占地图、不加载隐藏详情的塔形。浮层采用紧凑标签/值布局：窄屏（<600 CSS px）单列，每行左侧标签、右侧数值；较宽窗口双列，长关系占整行。关闭和查看详情保留 44 CSS px 点击区域。右侧地图工具仍可操作；“查看详情”退出沉浸并打开对象概览。

# 5. 工程导入与“我的工程”

## FR-IMPORT-01

用户可以通过 Android 系统文件选择器选择 `.gim` 文件。

## FR-IMPORT-02

导入后必须计算 SHA-256。

同一 SHA-256 已存在时：

> 提示“该工程已经导入”，直接进入现有工程，不重复解压和建库。

## FR-IMPORT-03

原始 GIM 必须保存在 App 私有目录。

数据结构：

```
projects/
  <project-id>/
    source/
      original.gim

    cache/
      project.sqlite
      semantic/
      previews/

    metadata.json
```

用户删除工程时同时删除：

- 原始 GIM；
- SQLite；
- semantic cache；
- HNum preview cache；
- 其他项目派生文件。

## FR-IMPORT-04

导入过程必须显示加载界面。

不能只有一个无限旋转 spinner，应显示阶段：

```
正在导入文件
正在识别 GIM
正在解包
正在解析工程结构
正在建立杆塔与档索引
正在保存缓存
正在准备地图
```

已知文件数或字节数时显示确定进度；未知阶段允许 indeterminate 状态。

UI 主线程不得因解析发生长时间无响应。

# 6. GIM 解析规则

当前线路解析策略正式固化为 Mobile v1 的兼容性契约。

## 6.1 层级

```
Project
  ↓
F1 System
  ↓
F2 System        线路
  ↓
F3 System        耐张段
  ↓
F4 System
  ├─ TOWER       杆塔
  ├─ WIRE        线
  └─ CROSS       跨越
```

六样本均保持这一层级和挂接键体系。

## 6.2 强制兼容规则

解析器必须：

- `ENTITYNAME` 大小写不敏感；
- 内部路径大小写不敏感；
- `/`、`\` 统一；
- MOD 判型前移除 UTF-8 BOM；
- DEV/FAM 关系以 `BASEFAMILY` 引用为准；
- 禁止假设 DEV 和 FAM 同名；
- GROUP/F4 使用 UUID 去重；
- 能识别边界塔重复引用；
- 能识别 line03 类型的 jumper 双计；
- `GROUPTYPE` 分派 TOWER/WIRE/CROSS；
- 未知字段保留原始值，不直接丢弃；
- 未知键形成 diagnostic warning，而不是工程加载失败。

line03 已证明 DEV/FAM 文件名可以完全不同，因此文件 stem 不能承担关联语义。

## 6.3 属性可信度

以下字段作为“源属性”展示，但不得作为结构约束：

- 回路数；
- 杆塔基数；
- 线路长度。

真实工程结构以引用图和几何事实为准。

例如样本中已出现：

- 长度为 0；
- 属性长度和实际几何长度相差数倍；
- 回路数为 0；
- 杆塔基数与实际对象数不一致。

因此移动版同时展示：

```
源属性长度
几何重建长度
```

当差异明显时显示：

> GIM 源属性与空间几何不一致

但不能阻断查看。

# 7. Mobile Domain Model

不要让 UI 直接处理数千个原始 CBM 节点。

在 `GimGraph` 上增加移动端通用业务投影：

```
LineProject
LineSection
StrainSection
Tower
PhysicalSpan
Crossing
RawWire
```

## Tower

至少包含：

```
id
sourcePath
number
towerType
nominalHeight
blha
elevation
azimuth
strainSections[]
sourceRefs[]
towerShapeRef?
```

杆塔坐标只使用 TOWER F4 的 `BLHA` 作为主坐标。

六样本中的塔位 BLHA 已表现出高度稳定性。

## PhysicalSpan

`PhysicalSpan` 不等于一个 WIRE。

一档可能同时存在：

- 三相或多相导线；
- OPGW；
- 普通地线；
- 双回路导线；
- 分裂导线。

因此：

```
多个 RawWire
      ↓
POINT0 / POINT1 空间挂点去重
      ↓
PhysicalSpan
```

`PhysicalSpan` 至少包含：

```
id
startTower?
endTower?
startCoord
endCoord
horizontalLength
strainSection
rawWireIds[]
conductors[]
groundWires[]
opgw[]
sourceRefs[]
```

## Crossing

每一处实际 CROSS 对象均建立独立 Crossing。

若 F4 CROSS 本身为空：

- 保留为 source diagnostic；
- 不伪造“跨越物”。

# 8. 工程树

这里明确取消任何“N001–N050 分页”。

## 8.1 逻辑要求

工程树必须能够访问：

- 每条线路；
- 每个耐张段；
- 每基杆塔；
- 每个物理档；
- 每处跨越。

数据永远完整。

若对象很多，只允许使用：

> Virtual List / Virtual Tree

即只渲染当前屏幕附近的行，但数据模型中不存在分页。

## 8.2 两种导航视图

建议提供：

### 结构

```
工程
 └─ 线路
     └─ 耐张段
         ├─ 杆塔
         ├─ 档
         └─ 跨越
```

保持原 GIM 业务层级和原引用顺序。

边界塔被两个耐张段引用时，两处可以出现同一对象的“引用节点”，但必须指向同一个 Tower ID，不得复制成两基塔。

### 对象

提供筛选：

```
全部
杆塔
档
跨越
```

对象模式按**唯一物理对象**展示。

# 9. 地图

## 9.1 地图技术

v1 使用：

```
MapLibre GL JS
       +
GIM Engineering Overlay
```

不使用 MapLibre Native。

原因是工程 Overlay 在业务去重后主要是：

- 数十～数百个杆塔；
- 数十～数百个物理档；
- 数量有限的跨越物。

没有必要为了该规模引入 Android Native Map 与 WebView 的双渲染体系。

## 9.2 天地图

默认底图：

> 天地图影像 + 注记。

设置中允许配置：

```
天地图 API Key
```

配置成功后提供：

- 影像；
- 矢量；
- 地形。

默认：**影像**。

API Key：

- 只保存在 App 私有设置；
- 不写日志；
- 不提交 Git；
- 不进入 crash diagnostics。

## 9.3 fallback

固定降级链：

```
天地图
   ↓ 失败
OSM
   ↓ 失败
Canvas-only
```

无天地图 API Key 时：

```
直接使用 OSM
```

并在地图设置处提示：

> 未配置天地图 API Key，当前使用 OpenStreetMap。

Canvas-only 仍必须完整支持：

- 塔；
- 档；
- 跨越物；
- 当前选中对象；
- 用户当前位置；
- 点击命中；
- fit project bounds。

即：

> 底图失败不能导致 GIM 工程不可用。

OSM 公共 tile 服务只能做交互式在线 fallback，不得实现批量预取或离线下载，并必须显示 attribution。

# 13. 杆塔形状预览

v1 正式支持 HNum 杆塔形状预览。

不作为 debug/source 功能处理。

流程：

```
Tower
 ↓
TOWER_DEVICE
 ↓
DEV
 ↓
PHM
 ↓
HNum MOD
 ↓
TowerShape
 ↓
SVG
```

预览采用：

> X/Z 二维正投影骨架。

P 点号全文件唯一时，预览可跨 Body 连接文件尾部 R 杆件；点号重复时仅在当前 Body 内解析。
几何范围由实际 P/R 决定，不按 H 段高截断。预览缓存采用独立版本，升级后自动重建，不要求重新导入工程。

保留：

- 点；
- 杆件；
- 等比例；
- 缩放；
- 平移；
- 重置视图。

不要求：

- 3D；
- 材质；
- 真实钢材截面；
- STL。

几何模板必须缓存。

因为不同塔实例可以复用同一 TOWER 模板。line02 中 129 基塔仅对应 26 个 TOWER 类型模板，是明确的模板复用关系。

缓存键：

```
source SHA
+
HNum MOD identity
+
preview parser version
```

找不到 HNum 时：

> 暂无可预览的杆塔形状

仍正常显示杆塔和全部属性。

不得把缺失 HNum 当作工程错误。

地图显示：

```

  ±12 m
```

```
经度
纬度
定位精度
定位时间
```

```

# 20. 性能指标

## P0-01 冷导入

基准工程：

> line02 或当前样本中规模最大的线路工程。

line02 解包后约 22,640 个文件、96.52 MB，是当前六样本最适合作为移动端压力基线的样本。

在 vivo X Fold5 上：

> **冷导入 ≤ 10 秒。**

计时起点：

> Android 文件选择器返回用户选择结果。

计时终点：

> 工程树可以交互 + Canvas 工程地图可交互。

包括：

- URI → 私有目录复制；
- SHA；
- header inspection；
- extraction；
- parser；
- Domain Projection；
- SQLite transaction；
- 首次工程 Overlay。

**不包含互联网底图下载时间。**

因此弱网络不能令性能测试失败。

## P0-02 缓存打开

已有合法缓存：

> **≤ 3 秒。**

起点：

> 用户点击“我的工程”中的工程。

终点：

> 工程树 + 工程 Overlay 可交互。

## P0-03 UI 响应

解析期间：

- Loading 动画不得冻结；
- Android 不得出现 ANR；
- UI 主线程不得承担大规模解包；
- parser 优先 Worker；
- Rust/Kotlin 原生 IO 不经 JS 大对象复制。

# 22. OSM 使用限制

OSM 是 fallback，不是项目自己的地图基础设施。

禁止：

- 后台瓦片下载；
- 大范围预取；
- 离线地图打包；
- 扫描式请求。

必须显示：

> © OpenStreetMap contributors

并遵守服务缓存策略。OSM 官方明确指出公共 tile server 无 SLA，也不允许 bulk/offline 下载。

如未来用户规模扩大，应替换为：

- 合规 OSM provider；
- 企业地图服务；
- 自建瓦片。

不能把 `tile.openstreetmap.org` 当成企业级 SLA 服务。

# 23. Android SDK

建议：

```

```

Android 当前大屏和折叠设备越来越强调 resizable/adaptive app；API 36 同时也是 2026 年 Google Play 的当前目标 API 基线。

首版虽然不进应用商店，也应直接按现代 Android target 构建，避免随后重新处理适配问题。

# 32. 长期方向

v1 完成后不立即做线路三维。

优先顺序应是：

```

        ↓

        ↓
外部业务 Plugin API
        ↓
DCP 施工进度
        ↓

        ↓

最终目标不是：

> 手机看 GIM 文件。
