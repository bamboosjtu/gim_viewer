# gim_element —— 简易实体识别工具

把一座变电 GIM 工程（`.gim` 包或已解包目录）里的全部对象，盘成 **设备 / 装置性材料 / 构件 / 其他** 四本账，并给出目录编码、证据状态与来源文件。

统一构建参数、产物约定、安全边界及 Windows 排查见 [tools 总览](../README.md)。

- 桌面版：`dist/GIM实体盘点器.exe`（PySide6 + PyInstaller 单文件，免安装）
- 命令行：`python element_core.py <路径> --html/--json/--csv`
- 分类标准：同目录 `01-分类与粒度总则.md`、`02-设备目录与组合边界.md`、`03-材料与构件目录.md`

口径上只认「工程上能整体识别、能单独列项」的实体，**不按 F2/F3/F4 层级、不按 CBM/DEV 拆件**决定粒度。

---

## 1. 快速开始

1. 双击 `dist/GIM实体盘点器.exe`（每次启动先把运行时解压到临时目录，数秒；系统缓存后再次启动更快）。
2. `Ctrl+O` 选 `.gim` 文件或已解包目录（也可直接拖进窗口）。
3. 右上树按 `组 → 类别 → 子类 → 名称模板` 展开；右下显示该分类下的名称实例（名称、轨道、状态、IFC 类型、来源文件）。
4. 选中右下任一实例，**左侧属性面板**显示它的全部属性：实例（名称/轨道/状态/IFC 类型/来源文件）、归属（分组/编码/标准类别/子类/名称模板）、模板统计（两轨计数/合计/状态分布/主要来源）。
5. 四组盘点数在**底部状态栏**：设备/材料/构件/其他，悬停可看来源文件数与两轨明细。
6. `Ctrl+E` 导出 HTML 报告，菜单「文件」另有 CSV / JSON。`F1` 查看内置口径说明。

界面里所有顺序都按目录编码走（设备 `E01→E19→E-T`，材料 `M01→M09`，构件 `C-A1…C-D6`，其他 `U-*`），不按数量排序。

## 2. 命令行

```bash
# 只看统计
python element_core.py "D:/工程/xxx.gim"

# 同时导出三种报告
python element_core.py "D:/工程/xxx.gim" --html 报告.html --json 台账.json --csv 台账.csv
```

输出示例（substation01，2026-11-03 构建）：

```
===== 盘点结果 =====
设备        : 420 台（已确认 420 · 候选 0；dev 385 + ifc 41；附件 6 并入本体、部件 0 上卷）
装置性材料　 : 810（dev 111 + ifc 699；已确认 810 · 候选 0 · 未确认 0）
构件　　　　 : 2,556（dev 0 + ifc 2,556；已确认 2,556 · 候选 0 · 未确认 0）
其他　　　　 : 1,998（dev 0 + ifc 1,998；已确认 0 · 候选 0 · 未确认 1,998）
```

设备的「台数」是去重后的台数（附件并入本体、部件上卷），与 `dev + ifc` 的来源条数不必相等；材料与构件按件/段计，不做跨组相加。

四种输入容器都支持：`GIMPKG` 系列头（`GIMPKGS` / `GIMPKGT`）、裸 7z、zip；解包到临时目录后解析，默认用完清理。

## 3. 四组与编码

| 组 | 编码 | 范围 |
|---|---|---|
| 设备 | `E01–E19`、`E-T` | 按《通用设备目录》2018 + 2025 并集 19 类：主变、站用变、GIS、断路器、隔离开关、开关柜、电容器、电抗器、互感器、避雷器、二次设备、动力辅助、水工暖通…；只有「变压器」而无用途证据落 `E-T` 候选 |
| 装置性材料 | `M01–M09` | 造价口径的施工散材 9 大类：导线、母线、金具、绝缘子、电缆、接地材料、套管、槽盒、其他材料；金具/绝缘子/接地/套管/槽盒再分子类 |
| 构件 | `C-A1…C-D6` | 4 大类 28 子类：`C-A` 建筑本体、`C-B` 结构构架与基础、`C-C` 水工与总图、`C-D` 附属设施（照明/消防/安防/暖通/给排水/其他） |
| 其他 | `U-*` | 不是工程实体的东西：空间骨架 `U-SPACE`、型号模板 `U-TYPE`、尺寸占位 `U-SIZE`、端口与系统 `U-PORT`、无名称产品 `U-NONAME`、同名异物 `U-EXCL`、紧固件内部来源 `U-INTERNAL`、中性点待归 `U-PENDING`、组织包装 `U-ORG`；词域外统一 `U-OBJECT` |

每条记录带状态三态：**已确认**（名称命中专属词条）、**候选**（只有型号 / 用途待定 `E-T` / 仅靠 DEV.TYPE 兜底）、**未确认**（词域外、无名称、占位名）。状态只反映目录映射的证据强度，与来源轨道无关。

## 4. 判定要点

- **两条轨道**：`dev` 走 `CBM → OBJECTMODELPOINTER → DEV`；`ifc` 只认暴露层（空间骨架 + 产品实体），几何/属性/材料/样式等内部表达封装成一条总数。两轨分别计数、互补不合并，明细表里标出来源。
- **设备与层级无关**：一台设备可能横跨多个 F4，也可能只是一个 F4 里的一个 DEV；变压器 = 本体 + 散热器 + 中性点成套装置，中性点装置虽自带 `.dev` 仍并入主变、不单独计台。
- **二次设备**：主变保护柜、测控柜、智能柜、电能表柜归 `E16`（细分 端子箱 / 蓄电池 / 控制柜 / 屏柜），不算主变附件。
- **箱柜与终端**：端子箱、检修箱、配电箱、照明箱、动力箱、电缆终端属设备；即使只在 `PARTINDEX`(PI) 层出现也释放为设备。
- **材料实例**：F4 与 PI 两层都计，散材件数按实例累计。
- **构件部件**：灯端子板、接线盒、支架立柱等并入父件，不单独计量。
- **紧固件**：螺栓/螺母/垫圈不新建实体，记「内部来源」；只有词域外时降级，`独立基础地脚螺栓` 这类仍按构件计。
- **同名异物**：`电缆隧道`、`母线支架`、`导线线夹` 等名字里带类别词但不是该类的，落 `U-EXCL`，不混进材料。
- **宿主不明不充数**：中性点成套装置若找不到所属主变，进「待归整体」`U-PENDING`，不挂在主变名下凑数。

## 5. 代码结构

| 文件 | 职责 |
|---|---|
| `element_core.py` | 解析核心（无 UI 依赖）：容器识别与解包、`DevTrack`（dev 轨道）、`scan_ifc_track`、`Ledger`（台账聚合）、`scan()`、`build_html()`、CLI |
| `devtype_class.py` | **词表唯一真源**：`three_way()` 依次判 设备 → 材料 → 构件 → 词域外；含设备 19 类、材料 9 大类及子类、构件 4 大类 28 子类、`EXCL` 同名异物表、型号代号兜底（LW/GW/JW…） |
| `entity_std.py` | 标准化层：目录编码 `code_of()`、E16 细分 `dev_sub()`、状态 `status_of()`、排序 `order_key()`、紧固件与 `E-T` 判定 |
| `element_app.py` | 桌面外壳：树表、明细表、KPI 卡、搜索、导出、`--smoke` 自检 |
| `01/02/03-*.md` | 分类与粒度总则、设备目录与组合边界、材料与构件目录（改口径先改这三份，再改词表） |

数据流：`unpack → DevTrack(...)`（构造即扫 CBM 树）/ `scan_ifc_track()` → `Ledger.add(track, group, cat, sub, …)` → `Ledger.to_rows()` 出 rows + totals → `build_html()` 或 GUI 树表。

## 6. 构建与自检

Windows x64 使用 Python 3.12，项目依赖固定在 `requirements-build.txt`。QtCore、QtGui、QtWidgets 使用 PySide6-Essentials，不需要 WebEngine/Addons。打包 spec 为工具根目录的 `element.spec` 并随源码提交，采用 PyInstaller 单文件（onefile）配置；公共目录 `catalog.json` 通过 spec 的 datas 打进 exe，运行时从 `sys._MEIPASS` 读取。此 Qt 构建使用 Windows 原生 ICU API；spec 排除从 Poppler/Conda 等 PATH 环境误收集的同名 ICU DLL，避免打包后 QtCore 报“找不到指定的程序”。

从工具目录执行 PowerShell：

```powershell
.\build.ps1
```

脚本通过 `../build-common.ps1` 创建工具自己的 `.venv`、安装依赖，再通过该解释器的模块入口调用 PyInstaller，不依赖全局 `pyinstaller` 命令或 PATH。已安装项目环境时可使用 `.\build.ps1 -SkipInstall`。

等价的手动入口：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --workpath ./_build --distpath ./dist element.spec
```

产物为单个 `dist/GIM实体盘点器.exe`，可直接拷走，不再生成 `_internal` 目录。`build.ps1` 暂存旧产物，打包后检查 `dist` 中只有一个 exe，通过 `verify_package.py` 确认归档内嵌 `catalog.json`、没有误收集的 ICU DLL，再实际运行 `--self-check`；全部成功后删除旧产物，失败时保留备份。

冒烟测试可从独立输出目录运行源程序或打包 EXE 的 `--smoke <gim或解包目录> <png>`。无显示测试设置 `QT_QPA_PLATFORM=offscreen`；成功生成截图并退出，失败以非零状态退出且不弹解析错误对话框。测试偏好写入当前目录的 smoke-settings.ini，不改用户正式偏好；截图旁写入 `.png.json` 回执。

运行 `.\.venv\Scripts\python.exe .\smoke_packaged.py` 可用自动生成的 GIM/7z 夹具验证冻结 EXE、内嵌 `catalog.json`（按归档内容比对 SHA-256）、Qt 平台插件、四类盘点和中性点附件口径。

## 7. 已知边界

- **样本代表性**：口径在 4 个变电样本（2018/2025 两版包、两个导出器方言）上验证，不代表所有 GIM 方言；新包先看「其他」组占比再定。
- **基础归属**：样本里没有 `IfcFooting`，设备基础与建筑物基础只能按名称证据三分（`C-B2` / `C-B3` / `C-B4 未分`），无证据不硬分。
- **构造模型偏大的包**：ProStructures 类模型（如 substation02）构件会到万级，主要是板/型钢逐件暴露，属真实暴露量，不是重复计数；`substation03` 的代理构件（`代理构件` 占名）统一落「其他」，不计构件。
- **看不见的东西**：IFC 内部表达、CBM 装配内部件只计封装总数，不列明细；需要逐件几何用 `gim_device` / `gim_info`。
- **材料件数 ≠ 台数**：设备按台，材料与构件按件/段，跨组不做汇总相加。

## 共享产品目录

编码与标签读取仓库的 `desktop/src/engineering/catalog.json`，通过桌面目录检查脚本与生成文档做一致性校验。参考工具继续使用自己的名称优先与聚合台账策略；不能用其桶计数校准桌面 occurrence/成员/实体数量，主变内部端子箱与独立端子箱也按各自明确边界对照。

重新构建 PyInstaller 包时，spec 的 `datas` 必须将上述共享 JSON 以 `catalog.json` 放入打包根目录（`sys._MEIPASS`）。普通源码运行从仓库读取；缺少目录数据直接报错，不回退到另一份硬编码标签。
