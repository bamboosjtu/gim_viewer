# GIM 指针类型谱系

> 依据：教程《线路GIM文件拆解》PPT / `tutorial.py`、Q/GDW 11809—2023 §6.2、
> 六份线路样本与四厂商变电样本研究成果。
> 本文件是 `gim_info/ptr_kinds.py` 的设计说明；**分类以 `ptr_kinds.py` 代码为唯一真源**。

## 1. 结论：一共有多少种

「多少种」必须先定口径，否则数字每次都不一样（教程 P29 第 4 条铁律）：

| 口径 | 数量 | 内容 |
| --- | --- | --- |
| **教程口径**（PPT P22、Step 8） | **3 大类** | 层级边 / 模型指针 / 属性指针 |
| **标准口径**（§6.2 a~f 引用关系） | **6 条** | 几何模型、phm 引用、dev/ifc 物理模型、cbm 组装、逻辑模型、根文件 |
| **工程实现口径**（本文件） | **4 组 9 种** | 3 大类展开 + 研究成果补出的「扩展」组，见下表 |
| 键名族口径（仅 s01 实测） | 33 个 | `BASEFAMILY` / `SOLIDMODELn` / `SUBDEVICEn` / `FILEn.DEVn` … 随方言变化，不作为分类 |

**答案：设计上要区分的是 9 种语义类型**（`L1 L2 M G A I U S D`），归到 4 组：

- 教程的 3 组：`层级`（L1/L2）、`模型`（M/G）、`属性`（A）；
- 研究成果补的第 4 组 `扩展`：IFC 轨（I/U）、逻辑模型（S）、材料与出图（D）。

其中 **7 种以「值 = 目标文件名」出现，可跳转**；`U`（IFC 实体标识）与 `D`（材料/出图占位）
**不是文件指针**，浏览器按「标识键」标注，不做成链接，也不会被算成悬空。

## 2. 依据链：3 类是怎么长成 9 种的

1. **教程 P13/P15/P22/P29**：「指针的本质：属性的值，就是下一个文件名」；三种指针各管一段路——
   层级往下（779 条）、模型换目录（343 条）、属性旁挂（547 条）。判据只看
   **值以 `.cbm/.dev/.fam` 结尾且键不以 `.NUM` 结尾**，不按 UUID、不按同名猜。
2. **Q/GDW 11809—2023 §6.2 a~f**（原文）：a 几何模型 `*.mod/*.stl`；b `*.phm`
   引用一个或多个 mod/stl，可同级引用；c 物理模型 `*.dev`/`*.ifc`，dev 引用 phm 与 fam，
   **可同级引用**，变电土建以 ifc 描述；d `*.cbm` 引用本层 fam 与**补充材料单 `*.xml`**，
   可同级引用；e 逻辑模型由 fam 引用的**逻辑描述文件**（`*.icd/ipd/cpd`）配置生成；
   f `project.cbm` 根引用全站组装模型。
   → 教程的「模型指针」实际是两段（cbm→dev、dev→phm→mod/stl），并允许同级引用；
   标准还写了教程样本里全为空或全为零的 xml / 逻辑 / IFC 轨。
3. **研究成果**（详见 §7 依据清单）：变电四样本的 IFC 挂接方式分化（逐实体直指 /
   F1 文件级整挂）、PARTINDEX 树外索引、FileDevRelation 出图 provenance、
   SUBLOGICALMODEL 逻辑容器、MATERIALSHEET 六样本 6/6 出现且全为空。
   → 同为 `cbm→cbm` 的边，有的是工程层级，有的是树外索引，混为一类会把遍历树画错；
   而 `IFCGUID` 根本不是文件名，必须单独标注。

## 3. 九种类型详表

| 码 | 类型 | 组 | 键名族 | 源 → 目标 | 依据 | s01 实测 |
| --- | --- | --- | --- | --- | --- | --- |
| L1 | 层级下钻 | 层级 | `SUBSYSTEM` / `SUBSYSTEMn` / `SECTIONn` / `STRAINSECTIONn` / `GROUPn` / `TOWER0` / `BASEn` / `STRINGn` / `BACKSTRING` / `FRONTSTRING` | cbm → cbm（F1~F4 + 部件叶） | 教程 P13/P22；§6.2f、§7.1/7.2；线路六样本键族谱 | 4,805 |
| L2 | 树外索引 | 层级 | `SUBDEVICEn`→PARTINDEX / `PARTINDEX` / `FILEn.DEVn` | cbm → cbm（PARTINDEX 节点 / 出图清单映射） | 变电研究 11.2、11.7；解耦研究 §5.1 | 8,539 |
| M | 模型锚点 | 模型 | `OBJECTMODELPOINTER` | cbm → dev | 教程 P15/P22；§6.2c | 4,179 |
| G | 几何装配 | 模型 | `SOLIDMODELn` / `SUBDEVICEn`（源为 dev/phm） | dev → dev/phm，phm → phm/mod/stl | 教程 P17/Step10④；§6.2a~c | 14,011 |
| A | 属性族 | 属性 | `BASEFAMILY` / `BASEFAMILY1..n` | cbm / dev → fam | 教程 P16/Step 9；§6.2c/d | 13,313 |
| I | IFC 挂接 | 扩展 | `IFCFILE` / `IFCn` / `FILEn.IFC` | cbm → ifc | §6.2c；变电四样本 IFC 挂接方式对比 | 4,384 |
| U | IFC 实体标识 | 扩展 | `IFCGUID` | cbm → IFC 文件内部实体（22 位 GUID） | 同上（s01 逐实体直指） | 标识键 4,645 |
| S | 逻辑模型 | 扩展 | `SCH` / `SUBLOGICALMODELn` / `LOGICALMODEL*` / `逻辑描述文件` | project.cbm / fam → sch、sld、std、icd、ipd、cpd、逻辑 cbm | §6.2e；Bentley 2.2、BIMBase 研究 | 3（另 116 条占位标识） |
| D | 材料与出图 | 扩展 | `MATERIALSHEET` / `FILEn.NAME` / 其它资料后缀 | cbm → xml / DGN（占位或包外） | §6.2d；六样本稳定性分析；变电研究 11.7 | 标识键 184 |

### 3.1 为什么 L1 与 L2 必须分开

同为 `cbm→cbm`、值同样是 UUID 文件名，但目标语义完全不同：

- L1 目标 `ENTITYNAME=F1System…F4System/TOWER_DEVICE`，是**工程层级树的父子边**；
- L2 目标 `ENTITYNAME=PARTINDEX`（s01 实测 3,894 条），或来自 `FileDevRelation.cbm`
  的 `FILEn.DEVn`（4,645 条映射回 F4），是**树外索引 / 出图清单**，不参与层级下钻。

Bentley 方言把 PARTINDEX 做成独立 cbm 节点（1,349 个），s01 是 F4 上的字段；
两者都靠 `SUBDEVICEn` 引用，但都不在 `SUBSYSTEM` 主链上。混进 L1 会把
「一个 F4 有多少部件」算成「层级又多了一层」。

### 3.2 为什么 M 与 G 必须分开

教程把 `cbm→dev→phm→mod/stl` 统称「模型指针」，但实现上这是两种边：

- M 只出现在 cbm，键唯一 `OBJECTMODELPOINTER`，是**跨目录第一跳**；
- G 出现在 dev/phm，键带序号且可同级引用（`dev→dev`、`phm→phm`），
  与 `TRANSFORMMATRIXn`/`COLORn` 同下标配对。

方言差异（教程 Step 10 坑④）：变电 Dev 用 `SUBDEVICEn→.dev`，线路 Dev 用
`SOLIDMODELn→.dev/.phm`，照搬一种键名会一条也找不到。

### 3.3 为什么 I 与 U 必须分开

s01 是**逐实体直指**：每个 F4 同时写 `IFCFILE=xxx.ifc` 与 `IFCGUID=22 位 GUID`，
前者是文件名（可跳），后者是 IFC 内部实体标识（**不可跳**）。
s02/s03 是**文件级整挂**：F1 上 `IFC.NUM=17` + `IFC0..16`，树内零 IFCGUID。
线路六样本该类型全为 0。把 IFCGUID 当文件指针会批量产生假悬空。

## 4. 两类「不是链接」的指针

| 类型 | 键 | 实测形态 | 界面处理 |
| --- | --- | --- | --- |
| U | `IFCGUID` | s01 4,645 条，值形如 `3IkIXpOtfAOw9VSEpBZvgb` | 琥珀色，tooltip 说明「指向 IFC 内部实体」，不生成链接 |
| D | `MATERIALSHEET` / `FILEn.NAME` | s01 160 + 24 = 184 条；前者全为空，后者是 DGN 图号名 | 灰色，tooltip 说明「占位 / 包外资料」，不生成链接 |
| S | `逻辑描述文件`（fam 内） | s01 116 条，值多为 `/` 占位 | 紫色，tooltip 说明「逻辑描述文件占位」，不生成链接 |

`MATERIALSHEET` 与 `逻辑描述文件` 若**值非空且目标文件存在**，仍可跳（走 D/S 类），
不是硬编码禁用；判据始终是「值是否像一个文件名」。

## 5. 三类「看着像、其实不是」的排除项

| 排除项 | 典型键 | 为什么不是指针 |
| --- | --- | --- |
| 计数键 | `*.NUM`：`SUBSYSTEMS.NUM` / `GROUPS.NUM` / `SOLIDMODELS.NUM` / `IFC.NUM` | 值是个数；数量为 0 时字段仍要输出，「有键无值」≠「没这个键」（教程 P11） |
| 配套参数 | `TRANSFORMMATRIXn` / `COLORn` / `BLHA` / `PARTNAME` / `SYSCLASSIFYNAME` | 与 `SOLIDMODELn` 同下标的位姿、颜色、地理锚点，是这条边的属性，不是另一条边 |
| 同名伴生 | dev↔fam 同 UUID、mod↔gl 同 UUID、F1↔fam 同 UUID | 导出端命名习惯。line03 的 dev 与 fam 完全异名仍 1,344/1,344 全可达，配对只能看 `BASEFAMILY` |

## 6. 实测对照（全部 0 悬空）

| 样本 | 文件 | 指针 | L1 | L2 | M | G | A | I | S | 标识键 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **line04（教程样本）** | 1,394 | 9,511 | **779** | 0 | **343** | 7,842 | **547** | 0 | 0 | 3 |
| s01（JinQu 变电） | 36,112 | 49,234 | 4,805 | 8,539 | 4,179 | 14,011 | 13,313 | 4,384 | 3 | 4,945 |
| s03（BIMBase 变电） | 9,203 | 8,522 | 197 | 386 | 386 | 6,666 | 871 | 16 | 0 | 44 |

**教程数字完全复现**：PPT P22 的 `779 / 343 / 547` 分别落在 L1 / M / A 三类；
另多出的 7,842 条是教程归入「模型链」但未单列的 G 类几何装配。
line04 的 I / S / L2 全为 0，正好说明「教程 3 类」在纯线路方言里已经够用；
变电样本才需要扩展组。s01 的 3 条 S 类为 `project.cbm → project.sch → zjx.std/zjx.sld`，
是以前只认七种模型后缀时被整体漏掉的一族。

## 8. 在 `gim_info` 里怎么区分（设计落点）

| 位置 | 做法 |
| --- | --- |
| `ptr_kinds.py` | 唯一真源：`PTR_KINDS` 9 种 + `classify()` + 3 类排除项 + 自检用例 |
| `gimbrowse.Ptr` | 每条指针带 `kind` / `type_name` / `group`；`markers()` 单独收非跳转标识键 |
| `gimbrowse.edges()` | 出边关系列写**细分类型名**（不再笼统写「层级/模型/属性」），保证属性表里每个链接在链上都有边 |
| `gimbrowse.check()` | 体检增加 `按类型` / `按大类` / `标识按类型` 统计 |
| 属性表 | 仍是「键 / 值」两列；值列按类型着色 + 下划线即链接，tooltip 给键名族、指向与标准依据；标识键灰色且不可点 |
| 顶部徽标 | 当前文件按类型的彩色计数，一眼看出这个文件挂了哪几类指针 |
| 工具栏 | 「指针」下拉按 9 种类型过滤属性表；「类型谱系…」弹出完整对照表（非模态，可边看边点） |
| 引用链树 / CSV | 第二列、导出列都写细分类型名；CSV 另加「大类」列，按链下载时可分类型筛 |
