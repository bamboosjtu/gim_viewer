本轮起点为 `4eeeb35`，沿用 GIM 浏览器的普通 L0/L1 与显式 L2 策略。目标是把选择延迟及大站长尾拆成可检验的局部问题。性能数字只适用于下述条件，不将局部收益写成整站或点击指标已经达标。

控制包源码指纹 `08de100b8ac0bada80499cdea4a195f6f1d2addd9be8ea87c6e7f63b6e58ca8d`、EXE SHA-256 `624cf0451fc107c9df4fbd02b230e24d3b15a986df78920bb0cd53a5d1de6ad2`，仅在起点上增加导航分段。候选包源码指纹 `1f1ff58688d9c6c76c6f8baded58768798ce59873748dff4cee0a9c1cf32e148`、EXE SHA-256 `970b3ee7c428b43fdd6439de3b679324b2ab86b78692a7af7dc044a5b49a9cbd`，增加导入 Promise 复用及批读调整。二者均为 Windows 原生 Release，固定运行时 SHA-256 相同，为 `d45c88e28d71af69bca5e179bf27531fa599ec2a7ecd220ac6fb92f522a5a8b6`；通过独立应用标识及实际数据库路径校验，不操作日常缓存。

## 导航分段

在现有有界 `selection.navigation` 下增加 `imports`、`tree`、`sldLookup`、`sldCommit`，均关联原 SelectionRequest；旧请求和工程代次守卫保留。导入段是墙钟等待，不是模块 CPU 执行时间。四段加上外层跨度可能重叠，不累计为工程耗时。

基线使用独立原生 Release，DEV 实例化关闭，在 substation02 搜索并顺序选择同样的三个导线来源：

| 操作 | 导入等待 | 树同步 | 单线图查询 / 提交 | 导航总墙钟 |
|---|---:|---:|---:|---:|
| 第一次 | 209.0 ms | 0.3 ms | 0 / 0.2 ms | 210.3 ms |
| 第二次 | 32.9 ms | 2.2 ms | 0 / 0 ms | 35.8 ms |
| 第三次 | 157.5 ms | 0.6 ms | 0 / 0 ms | 159.2 ms |

功能域索引原已缓存，增加第二份索引缺少依据。候选只复用第一次成功导入的 Promise；模块不捕获工程或选择状态，每次完成仍检查当前请求，失败的导入不永久占住缓存。首次导入等待仍需如实记录，不能宣称首次点击已经消除等待。

原始基线位于本地 `output/acceptance/stations/2026-10-23T04-59-59.275Z/`。该会话使用已清理验收 profile 的副本，属于缓存恢复交互检查，不是正式冷暖启动。

候选使用同一原始 profile 的另一副本、同样三个来源及顺序，原始记录位于 `output/acceptance/stations/2026-10-23T05-20-52.072Z/`。第一次导入完成等待为 150.6 ms，后两次均低于本次计时分辨率；导航总墙钟分别为 152.2、36.5、26.7 ms，树同步为 0.4、1.5、1.8 ms。首请求仍有等待，第二次总墙钟与基线相近，不能只展示第三次下降或用三个样本宣布点选 p95 达标。当前 imports 在 Promise 的 finally 回调结束，调用方继续执行前仍可能有调度间隙，外层总墙钟还包含这些间隙及记录开销，不能用四个内层跨度解释全部时间。

为了分离模块重入与 UI/相机工作，在同一候选原生场景中，从该构建产物提取实际导航导入工厂及 Vite 预加载辅助入口，对已加载模块执行 100 组交替查询。两侧模块命名空间身份全部相同，没有调用树、属性、选择或相机函数。重新调用导入工厂的等待中位数/p95 为 169.8/181.5 ms、最大 198.1 ms；复用同一成功 Promise 的 p95 低于计时分辨率、最大约 0.1 ms。此证据支持保留模块 Promise 复用，代表重复进入模块加载链的局部成本，不代表 GPU 呈现或输入排队。探针及汇总位于该目录的 `r2-navigation-import-probe.json`、`r2-navigation-import-summary.json`。

真实选择未增加 L2 编译；最后一次属性 owner、当前请求和高亮 occurrence 一致，诊断浮层结束后 loading 为 none。关闭工程并结束所属原生进程，cleanupComplete 为 true。完整快速切换、已缓存摘要与点击到呈现的门槛仍待独立验收。

## 原生派生缓存批读

源码确认 DEV 模板及目录缓存在原生文件中；SQLite 用于项目源身份校验，不能将整个缓存读写时间称作 SQLite 执行时间。原生入口已允许最多 64 条、按输出字节上限返回；桥接层原先继续拆成 16 条顺序调用。

在工程关闭后的同一原生空闲首页，对 64 个绑定 B1-1 源 SHA 的有效缺失键执行 100 组交替顺序对照。所有返回路径和未命中状态一致，没有写入探针缓存。首批 20 组发现尖峰后追加 80 组，并保留全部记录，不剔除首批：

| 每次原生调用条目数 | 64 条逻辑请求的调用数 | 中位数 | p95 | p99 | 最大值 |
|---|---:|---:|---:|---:|---:|
| 16 | 4 | 61.15 ms | 81.5 ms | 105.2 ms | 115.9 ms |
| 64 | 1 | 41.45 ms | 54.5 ms | 58.6 ms | 289.6 ms |

中位数及 p95 约改善 32% / 33%；64 条路线仍有一次较大的尖峰，不能声称改善所有尾部。原生总处理时间的中位数约 42.55 / 35.71 ms，说明收益同时来自减少往返和重复路径/身份准备；不将差值全部归于 SQLite。

候选把条目批次与原生 64 条上限对齐，同时让一个逻辑请求的所有分批、失败拆分共享剩余字节上限。原先每个 16 条子调用都能重新取得完整上限，不能保证逻辑批次累计仍受原上限约束。新路径预算耗尽后返回 deferred，未命中、无效和读取错误继续分别保留，不改持久化格式、键或缓存版本。

微基准位于 `output/acceptance/stations/2026-10-23T05-03-06.981Z/r2-cache-miss-probe-20.json`、`r2-cache-miss-probe.json` 与汇总 JSON。它是原生文件缓存未命中查询的局部证据，不代表暖命中解析、大文件传输或整站加载时间。

## 大站准入与输出消费

对照使用 B1-1、同一语义及解压源缓存、同一个已清理 IFC profile 的两个副本；仅将独立验收根下的 `device-lod/2` 分别移走并保留备份，使两侧 DEV 模板和目录均为空。源 SHA 及实际原生数据库路径校验保留。这是“语义/IFC 可恢复、DEV 派生缓存为空”的恢复场景，不是首次冷启动，也不是完整暖启动。

窗口固定为首次出现 DEV 状态后的前 180 秒，按 1 秒左右的实际采样边界取最后一条，不插值；最终完成时间未在此窗口验收。控制侧原始记录位于 `output/acceptance/stations/2026-10-23T05-03-06.981Z/`。

控制侧在约 179.23 秒窗口末显示 5625 个 occurrence，完成 226 个 L0 模板编译，失败 0；152 个采样中约 72.4% 的未消费输出计数为 0。提交队列一度达到 2807 项，但后续可自行排空。导出的编译 Worker 内部读取 RPC 单项最大约 29.9 秒，primitive 最大约 17.6 ms；它们属于不同阶段，不能相加。当前暖语义路径不会执行首次冷源的批量预取，缺少派生缓存时会走逐源 IPC。

因此“输出队列满导致这段窗口主要停滞”的前置假设不成立；扩大结果缓冲或直接提高 Worker 数量缺少依据，本轮未引入该类改动。现有计算槽释放、消费确认和预算结算继续保持。缓存批读只针对其中的派生缓存查询成本，不声称解决逐源读取长尾。

## 保留、未实施及验收边界

保留导航 Promise 复用、四段诊断，以及 64 条缓存批读和逻辑批次共享字节上限；两条实现都有独立局部对照。功能树再增加一份缓存、扩大输出缓冲和提高 Worker 数量，没有本轮证据支持，未进入实现；不把未执行的路线包装成失败 A/B，也不以此断言它们在所有工程都不可行。本轮没有需要保留的无收益候选实现或临时产品开关。

仍未完成的是派生缓存缺失恢复时的逐源读取，以及全站完成时间、内存、固定路线与点击端到端门槛。本轮没有修改源预取策略、Worker 池、生产 SQLite 逻辑或缓存版本。当前长期状态与未关闭验收仍以 [性能基线](../performance.md) 和 [问题清单](../open-issues.md) 为准。
