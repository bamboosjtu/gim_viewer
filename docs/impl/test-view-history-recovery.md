# 上一视角的状态结算与失败恢复

## 判定与收益

保留本轮视角历史修复。收益是浏览动作的正确性与可恢复性：快速返回不再跳过最近视角；相机恢复失败后，历史仍可重试；重复返回、工程清空及新的导航/可见性动作不再被旧返回任务错误结算。

基于 substation01–04 的真实 L0 子集及 CBM 放置矩阵，每站选取三个不同设备位置，使用实际 CameraControls 执行七类定向场景，三轮交替基线/候选。候选共 84 项通过，基线在这些专门复现缺陷的场景中均未满足预期。这是定向缺陷复现集合，不是产品总体成功率；没有测量或宣称 FPS、启动、内存或原生点击延迟收益。

本轮只处理“上一视角”的状态、失败恢复与导航结算，不将整个性能计划或状态/恢复方向标记为完成。[问题清单](../open-issues.md)中原生隔离、加载反馈、几何故障和输入响应验收继续保留。

## 复现问题与实现

基线 [viewHistory](../../desktop/src/viewer/viewHistory.ts) 使用 220 ms 相机更新防抖，返回前直接弹出当前历史并立即恢复可见性。实测存在以下问题：

| 场景 | 基线行为 | 候选行为 |
|---|---|---|
| 初次 A→B 后立即返回 | 记录窗口内没有可用返回入口，直接调用也返回 false | 入口识别待记录移动，返回前结算 B，回到 A |
| A、B 已记录，移到 C 后立即返回 | 尚未记录 C，弹出 B 后跳到 A | 先结算 C，准确返回 B |
| 相机恢复抛错 | 历史已弹出，筛选也已改变，后续不能重试同一步 | 成功后才消耗历史和恢复筛选；失败回滚，保留重试入口 |
| 返回过程中再次返回 | 两个请求连续弹出历史，跳过一层 | 当前恢复期间忽略重复请求 |
| 工程 clear 时仍有返回动画 | 旧目标继续生效，旧 Promise 仍可返回成功 | 冻结当前相机，立即结算取消；代次守卫拒绝旧完成 |
| 新导航覆盖旧返回 | 相机已经到了新位置，旧返回仍报告成功且提前改过筛选 | 核对当前目的地与筛选，保留新动作，不消耗旧历史 |
| 返回过程中用户修改筛选 | 新筛选本身保留，但旧历史已消耗，下一步返回丢失 B | 保留新筛选与 B 的历史，下一步仍能返回 B |

候选沿用最多 20 个快照及 220 ms 普通记录防抖。只有用户主动返回时结算待记录的目的地；恢复中不产生额外相机历史。快照读取 CameraControls 的目的地值，避免恢复动画阻尼尾部生成伪历史；位置/目标按 1 微米容差去除球坐标往返舍入差，仅用于导航去重，不用于模型几何或测量。

返回操作拥有独立取消入口。手动相机控制开始、clear 和 dispose 都能中止该操作；clear 递增代次，旧任务不能再提交可见性或改变新任务的恢复标志。CameraControls 3.1.2 的 `stop()` 会跳到旧目的地，故取消先以实际当前位置/目标执行非动画定位，再 stop；不单独调用 stop 冒充原地停止。控制器的最后一次更新在历史记录仍受抑制时以 `update(0)` 消费，避免下一帧为已清空的历史重新写入旧视角。取消可自行结算，不要求旧运动 Promise 先完成。

相机恢复成功后再提交可见性并弹出当前快照；失败时尝试恢复开始前的相机/筛选，保留历史并向调用方报告错误。相机不可用且回滚也失败时不宣称画面已恢复，但仍保留历史供重试，工程清理不被取消异常阻断。

[菜单入口](../../desktop/src/ui/shell/viewerShell.ts)捕获错误，以普通选择状态提示“暂时无法恢复上一视角，请重试。”，不创建工程加载浮层。工程会话或当前选择已变化时，迟到失败不覆盖新状态。只有位置、目标与既有“仅看选中”开关参与本次历史契约，未加入模型编辑、选择身份回放、图层回放或持久化。

共 245 条记录、219 个 GLB；02 的 17 个 partial、26 个 empty 沿用原诊断，未变为“全部完整”。每站从已加载 occurrence 中选前三个包围盒中心相距至少 1 m 的设备位置，按真实中心/尺度生成 A/B/C 视角。三轮重用这三个目标，不是 84 个不同设备。CBM 使用产品累积矩阵、列主序和毫米平移换米规则；工程 source-to-viewer 使用单位阵，没有加载真实 IFC 锚点。

装置使用真实 PerspectiveCamera 和 CameraControls，按固定 1/60 s 步长推进阻尼，最多模拟 20 秒等待运动结算。220 ms 记录窗口用真实 250 ms 等待跨过；快速返回则在同一 JS 流程中主动调用。这个步进方式用于状态验证，不是实际用户运动时长、RAF 或点击延迟测量。

相机失败通过仅一次拒绝 animated `setLookAt` 注入，随后恢复真实方法；没有损坏 GIM、派生缓存或生产数据库。四站前后 UUID、几何身份、世界矩阵与顶点/索引缓冲区指纹一致。导航检查不触发 L2、几何编译或源补读；完整属性、树选择、GPU 画面未由此验收。

## 结果与复现

每站每轮七项候选均通过，基线均复现至少一个预期违约。最早两个新增单元用例也在基线上实际失败，分别证明待记录移动不可返回、失败提前改变筛选；不是仅以源码推断问题。

以下入口缺少任一样本或产物会失败，不跳过。先按 [基准说明](../../desktop/scripts/benchmarks/README.md)生成 L0 产物与 CBM 清单，再保持 Vite `127.0.0.1:14317` 运行，从 `desktop/` 执行：

```powershell
node scripts/benchmarks/view-history-browser.mjs substation01
node scripts/benchmarks/view-history-browser.mjs substation02
node scripts/benchmarks/view-history-browser.mjs substation03
node scripts/benchmarks/view-history-browser.mjs substation04
```

原始记录保留各场景的返回值、异常、目标检查、筛选、后续重试与显示指纹，位于忽略目录 `output/view-history/`：

- `substation01-2026-10-25T05-11-07-829Z.json`
- `substation02-2026-10-25T05-11-22-803Z.json`
- `substation03-2026-10-25T05-11-37-305Z.json`
- `substation04-2026-10-25T05-11-51-900Z.json`

更早的初跑记录保留，但缺少“新筛选后继续返回 B”或清空后等待末帧再开启新视角的检查，不与最终主表混用。早期候选在新增真实 CameraControls 单元回归中复现了取消末帧写回旧视角，故补充 `update(0)` 后重新执行四站；不把此前立即切换目标的通过记录作为该边界已通过的证据。每个场景释放历史订阅和 CameraControls，站级结束释放模板并清空 placement，关闭所属浏览器树。
