# 变电业务树实施与验证

当前正确性修正版采用 `business-tree-v3`；以文末“0.1.3 归属正确性修正”一节为准。前述无空间挂接、按 IFC 来源分建筑和待确认树层等描述属于当时构建，保留作问题与失败探索记录，不代表修正版的界面和规则。

## 范围与业务边界

当前交付目标为 **0.1.3 默认业务树，冷构建、暖加载**。工程→安装工程/建筑工程投影保留来源层级、既有功能系统和 IFC 空间入口。采用用户修正后的术语 **母线设备间隔**：同一电压配电区域的Ⅰ母、Ⅱ母及各母线段整体归组，与母联、进线、出线间隔同级，不跨电压或明确独立区域合并。柜内母排不单凭材料词覆盖设备归属。本文保留 0.1.2 探索和失败决定，不能将旧按需交付结论当作 0.1.3 当前行为。

用户确认没有逐件人工真值，材料自动空间改挂因此关闭。研究最近邻输出不作为人工标签，不设置未经标定的生产阈值。本轮交付明确归属、待确认展示和选择交互；空间算法提供材料门控、有效几何、独立间隔最近/次近候选及拒绝原因的领域入口，没有据此自动重挂真实材料。没有新增人工编辑功能。

安装侧按主变压器系统、有效电压配电装置（从高到低）、无功补偿、站用电、电缆及接地、二次的顺序组织。站用电和二次分开，配电区域内按出线、进线、母线设备、母联、分段排序，同类使用数字自然顺序。参考 `research/gim_info` 的业务名称，不采用其中具体厂商电压修正、文件名角色猜测或未标定坐标挂接。明确的 EM PT 母线设备业务分组可并入所属电压区域的母线设备间隔，不能仅凭普通 PT 设备类型归入母线。建筑侧按来源建筑/楼层组织，消防、照明与楼层并列。无明确建筑或楼层证据的对象保留待确认。不同来源的未命名建筑不凭同名合并，显示来源文件以便区分，不冒充已确认的实体建筑。

唯一对象级 IFC 关联才合并 DEV/IFC 来源，保留模型身份、大小写敏感 GUID 及来源别名。多义候选不取第一个，同名和邻近不去重。DEV 装配子部件随物理根保留，不增加几何 seed。IFC 端口不作为物理资产；开洞/特征保留在明确宿主上，无独立网格的门窗仍保留为对象。业务对象数不是设备台数或工程量。

业务证据使用设备名称、原始 CBM 上下文及 FAM 标称电压。FAM 裸引用按唯一文件名匹配已有属性索引，路径大小写不敏感，歧义不猜测。额定/最高电压不直接替代系统电压，范围表达式不当作标称值。通用 F2 电压标签不能单独决定区域，须结合明确业务单元或对象证据。源中 `31.5 主变进线柜` 不产生“5号主变”，保护柜不挂到主变本体单元；上下文中的主变编号优先于导线名称内的数字。

## 架构与交互

纯领域索引位于 `gim/businessTree.ts`，冷构建服务绑定 root/FAM/Spatial 会话版本。CBM 基础投影先可用；IFC 补充复用现有 Spatial 索引，将裁剪后的语义输入交给 Worker，不重读或重解析 IFC。返回后恢复原始 CBM 节点引用，工程切换终止旧任务并拒绝迟到结果。0.1.3 增加独立业务派生快照，不修改 SQLite 表、既有缓存格式、依赖版本或 L2 调度。

UI 使用稳定成员集合、懒展开和大分支虚拟窗口。搜索展开祖先并显露目标；投影更新保留展开、查询及滚动。基础树可操作，IFC 补充中和失败有独立提示。会话结束清理投影与 Worker。

设备叶子复用原 FAM/DEV 检查器和选择路径；IFC 叶子按实际模型/GUID 查找运行时对象，复用 IFC 检查器，提交高亮并自动近景。聚合行按成员集合选择、定位、隔离及恢复。DEV 支持多根隔离，IFC 已加载 L1 实例使用多个高亮覆盖层。普通选择不触发 L2，A→B 与工程会话守卫保留。

## 0.1.3 冷构建与暖加载设计

用户将本轮目标明确为 0.1.3 业务树功能，并要求只读模型冷构建、暖加载，取代前轮会话内重算方案。默认视图改为业务树，新增 `businessTreeCache.ts`，通过既有原子文件桥发布独立派生快照，不新增数据库表。当前契约为 `business-snapshot-v3` / `business-tree-v2`，同时绑定原生返回的变电语义版本、Spatial 快照/解析契约、源 SHA 与模型清单摘要；头部记录完整标志、压缩及展开长度和内容 SHA。快照只保存对象、区域、功能单元、归属证据及准确的 IFC 身份，成员映射和来源索引在加载时恢复，CBM 节点绑定本次恢复的原对象。

冷路径先提供 CBM 基础业务投影，复用语义第二阶段已解析的 FAM 原行；FAM 未完整发布前不构建和保存最终归属。IFC 补充延至 IFC/基础表示结算后，复用 Spatial，不重复读或解析 IFC、不触发 L2。合法暖恢复仅校验、解压、反序列化并恢复查找映射，完整投影在只读会话内保持不变，后续 FAM/Spatial 通知不重新分类或生成搜索投影。精确 IFC 模型/GUID/ExpressId 随快照保存，因此选中和近景不依赖再造业务索引。缓存缺失、损坏或契约改变只回退业务重建，不丢弃其他合法缓存。

原型首先采用未压缩正文：四站功能检查通过，但 substation02 在一对全命中记录中基础树从 798.3 ms 增至 1398.8 ms，单独快照恢复 584.1 ms。该格式没有作为最终实现保留；改用运行时内建 gzip，压缩和展开上限均为 64 MiB，逐块核对声明的展开长度并在超限时取消读取。保留原始 `cached-A1/B1` 四站探索记录；substation01 该对仍有 L1 冷编译，不计作全命中对照。最终使用新的独立构建重测，不混用原型成绩。

首次原生重开还发现文件名索引被误用作完整 CBM 路径映射，已修正为从恢复图绑定完整路径，既有测试也改用真实的文件名索引夹具；错误轮次 `v013-hit` 实为 miss/rebuild，未计入缓存命中证据。该修复不重新解析 CBM。其后冷构建样本直接生成的快照包含原始 CBM 上下文，暖加载保持相同归属；升级时缺失业务快照也可从既有合法语义首次补建。

### 规则与边界

1. **建筑公用设备用途优先**：照明箱、空调柜机中心词先于“柜”通用词；动力照明/暖通来源中的配电箱、检修箱、空调等可补充用途。按本项目本轮业务口径，空调在所在建筑的“照明”系统展示，原设备类型不改写。原名含“户内”不单独决定建筑所有权；跨专业归楼仍需要名称、宿主或已有建筑范围。未确定具体楼的对象保留站区分支及归属状态，不能据此宣称其拥有明确的户外工程关系。
2. **站区设施优先于空间包含**：电缆沟、构架、道路、围墙等明确设施类型不能因为位于楼下而被收进楼层。普通“支架”可遵循建筑宿主；未命名设施不强行推断独立构筑物。基础集中在“基础”，按设备基础、建筑基础、其他基础分组，明确建筑基础名称先于附近主变距离；用途缺失时不伪造类型。主变相关单元及来源楼层仍在属性中保留，不因业务归组修改 IFC 空间关系。
3. **唯一主设备短接引**：显式归属及完整端点集合优先。对仍未确定、有效平面跨度不超过 12 m 的导线，复用网格和固定主设备范围，检查是否仅与一个兼容主设备单元平面相交；母线不作为主设备竞争候选。该证据可优先于导线中心的最近距离，结果为推断。多个主设备交叠、异常电压、重复来源歧义、超长或端点冲突不能由此单归属；不借推断导线扩大边界，不推断真实电气连接。A 相源范围约 X=0.376–3.997 m、Y=-7.046–-1.658 m、Z=13.319–13.926 m，缺少已支持的显式端点，因此使用平面接引证据，未伪造端点。
