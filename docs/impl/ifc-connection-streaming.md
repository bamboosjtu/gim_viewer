# IFC 连接构件提前显示与来源归属

## 范围与判定

本轮处理桌面变电工程的连接构件显示、冷暖一致性及明确引用归属，不生成源中不存在的导线，不以空间邻近认定电气连接。DEV、线路和 Android 几何行为不变。连接构件分类包含已有的管线、接头和部分代理构件，不能把该分类的对象总数等同于电气导线条数。

当前实现包含三项独立工作：大源首对象提前显示、暖恢复状态修正、可核对的端点引用。单元/样本通过不代表原生 Release 性能达标；本页下方按实际执行范围记录验收，未执行项保留未完成。

## 提前显示的实现及边界

完整源仍使用现有 web-ifc + Fragments 管线。在源哈希完成后，对 64–512 MiB 且前 4 MiB 已出现受支持连接实体的源，尝试建立有界 STEP 字节索引，提取 ExpressId 最小的一个连接对象及其几何、单位、坐标、项目和外观引用闭包。保留原始记录字节和源身份，不改写数字或重新拟合位置。私有子集使用绝对 Y-up 米，不能以其私有原点替代工程锚点。

索引最多 64 MiB，闭包最多 10 万条记录 / 8 MiB，首对象网格最多 4 MiB。首对象完整通过校验并释放私有 API 后才发布批次；完整源使用新的 API 打开并发送其余对象，跳过已发布对象，序号连续。只有完整源的最终凭据能发布整源完成。索引不可用、引用缺失、复杂 STEP 语法或预算不满足时走原完整源路径；消费失败与取消直接终止所属任务，不能作为可选提取失败重放已发布批次。

原生首轮发现当前 Fragments 共享导入要求完整源为模型编号 0。仅关闭首对象模型仍会让同一 API 的下一模型编号变成 1，导致最终导入失败。该试验记录不计入验收，也不作为暖启动前置。实现已改为明确分离临时 API 与完整源 API；真实大源回归同时执行提前显示、全部连接网格提取和真实 Fragments 导入，防止仅检查预览就误判成功。

索引同时记录既有忽略开孔策略所需的关系范围，完整源准备复用该范围，避免先做新索引、再重复旧全字节扫描。源 SHA 在任何派生修改之前计算。私有模型增加一次解析，`coldPipeline.parsedModels` 如实计数；并未将大源 OpenModel 改成可中断或按对象增量解析。

`OpenModelFromCallback` 是回调供给字节的接口，不能仅凭接口名称认定其会在完整打开前提供可渲染对象；官方接口仍返回打开后的模型 ID。本轮没有把它宣传成已实现的流式解析方案。[web-ifc API](https://thatopen.github.io/engine_web-ifc/docs/classes/web-ifc.IfcAPI.html)

源队列保留最初的坐标锚点源，其后按已有 CBM 对象引用证据和调度提示提高连接来源顺序；文件名提示只影响顺序，不决定几何解析分支。内存压力较高时关闭可选首对象路径。完整源读取、哈希和最终 OpenModel 仍需计时，不能只报子集打开耗时。

## 暖缓存与状态

保留 `connection-mesh-v1`、远景及其他缓存域版本。已有连接网格缓存仍受 48 MiB 会话保留预算限制，大源超过预算时只显示，不扩大内存预算保留重复副本。暖恢复以已成功加载的远景索引对象为显示/来源数量依据，单独记录 `readyModels`；没有重放预览凭据时不增加 `completeModels`。空的最终批次不计作某源首个几何批次。

`RegionalObject.connectionEndpoints` 是可选、兼容的诊断元数据。未定义表示旧缓存或没有收集；空数组表示本轮支持规则已经扫描但未发现引用。这两种情况在界面区分，旧缓存不会被错误报告为源没有证据。未实现旧远景缓存端点元数据的自动补采；用户看到旧缓存时仍可能需要后续重新转换才能取得新元数据。

## 来源与设备端点

对象本身的 `IFCFILE + IFCGUID` 只在同一来源内精确匹配 CBM，大小写不折叠 IFC GlobalId，重复 basename 或多候选不任选其一。CBM 来源对象、DEV 装配归属、设备端点分别呈现；没有 DEV 的语义对象不是已确认物理设备。

端点新增两条受支持证据：

- 标准 `IfcRelConnectsPorts` / `IfcRelConnectsPortToElement` 和 `IfcRelConnectsElements`，保留关系、端口与相邻 IFC 元素身份。
- 明确接线点 GUID 属性集的实际 `NominalValue` → GL 的 `GimGeCableConcentration.ConnectGuid` → 同 UUID DEV → 现有 CBM/PARTINDEX occurrence。仅 Description 中出现 UUID 不构成引用。GL 保留为辅助证据，不加入 SOLIDMODEL 几何主链。

GL 只批读已知大小、单项 ≤1 MiB、总量 ≤4 MiB 的小来源，等待上限 5 秒。它不占几何计算 gate、不阻挡连接线显示；超时/切换工程后的迟到结果不安装。共享接线点仍保留全部实际实例候选，不按文件顺序、设备名称或距离自动归属。局部证据失败不使已可用几何失败。

## 样本复核

四份 GIM 的 SHA 已与样本台账核对。全 IFC 静态/真实解析审计中的既有分类对象分别为：substation01 1159、02 1152、03 272、04 487。这些数量包含管线及接头，电气连接子集应独立说明。

substation01 电气来源共 299 个受支持对象，其中 69 个名称为导线，其他包括线夹和母排。对象到 CBM 的来源身份可以核对，但三台主变缺少对象级连接归属证据，不能把“来源身份匹配”当成“主变端点已全部建立”。

substation03 大源共 272 个对象（260 个软导体、12 个硬导体管母线），修正此前仅记录 6 个软导体的不完整描述。202 个对象具有支持的端点属性引用，共 76 个不同被引用 UUID；其中 30 个能唯一映射到 DEV occurrence、43 个有多个候选、3 个未映射。侧文件共 45 个、201 个接线点、78 个不同 GUID。GUID 数与对象数不是同一统计口径，不以唯一 GUID 数推算全部导线的完整归属。

真实几何回归逐对象对照源身份、展开顶点字节摘要、三角形顺序、颜色、归一化/未归一化坐标及放置后的包围盒。四个固定来源均通过，包含大源全部 272 个对象；这证明本轮输入和路径，不扩大为任意 IFC 等价性承诺。
