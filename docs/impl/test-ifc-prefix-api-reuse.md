# 未保留：首对象与完整源共用 IFC API

尝试在完整源 OpenModel 前，用同一个 web-ifc API 打开首个连接对象子集，提取后 CloseModel，再打开完整源。预期复用 WASM 初始化，减少额外准备成本。

该路线没有通过正确性验收，已经移除。私有子集获得模型编号 0，CloseModel 不重置同一 API 的模型编号；完整源随后获得编号 1。项目当前的 Fragments 共享导入适配明确要求模型编号 0，因此原生 Release 中预览可见，但最终远景导入报 `Installed Fragments requires IFC model 0`。这是新增方案的生命周期错误，不是样本损坏。

失败包源码指纹为 `4d820f2a304f…`，原生记录目录为本地 `output/acceptance/stations/2026-10-24T08-57-18.135Z/`。该运行不计入性能通过记录，也没有作为暖启动前置；其派生缓存保存在独立隔离目录，未回写日常缓存。仅凭首屏、完整预览凭据或局部网格等价测试，不能证明最终 Fragments 导入成功。

最终实现将临时 API 的创建和释放封装在首对象路径内，完整源使用新 API 并从模型 0 开始导入；不符合提前提取条件时不创建临时 API。对应真实大源回归同时执行首对象提取、全部连接网格和真实 Fragments 导入。有效路线及其性能取舍、缓存和跨表示验证见 [连接构件报告](ifc-connection-streaming.md)。不保留同 API 模型复用开关、重试分支或仅适用于该失败方案的生产代码。
