# 性能探索记录

本文件只记录性能路线的假设、实验边界、结果与未保留原因，不描述当前能力。当前机制见 [架构](../architecture.md)、[性能](../performance.md) 与 [软件规格](../software-spec.md)。

## 1. 保留门槛

一条性能路线只有同时满足以下条件才进入正式实现：

- 正确性不变量不退化，失败与取消仍按原任务结算；
- 在相同构建、相同源、等价缓存状态下取得可复核的端到端收益；
- 不以局部 CPU 时间、局部计数或单次运行替代产品指标；
- 不通过放宽完成口径、隐藏失败或增加无界资源换取数字。

单次对照不足以否定整类技术；以下记录的是该假设在该条件下未通过，不是同类方案普遍不可行。

## 2. 逐条记录

### E-01 DEV 派生缺失时按需小批合批

- 假设：把 Worker 逐源索取合并为固定小批，并提供会话源字节复用，可提高 DEV 派生缺失恢复速度。
- 边界：语义/IFC 缓存可用、DEV 派生域为空的大站；原生 Release 固定窗口。
- 结果：约 5690 个 occurrence、291 个 L0 模板的受控样本中，源读取被合批但新增源缓存与在途共享均未命中；设备显示和编译进度没有推进。
- 未保留：候选、专属测试和诊断已删除。
- 约束：不能把“小批合并未获益”泛化为“所有源批读不可行”；后续受控工作集改为整份不可变 File 交给 Worker，已进入架构。

### E-02 完整缓存恢复前额外目录探测

- 假设：在完整缓存恢复前主动探测目录，可减少后续 miss 与等待。
- 边界：同一完整缓存前置、独立复制 profile、DEV 实例化关闭；三次基础表示对照。
- 结果：候选中位数改善约 8%，但最大值增长约 14.5%，未通过“不回退”门槛。
- 未保留：最终实现复用正常目录首批，不为判断是否准备源再发 IPC。
- 约束：重复恢复的暖路径仍以正常目录批读为唯一入口。

### E-03 提高 DEV Worker 比例

- 假设：提高 DEV 编译 Worker 数量可加快大站基础表示。
- 边界：大站历史原生冷运行；池比例从 60% 提高到 90%。
- 结果：已显示 occurrence 从 225/285 降到 81/285，但主线程消费、结果背压与 IFC 争用未被证明改善。
- 未保留：比例已回退；当前按逻辑核 60% 取 2–8 个，IFC 期间最多两个编译槽。
- 约束：增加并发前必须核对主线程消费、结果背压和 IFC 争用；不以“空闲 Worker 多”作为提速证据。

### E-04 首对象与完整源共用 IFC API

- 假设：提前显示的首对象与完整源转换共用同一个 web-ifc API，可减少初始化成本。
- 边界：大源真实样本，包含首对象提取与 Fragments 导入。
- 结果：共用 API 导致完整源模型编号不为 0，Fragments 共享导入失败。
- 未保留：路线已移除；临时 API 与完整源 API 必须分离，临时 API 释放后再打开完整源。
- 约束：当前 Fragments 共享导入要求完整源为模型 0；不能用局部预览成功替代整源导入回归。

### E-05 选择依赖复用与高亮合批

- 假设：跨选择复用导航依赖并把多来源高亮合并提交，可降低选择延迟。
- 边界：缺少同一最终构建、同一负载下的端到端 A/B；只有并发负载下的正确性记录。
- 结果：没有满足保留条件的延迟收益；并发记录只证明身份与提交守卫正确。
- 未保留：候选实现与专属测试撤回；导航导入 Promise 的页面级复用仍保留，见架构“选择提交权”。
- 约束：选择优化必须同时记录点击到高亮/摘要的端到端时间，不能只报内部阶段。

### E-06 最近候选优先的选择拾取

- 假设：先核对最近首命中，跳过远处来源，可减少 IFC 选择延迟。
- 边界：四站首次分段观察；每站 5×5 固定点击点、重复两遍，未达到每站 20 个独立对象。
- 结果：原型在隐藏对象的跨来源回退场景中改变了命中身份，正确性预检 `accepted=false`；未执行候选 Release A/B。分段观察也未提供足以支持该路线的稳定收益。
- 未保留：原型只在忽略目录运行，产品源码保持原状；没有新增仓库测试或临时埋点。
- 约束：Fragments 首命中与应用 `rayDistance ?? distance` 排序不是同一距离契约；要安全剪枝，必须证明来源全部候选的统一距离下界，或核对全部相关来源的可见性与回退。后续优先归因必要射线及高亮清理/提交的 Worker 往返，并保留 A→B 提交守卫、L1/L2 掩码和隔离恢复语义。

## 3. 重新尝试条件

- 使用同一 Release、同一源文件、等价冷/暖缓存状态和相同 WebView2 运行时；
- 同时记录 First usable、Current view、基础表示、失败数、缓存完成与内存；
- 交互路线使用固定相机和真实输入，报告 p50/p95/p99 与长任务，不只报平均值；
- 先量化回退代价和清理方式，再决定是否保留；正确性缺陷不得因“有性能收益”而保留。

证据保存在本地 `output/` 或临时目录，不提交真实工程属性、坐标或构建指纹；正文只保留可复核的定性结论与约束。
