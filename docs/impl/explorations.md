# 已回退与未采用路线（探索记录）

> 本文件不是当前能力清单。当前机制见 [架构](../architecture.md)、[性能](../performance.md) 与 [软件规格](../software-spec.md)。
> 本目录只保留“假设、实验边界、结果、未保留原因”，不保留日期流水、构建指纹和逐窗口采样表；证据位于本地被忽略的 `output/` 目录。

## 1. 保留与重试门槛

一条路线只有满足以下条件才进入正式实现：

- 正确性不变量不退化，失败与取消仍按原任务结算；
- 在相同构建、相同源、等价缓存状态下取得可复核的端到端收益；
- 不以局部 CPU 时间、局部计数或单次运行替代产品指标；
- 不通过放宽完成口径、隐藏失败或增加无界资源换取数字。

单次对照不足以否定整类技术；本文件记录的是该次假设在该条件下未通过，不是“所有同类方案不可行”。

## 2. 记录格式

每条记录包含：假设、实验边界、结果、未保留原因、保留的约束。

## 3. 逐条记录

### E-01 DEV 派生缺失时按需小批合批

- 假设：把 Worker 逐源索取合并为最多 64 条、并提供 32 MiB 会话源字节复用，可提高 DEV 派生缺失恢复速度。
- 边界：语义/IFC 缓存可用、DEV 派生域为空的 B1-1；原生 Release 固定 180 秒窗口。
- 结果：控制约 5690 个 occurrence / 291 个 L0 模板，候选约 5671 / 272；双方失败为零，基础表示均未 settled。3999 条源读取被派入 1171 批，但新增源缓存及在途共享均未命中。
- 未保留：没有设备显示或编译推进收益；候选及其专属测试、诊断已删除。
- 约束：不要把“小批合并失败”泛化为“所有源批读不可行”；后续受控工作集改用整份不可变 File 交给 Worker，已进入架构。

### E-02 完整缓存恢复前额外目录探测

- 假设：在完整缓存恢复前主动探测目录，可减少后续 miss 与等待。
- 边界：同一完整缓存前置、独立复制 profile、DEV 实例化关闭；三次基础表示对照。
- 结果：候选中位数改善约 8%，但最大值增长约 14.5%；未通过“不回退”门槛。
- 未保留：最终实现改为复用正常目录首批，不为判断是否准备源再发 IPC。
- 约束：重复恢复的暖路径仍以正常目录批读为唯一入口。

### E-03 调整 gate 失败释放顺序

- 假设：gate 失败时的同步释放顺序存在竞态，调整顺序可避免唤醒丢失。
- 边界：既有 gate/结果消费回归；未构造出真实竞态。
- 结果：既有微任务唤醒已保证原顺序安全，未复现问题。
- 未保留：生产改动撤回，不记为 bugfix。
- 约束：再次修改前先证明现有唤醒路径会丢失，不能仅凭代码顺序怀疑。

### E-04 提高 DEV Worker 比例

- 假设：提高 DEV 编译 Worker 数量可加快大站基础表示。
- 边界：substation01 历史原生冷运行；池比例从 60% 提高到 90%。
- 结果：已显示 occurrence 从 225/285 降到 81/285。
- 未保留：比例已回退；当前按逻辑核 60% 取 2–8 个，IFC 期间最多两个编译槽。
- 约束：增加并发前必须核对主线程消费、结果背压和 IFC 争用；不以“空闲 Worker 多”作为提速证据。

### E-05 首对象与完整源共用 IFC API

- 假设：提前显示的首对象与完整源转换共用同一个 web-ifc API，可减少初始化成本。
- 边界：大源真实样本，包含首对象提取与 Fragments 导入。
- 结果：共用 API 导致完整源模型编号不为 0，Fragments 共享导入失败。
- 未保留：路线已移除；临时 API 与完整源 API 必须分离，临时 API 释放后再打开完整源。
- 约束：当前 Fragments 共享导入要求完整源为模型 0；不能用局部预览成功替代整源导入回归。

### E-06 选择依赖复用与高亮合批

- 假设：跨选择复用导航依赖并把多来源高亮合并提交，可降低选择延迟。
- 边界：缺少同一最终构建、同一负载下的端到端 A/B；只有并发负载下的正确性记录。
- 结果：没有满足保留条件的延迟收益；并发记录只证明身份与提交守卫正确。
- 未保留：候选实现与专属测试撤回；导航导入 Promise 的页面级复用仍保留，见架构“选择提交权”。
- 约束：选择优化必须同时记录点击到高亮/摘要的端到端时间，不能只报内部阶段。

### E-07 严格变电入口的全局 SQLite 准备

- 假设：在严格样本 Vitest 配置中复用统一 SQLite harness 准备，可直接跑通四站样本链。
- 边界：`test:substation:strict` 真实样本入口；需要构建一次 Rust harness。
- 结果：配置未接入 `sqliteGlobalSetup`，helper 注入路径为 undefined，四个在册样本均在入口失败；未形成可执行样本链。
- 未保留：该测试入口的修复未混入本轮清理；后续已修复并跑通四站严格链，证据见[验证 §4](../validation.md#4-真实桌面复核)。
- 约束：不能以普通单元测试或独立 `test:sqlite` 通过替代严格样本入口。

### E-08 PMTiles 离线瓦片

- 假设：用本地 PMTiles 矢量瓦片替代在线底图，提供离线地图能力。
- 边界：仅预研开关与本地 style，未进入底图切换 UI，也没有真实瓦片包验收。
- 结果：开关恒为关闭，生产路径永远不会加载该协议；没有形成可用的离线底图能力。
- 未保留：PMTiles 模块、依赖和构建分块已移除；线路底图只保留 OSM/天地图在线服务与 Canvas 兜底。
- 约束：若重新引入离线底图，需先定义瓦片包来源、许可、更新方式和独立验收，不能恢复一个恒关闭的开关。

## 4. 重新尝试的通用条件

- 使用同一 Release、同一源文件、等价冷/暖缓存状态和相同 WebView2 运行时；
- 同时记录 First usable、Current view、基础表示、失败数、缓存完成与内存；
- 交互路线使用固定相机和真实输入，报告 p50/p95/p99 与长任务，不只报平均值；
- 先量化回退代价和清理方式，再决定是否保留；正确性缺陷不得因“有性能收益”而保留。

## 5. 证据位置
