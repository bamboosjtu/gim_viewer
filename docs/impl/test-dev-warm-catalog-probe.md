# 未保留：在正常目录批读前额外探测派生缓存

日期：2026-10-23。结论：**独立前置探测没有证明完整缓存路径稳定不回退，已从生产代码删除。** 源工作集路线本身另有派生缺失收益，本报告只否定新增这次探测的必要性。

最初在 Worker 初始化前查询最多 64 个未排序 DEV 的 catalog；全 miss 时准备不可变源 File，命中时保留懒读。后改为与 Worker 初始化并行，但仍增加一次 native IPC，并与随后按视觉优先级排序的目录批读部分重叠。

B1-1 完整缓存恢复三次对照，控制基础表示为 45.498 / 44.273 / 38.355 秒，候选为 40.375 / 52.078 / 40.749 秒。候选中位数约改善 8%，最大值却增长约 14.5%；单项尖峰原因未确认。这既不是全面无收益，也不足以证明新增探测符合性能特性不回退的门槛。

最终实现直接使用现有正常目录首批结果：全部明确 miss 才异步准备源，hit、invalid、read-error、deferred 不触发。没有额外探测命令，没有独立探测等待 timer，删除该路线专用的超时模拟，保留源批读本身的 10 秒限制、状态分类与旧会话回归。正常目录加载行为及完整缓存键不变。

本报告不以移除一次 IPC 直接宣称端到端目标达标，也不把已移除版本的较快一次转移给最终包。完整条件、各次会话及故障检查见 [受控源工作集](dev-recovery-workset.md)。
