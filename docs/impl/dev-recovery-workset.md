## 当前实现

- 从现有语义索引恢复 entry 大小，工程释放时清空；源身份、规范路径、矩阵及几何版本不变。
- 复用正常目录批读的首批最多 64 个 catalog 键，不增加暖路径探测调用。只有全部明确 miss 才准备源；read-error、invalid、deferred 不视作派生域缺失。首轮实验包在创建 Worker 前准备，现行版本与 Worker 初始化和基础任务并行，准备完成后补发共享 File，不把可选准备作为计算 gate。
- 复用现有源批读，将大小已知的 DEV/PHM/STL/GL/MOD 转为不可变 File，交给 Worker 既有的 File/Blob 读取路径。未知大小、过大来源及读取失败保留原受权懒读入口。
- 按索引大小准入：单源最多 8 MiB，普通批次最多 4 MiB、4096 文件，单个 4–8 MiB 来源独占一批，总源工作集最多 128 MiB。高/临界压力停止准备，工程切换丢弃迟到回复。该数值是源准备额度，不是整个进程树、WASM 或原生在途响应的硬驻留上限。
- catalog 批读的明确 miss/invalid/read-error 交给原有处理分支复用，不再为每个已确认 miss 重新读一遍相同键；deferred 继续按需重读。
- 沿用已有最多 8 秒的 IFC 预取让步，不等待最后一个 IFC 完成；不改变计算 gate、Worker 数量、提交预算、缓存写入预算或完成口径。
- 源准备有 10 秒期限（不含既有最多 8 秒的 IFC 让步）；超时保留懒读，迟到回复不安装来源。它不取消已经进入原生层的读取，也不宣称能在主线程长任务内部抢占。

本轮 B1-1 实际准备 8851 份源、16,878,592 bytes，通过 5 次批读取得；native 源批读累计约 839.7 毫秒。候选的 DEV bounds RPC 聚合为零，Blob 读取聚合约 5.51 秒、最大约 109.3 毫秒。另有 1 次非 DEV 单项读取，不能记成 DEV 回退。

这与此前失败的按需小批路线不同：后者保留 Worker 对主线程的逐源索取，本次将整份已准入来源交给 Worker 直接读取。前次无收益结论仍成立，见 [已回退路线](test-dev-recovery-demand-batching.md)。
