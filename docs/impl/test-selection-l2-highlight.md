# 选择高亮跨 IFC 表示迁移（O-08）

日期：2026-10-23，桌面 v0.1.1，起点 `dcbfc8c`。本项属于正确性修复：普通浏览和选择仍不启动 L2；主动精化及返回浏览时，高亮跟随当前源对象。按本轮确认的验收口径，允许修复所需的有限材质与提交成本，不以它宣称新的性能优化收益。

## 原因与实现

远景选择由 Fragments 高亮记录持有 LocalId，显式 L2 是独立 Three.js 网格；隐藏远景不会自动把高亮应用到替换网格。原 L1 释放回调还会重置全部 MOD/区域高亮，导致当前表示的高亮中断，并可能影响同一选择中的其他来源。

现在区域 L1、显式 L2 和返回远景均在表示提交时通知高亮绑定层。绑定只接受当前 SelectionRequest 的模型/LocalId 或明确的 ExpressId 身份，并通过既有高亮短队列排序；再次检查工程和表示对象所有权。迁移只处理新网格，不重新查源、读取属性、计算几何、移动相机或重建全站可见性范围。无关表示跳过材质遍历。

新 `addModHighlightGroup` 增量加入当前选择的表示，不重新克隆未变化的网格；`removeModHighlightGroup` 只恢复被释放组的原材质并释放其克隆，其他已选来源保留。实例化 L1 按需生成当前对象的高亮覆盖网格。返回浏览时，已有 Fragments 高亮继续复用；从区域拾取开始、此前无远景高亮时，只为对应 LocalId 补远景高亮。记录兼容既有数组和 Set 两种可迭代 ID 集合。

精化提交的异步前置步骤完成前保留旧浏览表示和高亮。取消、失败或同对象快速重试时，未提交的新组独立释放，不能删除较新请求已经提交的组或其高亮。此变更不修改缓存键、版本或持久化含义。

## 回归

新增 12 项专项测试覆盖：

- 远景→L2、区域→L2→远景；已有远景高亮复用及必要时补充高亮。
- 重复通知不重复克隆；只恢复离开表示的材质；其他选中来源材质引用不变。
- 未选中来源不遍历几何；已过期的表示、选择和工程不提交。
- 迁移等待原高亮提交结束；A→B 时跳过排队的 A；已开始的外部远景高亮仍可被 B 正确重置。
- 同对象并发精化只执行一次；取消、求值失败和表示提交失败保留浏览反馈；旧提交不得删除新重试结果。
- 实例化 L1 仅为当前选中对象准备一次覆盖网格。
