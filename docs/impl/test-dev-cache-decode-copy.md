# DEV 暖缓存解包：省去中间记录复制

## 结论与范围

保留该候选。原生 DEV 批量恢复在解包时借用批次内的记录视图，再将最终 GLB 复制到独立缓冲区，省去原有的整条记录中间副本。四站真实 L0 模板的三次独立 headless Edge 对照中，缓存解包中位数降低约 45%–51%，各次 p95 均降低。

这只是 **GIMR 解包及 DEV 记录解包的 CPU 收益**。未测原生 IPC、校验、GLTF 解析、实例放置、GPU 提交、完整冷暖启动或进程树峰值内存，不将上述百分比写成工程打开加速。本轮没有减少 parser 调用，也没有完成整个“重复解析与数据搬运”方向；不关闭 O-02/O-07，不进入其他三个优化方向。

## 成本与实现

此前的暖路径为：原生二进制批次 → `parseBatchCachePayload` 复制每条完整记录 → `unpackDevArtifact` 解析元数据并再次复制 GLB → 校验及模板解析。记录元数据通常很小，大部分中间复制是已存在于批次内的 GLB。

现在 `parseBatchCachePayload` 默认仍返回独立条目，只在 DEV 原生批读内部使用 `copyBytes: false`。记录视图只用于同一次同步解包；`unpackDevArtifact` 保留最终 GLB 的独立复制，返回的 GLB 从偏移 0 开始，缓冲区长度等于其自身长度，不引用整个批次或相邻模板。JSON 元数据也不持有输入视图。目录元数据采用同一同步解码入口。

普通源文件读取保持默认复制，避免逐文件 Transferable 移交时连带分离其他条目。原有逐条损坏隔离、传输失败拆批、字节上限及 deferred/miss 区分保持原行为。没有改动缓存格式、版本、SHA 校验、原生路径校验、64 条批次上限、Worker 数或消费预算。

实现入口：

- [批次解析](../../desktop/bridge/database.ts)：显式选择借用记录视图。
- [DEV 原生批读](../../desktop/bridge/devLodCache.ts)：同步解包后只返回独立结果。
- [所有权及损坏隔离回归](../../desktop/bridge/__tests__/devLodCache.test.ts)与[协议边界回归](../../desktop/bridge/__tests__/database.test.ts)。

## 输入、选择与方法

基于 `2cc104ea7fcddbf494e055905b18355567772f68`，受检源码指纹为 `30dc24f5fef15487baf4e2cedf567592f0bacd6443a7fdfbe7bf8e20aaca9f20`（按既有 acceptance-build 工具计算，包含桌面脚本与入口说明）。2026-10-25 在 Windows、i7-8700（12 逻辑核）、约 64 GiB 内存上执行。Node 为 22.23.1，独立浏览器实际 UA 为 headless Edge 156；它不是原生 WebView2 Release。

四个原包 SHA 与[样本台账](../schema/sample-corpus.md)逐包一致，解包目录由原包生成并保存源 SHA 标记。先构建真实 CBM 树和物理 occurrence，再对唯一 DEV 根按路径排序，选取文件较大的前 16 个及均匀分布的最多 48 个，去重后生成 L0 模板。没有复制模板来扩大批次，也没有把全部 DEV 文件数当物理根数。

| 样本 | 唯一 DEV 根 / occurrence | 对照记录数 | 有 GLB / empty | partial（包含于有 GLB） | 批次字节 B | 每批省去中间复制 B |
|---|---:|---:|---:|---:|---:|---:|
| substation01 | 285 / 285 | 63 | 63 / 0 | 0 | 38,896,788 | 38,886,021 |
| substation02 | 976 / 3326 | 64 | 38 / 26 | 17 | 4,544,089 | 4,533,152 |
| substation03 | 162 / 162 | 58 | 58 / 0 | 0 | 15,416,246 | 15,406,329 |
| substation04 | 207 / 532 | 60 | 60 / 0 | 0 | 5,766,722 | 5,756,312 |

245 条记录中有 219 个实际 GLB，26 条 empty；substation02 的 17 条 partial 保留原诊断，不作为完整几何。每个 GLB 的旧/新解包结果都与生成时 SHA 一致，并分别经过实际 GLTFLoader 核对顶点、法线等属性、索引、世界矩阵和材质；只忽略加载器新生成的资源 UUID。两条路径的元数据、状态与诊断一致。

用这些真实产物构造与原生 `GIMR v2` 对齐的批次；这不是从原生暖启动录制的 IPC 批次。每个环境先预热 10 对，然后交替先后顺序执行 100 对旧/新解包；原生传输、产物生成和几何核对不计入计时。浏览器在三个全新 headless 进程/profile 中重复，测量时不运行构建或其他基准。保留全部样本，不删除慢点。

## 浏览器结果

下表 p50 为三次各自 p50 的中位数；p95 为三次各自 p95 的最小–最大范围，单位 ms。不是合并分布的 p95。

| 样本 | 旧 p50 | 新 p50 | p50 减少 | 旧 p95 范围 | 新 p95 范围 |
|---|---:|---:|---:|---:|---:|
| substation01 | 20.30 | 10.70 | 47.3% | 33.90–36.20 | 16.40–17.60 |
| substation02 | 3.30 | 1.80 | 45.5% | 5.50–7.30 | 2.60–3.20 |
| substation03 | 8.20 | 4.00 | 51.2% | 10.60–11.20 | 6.10–7.20 |
| substation04 | 3.70 | 2.00 | 45.9% | 5.30–6.00 | 3.10–3.50 |

每个样本的三次 p50/p95 均改善，但不保证单点最大值降低：第三次 substation02 的 max 从 8.80 ms 到 10.30 ms，其余两次分别为 9.80→6.80、8.90→3.30 ms。保留该点；它不改变同次 p95 的 5.50→2.70 ms，但不能据此宣称所有尾延迟无回退。

## Node 对照与波动

| 样本 | 旧 / 新 p50 ms | 旧 / 新 p95 ms | 旧 / 新 max ms |
|---|---:|---:|---:|
| substation01 | 30.35 / 12.96 | 48.70 / 29.15 | 60.65 / 46.47 |
| substation02 | 1.92 / 0.99 | 4.23 / 7.03 | 11.01 / 16.46 |
| substation03 | 7.35 / 3.96 | 12.62 / 7.93 | 20.71 / 10.65 |
| substation04 | 2.39 / 1.41 | 5.90 / 3.87 | 13.00 / 9.05 |

Node 的 substation02 尾延迟回退不能隐藏，也不能无证据全归因于 GC。Node 数据在真实模板生成及几何检查之后取得，浏览器则以新的进程只解包同一份固定产物。浏览器三次重复及明确省去一份记录副本共同支持保留这项局部改动，不将一次 Node 中位数当作完整性能验收。

减少的复制字节数来自实际记录长度，是分配/搬运工作量，不是实测进程私有内存降幅。批次输入、最终 GLB、原生/IPC 临时副本、解析后模板与 GPU 驻留仍存在；6 GiB 内存门槛与工作集回收需后续单独验证。

## 复现与证据

在 `desktop/` 执行：

```powershell
npx vitest run --config scripts/benchmarks/dev-cache-decode.config.ts
# 另一个终端运行 npm run dev -- --host 127.0.0.1 后：
node scripts/benchmarks/dev-cache-decode-browser.mjs
```

生成脚本要求四个样本，缺失直接失败，不使用 skip。浏览器入口只读取生成在 `output/parse-reuse/` 的固定产物，使用独立 profile 和 loopback 来源服务；退出时关闭本次所属进程，不操作日常缓存。脚本只输出原始记录，不自动判断验收通过。

本地证据：`output/parse-reuse/substation01-decode.json` 至 `substation04-decode.json`、各站 `*.cache`、`paired-summary.json`、`decode-benchmark.log`，以及三次 `browser-2026-10-25T03-20-58-506Z.json`、`browser-2026-10-25T03-21-21-745Z.json`、`browser-2026-10-25T03-21-38-371Z.json`。原始日志、真实属性和几何留在忽略目录。

最终检查：

- 四站专项 4 项通过，无样本跳过；245 条记录及 219 个实际 GLB 的身份、元数据、缓冲区所有权和几何对照通过。
- 桥接定向 4 文件、24 项通过，覆盖非零偏移、截断/尾随数据、默认独立条目、相邻模板隔离、损坏记录、拆批及配额。
- 默认单元 128 文件、1105 项通过，3 项既有条件跳过。
- 现有真实样本套件 3 文件、11 项通过，2 项因线路解包目录缺失跳过；包含四站语义/引用/属性/空间快照、重 MOD 轮廓与四站连接几何检查，耗时 301.54 s。两项线路 skip 不作为通过，四站输入均实际执行。
- TypeScript/Vite 构建通过，保留既有大 chunk 等告警；`git diff --check` 通过。

完整日志为同目录的 `bridge-tests.log`、`unit-tests.log`、`sample-regression.log`、`build.log`。严格样本入口已有 O-09，未以本轮专项或普通样本通过替代其验收；本轮未做原生 Release 整站运行。
