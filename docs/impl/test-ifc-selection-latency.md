# IFC 选择延迟：最近候选优先的探索与淘汰

日期：2026-10-26。对应 O-07。

## 结论与取舍

**不保留“先核对最近首命中，跳过远处来源”的候选实现。** 原型在隐藏对象的跨来源回退场景中改变了命中身份，未通过正确性预检。候选只在忽略目录运行，没有替换产品实现，没有生成候选 Release 包。

四站的首次分段观察也没有提供足以支持该路线的收益证据。没有执行后续三轮 Release A/B，不宣称满足四站 p95 降幅中位数至少 15% 的保留条件。计划中的完整原生组合场景、每站至少 20 个不同对象、三轮交替对照和内存回退验收均未完成；候选在前置正确性门槛淘汰后，不以错误拾取的低耗时作为优化成果。

最终产品源码保持实施前状态；O-07 和 O-05 继续开放。没有新增仓库测试文件或保留临时产品埋点。

## 原型为何不能保留

已安装 Fragments 的 `RaycastController.getNearest` 在两个命中都带 `raySquaredDistance` 时使用 `32 × raySquaredDistance + cameraSquaredDistance`；其中一个不带该字段时按相机距离比较。应用跨来源排序和隐藏回退排序使用 `rayDistance ?? distance`，二者不是同一排序契约。公开首命中没有提供其余命中在应用排序下的严格距离下界。

独立原型保留并行首射线、隐藏祖先排除、隐藏后的全射线与可见性批查，并将当前首命中中存在 `rayDistance` 或非有限距离的场景退回原实现。即便如此，仍有下面的合法返回形状反例：

| 来源/对象 | 首命中或回退 | `distance` | `rayDistance` | 可见 |
| --- | --- | --- | --- | --- |
| A:1 | A 首命中 | 2 | 未提供 | 是 |
| B:1 | B 首命中 | 3 | 未提供 | 否 |
| B:2 | B 的全射线回退命中 | 100 | 0.5 | 是 |

B 的首射线可按相机距离返回 B:1；它与 B:2 比较时，并非两者都有射线距离。原实现检查 B:1 不可见后，通过全射线和可见性查询得到 B:2，跨来源按 0.5 与 2 比较，返回 B:2。原型先确认 A:1 可见后提前结束，错误返回 A:1。所有**首命中**均没有 `rayDistance`，所以只对首命中增加字段检查仍不足以保守回退。

该反例是公开返回类型与已安装实现相容的合成契约检查，不声称已在四站真实路线观察到它。四站未遇到该形状不构成全边界保证。原型的普通最近对象、隐藏回退落后另一来源、隐藏回退仍最近三个检查与原实现一致，第四个检查不一致，结果记录为 `accepted=false`。

要安全剪枝，需要额外证明来源全部候选的统一距离下界，或验证全部相关来源的可见性/回退。当前公开首命中数据不足；后者恢复了主要查询成本。本轮不通过改变距离语义、引入跨点击可见性缓存或再次忽略 L1 掩码来扩大方案。
