# 桌面版 0.2 工程实体重构计划

范围：桌面变电工程，一个工程一份 GIM；首期提供“工程组成”和“来源”两个视图。本文作为实施与验收基线；现有重构草稿按下列阶段复核，不以文件存在或局部接入认定阶段完成。

**先建立施工、运维理解的工程整体，再独立组织工程和集合渲染。GIM 层级、设计拆分深度以及当前软件的粒度判据均不决定工程实体边界。**

在 `desktop/` 运行 `npm run engineering:baseline`，从本地 `research/` 的完整来源扫描生成经源 SHA/规则指纹校验的独立参考，输出到 `output/refactor-baseline/`；运行 `npm run engineering:geometry-input` 从原包准备独立几何证据，再运行 `npm run test:engineering:nine`。后者包括来源扫描到领域归一化对照，以及原始解包目录的 CBM/DEV 抽取检查；必需样本和输入缺失会失败。原始解包目录的身份必须与研究中的源 SHA 相符。

`npm run test:engineering:worker` 在独立 headless Edge/profile 和 loopback Vite 中检查真实 Worker、Blob/共享二进制缓冲区传输、缓存恢复与取消，不访问日常浏览器或应用缓存。该检查是功能夹具，不代替原生 IPC、真实工程渲染或性能验收。

界面和集合操作采用独立浏览器中的生产构建验证，经真实文件入口打开原始 GIM；覆盖组成、来源、搜索、显隐、精化及工程切换。按当前验收方式，浏览器负责实际应用操作，原生侧保留 IPC、SQLite、缓存和性能验证，不以 Windows 解锁作为界面验收前提。浏览器/WASM 打开时间和 IFC 局部缓存命中不能计作原生完整暖启动。实际渲染与关键操作、资产构建指纹及各样本覆盖范围记录在 `output/browser-engineering-v3/`，完整九工程路线和性能矩阵仍待补齐。

九工程的原始来源测试同时构建生产 IFC 外露接口、整体及两视图，校验完整成员覆盖，并对来源完整的样本验证来源/投影缓存往返；输出位于 `output/refactor-navigation-v1/`。其中来源不完整与分类未知分别报告，部分结果不得记作完整缓存通过。来源完整的八工程通过缓存往返；a31 的 258 条未解析引用保持部分状态。完整结论以当前源码指纹及本次测试输出为准。

现有生产 IFC 差异报告记录：两工程共 1,930 个原 Name 为占位符的对象依据自身 Description/ObjectType/Tag 进一步分类。实施时复核这些字段证据与整体归属；额外端口、洞口、图示保留来源，不新建默认实体。报告位于 `output/refactor-baseline/*production-ifc-differences.json`，不能将改进后的类别数量冒充研究原始统计。

当前草稿与既有验证不证明两视图、集合几何覆盖、原生桌面操作或性能验收完成。后续先补契约与覆盖，再进行产品切换。

## 1. 依据与交付边界

领域依据按 [分类与粒度总则](../../research/01-分类与粒度总则.md)、[设备目录与组合边界](../../research/02-设备目录与组合边界.md)、[材料与构件目录](../../research/03-材料与构件目录.md)实施；[九工程验证](../../research/05-九工程归一化验证结果.md)和[工程合理性评价](../../research/06-工程合理性评价.md)提供案例及限制。

[redesign](../../research/redesign.md)作为总体方向；其中“第一阶段只做来源视图”、逐产品暴露和设备级 GLB 等表述，以当前两视图、工程整体及表示集合的边界为准。当前业务树实现只用于查找替换点，不作为分类真值或兼容目标。

- 设备兼容通用目录 2018、2025 口径；构件和装置性材料按研究目录归一。目录编码是项目编码，不宣称国网标准编码。
- 主变本体及已确认归属的中性点装置共同表示主变整体；端子箱、独立控制柜、基础等保留独立实体及关联。
- 内部设计零件留在来源域；梁、门、盖板等有独立工程意义的对象仍是整体，不将整栋建筑或同类对象合成一个实体。
- IFC 只提取 GIM 交付的外露产品及必要语义证据；内部类型、属性、几何定义不升级为工程实体。外露产品还需判断整体边界。
- 不扩展台账、算量、出图、质量验评、运维工单及模板编辑器；不实施跨导出身份承接。桌面线路、Android、独立设备的产品流程保持现有范围，共享底层修改须回归。
- 项目尚未正式发布：只支持当前缓存契约；旧缓存直接失效重建，不提供迁移、旧格式读取或历史兼容分支。已被替代的业务树及选择代码删除；线路、独立设备仍使用的共享能力属于现役流程。

## 2. 目标架构与数据契约

```text
GIM / IFC → 来源适配与证据索引 → 工程实体标准化 → 工程组成投影
                     │                 │
                     ├→ 来源投影       └→ 实体—表示集合绑定
                     └→ 几何编译 / 资产与实例索引 ─┘
                                          ↓
                                 整体选择、定位、高亮、显隐
```

几何资产可从来源独立编译；工程实体准备好后绑定集合。实体识别不等待 Viewer、网格、LOD 或几何加载完成。实体粒度变化只重建成员绑定，不强制重新三角化。

| 契约 | 内容与约束 |
|---|---|
| `SourceRecord / SourceLink` | 原始文件身份、引用 occurrence、字段来源及原行、真实装配边、别名及歧义；来源引用图与展示树分开 |
| `NormalizationEvidence` | 从来源提取的对象角色、工程编号、用途、类型、装配声明及冲突；保留字段所描述的对象，不能把上级名称当当前组件身份 |
| `EngineeringEntity` | 整体 ID、目录类别、名称、规范属性、识别状态及证据引用；没有强制业务 `parentId`，不嵌入 CbmNode、Mesh 或运行时模型对象 |
| `SourceMembership` | 来源归入整体、待确认集合或仅来源的去向；一份来源的主归属唯一，别名/辅助证据另存关联，不重复计数 |
| `EntityRelationship` | 独立整体之间的工程关系、依据及状态；服务对象、安装关联与内部成员不是同一种关系 |
| `PendingWhole` | 实例身份或宿主不能确定的来源集合及候选；不冒充一台已确认设备 |
| `RepresentationIndex` | 资产、放置实例、源对象覆盖范围、坐标、表示版本和可替换关系；逻辑身份与运行时 Fragment/LocalId 分开 |
| `EntityRepresentationSet` | 整体到表示集合的绑定及反向拾取索引；表示缺失、共享和歧义显式保留 |
| `ViewProjection` | 视图节点、实体引用和分组依据；一个实体可多处引用，节点 ID 与实体 ID 分离，集合统计按实体去重 |

身份限定在源包版本内：源 SHA + 包内实例证据确定身份范围，不以类别、显示名、业务父节点或数组遍历顺序生成实体 ID。同模板的不同放置实例必须独立；规则造成实体拆分/合并时发布新快照并重新解析选择目标，不把旧 ID 强行沿用。未知类别、待归整体、组成完整性、表示可用性分别记录，不能用一个“完整”标记混同。

物理实例另立 `SourceGeometryOccurrence` 契约：来源 occurrence ID、模板路径、真实装配路径、累计变换、单位及坐标基准。由完整来源引用图产生，不接收工程树节点；同一文件被不同路径引用仍是不同放置实例。几何编译按模板复用、实例独立放置，PARTINDEX 只按实际子 DEV 身份挂接，不产生第二个物理根。工程实体再通过 `SourceMembership` 绑定这些实例及其局部表示，不能一实体生成一个几何 seed。

建议模块边界（名称在第一阶段落实）：

| 位置 | 职责 |
|---|---|
| `desktop/src/gim/engineering/` | 来源适配、DEV/FAM 角色解释、IFC 外露证据、来源到中立语义证据的转换 |
| `desktop/src/engineering/`（新增） | 无 UI/数据库/Viewer/GIM parser 依赖的领域契约、整体归一化、关系和工程组成投影；不接收 F2/F3/F4 层级作为领域判断条件 |
| `desktop/src/services/` | Worker 调度、快照发布、缓存、表示绑定、选择和生命周期编排 |
| `desktop/src/viewer/` | 既有几何编译与渲染能力、集合高亮/显隐/定位；不判断工程类别和实体宿主 |
| `desktop/src/ui/` | 两视图、整体属性摘要、来源追溯、待确认内容及搜索 |
| `desktop/bridge/`、Rust SQLite | 分域持久化及事务，不在数据库读取阶段重新判工程语义 |

## 3. 两视图和整体交互

**工程组成**采用内置、版本化的建筑工程/安装工程模板，规则见[工程组成模板](../../research/08-工程组成模板.md)。建筑工程组织有依据的建筑物及楼层、构支架和独立基础、电缆沟、站区性建筑、照明、暖通空调、给排水、消防；安装工程组织主变、各电压配电装置及间隔、无功补偿、站用电、二次及直流、电缆和接地。末端按类别检索整体，不增加设备/材料/构件大层级。

系统和单元读取明确工程声明，不使用 F 层级作业务含义，不将额定电压或默认 IFC 容器名当工程关系。s01 的 36S/24S 等编号可作为间隔，s03 的“主变系统01/主变01”可建立主变系统归属。建筑物或间隔有声明但缺少整体关联时保留可追溯的待确认分组，不制造实体或几何范围。分组计数按整体身份去重，不冒充台套。

**来源**保留 CBM 引用组织、DEV 实际装配及 IFC 文件—空间/外露对象组织；包括未被 CBM GUID 精确挂接的 IFC 对象、未知来源和原始冲突。内部类型作为属性或证据按需查看，不展开另一棵 IFC 内部定义树。来源行可跳转整体；组件级歧义但整体唯一时允许整体追溯，候选跨整体则展示候选。

普通三维拾取、工程树选择与搜索以整体为对象；端子箱等独立设备不会被其宿主整体的选择吞入。来源模式允许查看原始来源及其表示范围，但必须明确当前选择的是来源，不将其提升为工程实体。待确认集合可查看可用表示，同时标识范围未确认。

属性摘要按整体展示类别、工程名称和有依据的参数；内部属性留在来源。不能把三个单相本体的参数盲目相加，或把冲突字段任选一个作为整体属性。大集合选择分批处理；尚未加载的成员继续保持逻辑选择，表示到达后增量高亮，不自动触发全部成员的精细几何。

## 4. 实施顺序与阶段验收

阶段按 P0 → P1 → P2 → P3 → P4 → P5 → P6 推进，每阶段可独立评审。现有草稿可缩短实施，不跳过阶段验收；P1 契约确定后可准备物理实例适配，P2 后可准备视图，但产品切换须等完整链路验收。每阶段保留可运行桌面版本。

| 阶段 | 工作与产物 | 通过条件 |
|---|---|---|
| P0 研究迁移与基线 | 核对 `research/` 路径、源包/扫描/规则指纹；保存可复现参考及匿名夹具；审计现有草稿与缓存版本。冻结旧版 Release 和固定桌面操作路线 | 13 项研究回归及 196,555 条来源基线可复现；缺少必需样本直接失败；不改校验值冒充复跑。记录构建指纹、环境、缓存条件及性能预算 |
| P1 来源与领域契约 | 落实上节接口及身份/状态；建立独立来源图适配，抽取必要 FAM 和 IFC 语义；梳理 CBM parser 是否过早裁掉候选 | F2/F3/F4、包装层变化不裁掉合法来源；同模板多实例保留；GUID 重复/缺失和真实 DEV 子装配歧义可追溯；纯领域模块依赖检查通过 |
| P2 整体标准化 | 将研究规则转为可测试的 TypeScript 领域规则与目录数据，先判角色再分类，建立平级组合、主变成组、独立对象和待确认集合；在 Worker 内生成快照 | 九工程逐来源去向可核对；关键案例通过；粗细拆分/平级嵌套/输入顺序变换保持同等工程结果；差异逐项解释，不能只对齐总数 |
| P3 分域缓存与打开编排 | 来源、整体/成员/关系独立快照；提供投影缓存接口；原子写入及完成标记、失败重建、取消/释放；由来源语义就绪启动构建 | 冷暖实体/成员/关系一致；无需场景即可构建；损坏、版本变化、缺失 IFC 和切换工程不能发布伪完整快照；暖开不重跑有效归一化；缓存失败不丢可用结果 |
| P4 表示集合与统一选择 | 先以来源 occurrence 替换旧树物理根输入；再接来源覆盖、整体绑定、反向拾取和集合操作。保留模板及 IFC 资产、坐标与 LOD 能力 | 同模板多实例/同 CBM 多引用无漏绘误放；多来源整体可整体操作；独立端子箱可单选；父子表示不重复；LOD 替换保持选择；未归属几何不丢；不可分离粗模型明确降级 |
| P5 两视图接入 | 工程组成默认页、完整来源页、双向定位、整体搜索与属性摘要；投影在 Worker 构建并独立缓存，虚拟列表按需生成；两视图共享领域 ID | 普通树不展开设计零件；来源证据完整可查；未知/待确认可见；命中零件可引导到整体和来源；无几何整体可查看；暖恢复不重做有效分类及投影 |
| P6 桌面切换与清理 | 九工程冷暖桌面验收、性能对比、线路/设备回归；默认切换新链路，删除已替代旧逻辑，更新正式文档 | 功能、守恒、缓存、竞态、几何及性能门槛全部通过；正式导航仅两视图；旧业务树不再创建工程身份，空间/功能导航退出主流程 |

P2 是领域决策验收点，P4 是渲染边界验收点，P6 才是产品完成。不得以 Python 研究通过或树已可显示替代桌面集合渲染验收。

P4 分两次交付：先验证物理实例清单、引用链和矩阵，再验证实体集合选择。P5 先用固定工程案例确认组成与来源的表达，再接全量投影、缓存和虚拟列表。每次交付附输入指纹、差异、验证结果及未完成项。

## 5. 现有模块迁移清单

| 当前入口/模块 | 迁移方式 |
|---|---|
| `gim/cbmParser.ts`、`substationEvidence.ts`、`ifcSpatialParser.ts` | 复用原始解码、引用和 STEP 事实提取；审计层级裁剪、子件别名与身份假设。空间 parser 提供证据，不要求先加载三维场景 |

| `substationRuntime.ts`、后台协调器、`app/state.ts`、清理服务 | 增加实体/投影/表示各自就绪状态和会话提交守卫，避免一个 pending 状态覆盖所有阶段 |
| `collectCbmDeviceInstances`、DEV LOD/GLB、IFC regional/Fragments、坐标对齐服务 | 将物理实例输入改为独立来源 occurrence 契约；复用模板编译、逐边矩阵、放置和缓存；补覆盖及成员映射，不以目录规则生成第二套几何 seed |
| `ui/cbmTreeView.ts`、`businessTreeView.ts`、搜索/属性面板 | 接入两种独立投影；复用虚拟窗口和 DOM 基础，移除按模式变化的三/多选项卡导航 |
| bridge/database、Rust `db.rs` | 添加独立快照契约；旧业务快照不直接转换成实体真值，有来源缓存则从来源重建 |

按阶段替换主链，不保留旧业务树的运行开关、身份、选择、Worker 或快照读取路径。失败时展示来源及错误状态；当前契约缓存损坏可按域重建，这不构成历史格式兼容。空间索引继续作为来源与关系证据，不因移除空间选项卡而删除仍需使用的事实提取能力。

## 6. 缓存与增量失效

以[现有缓存域](../architecture.md#当前缓存域)及源码契约为迁移起点，不统一提升所有 parser 版本。

| 产物 | 指纹/依赖 | 变化后的最小动作 |
|---|---|---|
| 来源证据快照 | 源 SHA、来源 parser、外露证据 schema | 重新提取受影响来源，重建依赖实体与视图；几何是否失效另按几何输入判断 |
| 工程实体快照 | 来源快照 ID、实体 schema、目录/归一化规则 | 重建整体、成员、关系与依赖投影、表示绑定，复用有效几何资产 |
| DEV/IFC 几何资产 | 几何源、编译器、精度、放置/坐标及依赖版本 | 重编受影响资产；实体识别不重跑 |
| 实体表示绑定 | 实体快照 ID、表示清单及覆盖策略 | 重新绑定集合；不重新解析全部 FAM 或编译未变化网格 |
| 工程组成投影 | 实体快照 ID、模板和映射规则 | 仅重建投影；来源视图按来源快照独立恢复 |

每域记录输入集合、构建状态、错误和版本；分块数据库产物最后以事务发布完成标记，文件快照经校验后原子替换，未完成产物不能命中完整缓存。局部 IFC 缺失可展示部分结果，其他域可独立可用；后续完整快照发布时按稳定来源重新解析当前选择，遇到实体拆分/合并则显示候选，不沿用过期成员集合。来源空间/系统上下文随来源快照或独立证据产物恢复，组成投影不能等待场景包围盒才可建立。原始来源归属统计与渲染覆盖统计分别验收。首期只承诺域级失效，不承诺跨导出的细粒度增量比对。

## 7. 必须通过的验收

### 领域与来源

- 九工程全量逐来源守恒：整体、待确认集合、仅来源三类去向可核对，无静默遗漏、重复主归属或悬空成员；同一工程实体在多视图只计一次。
- 固定案例：12 个借用上级 FAM 名称的内部件不变成中性点设备；六个单相本体按 #2/#3 归两组主变；208 来源电容器组成整体；泛称“接地变”不强认唯一设备；端子箱独立。
- 6,628 条细部歧义保留；研究中 6,625 条可在整体层唯一挂接，产品差异需逐项复核。不可把该比率作为未知新样本的准确率。
- 增加层级标签、包装层、平级/嵌套拆分、粗细表达和输入顺序变换测试；比较工程语义及成员覆盖，不要求不同导出包的原始 ID 一致。
- 155,947 个研究整体候选、28,401 个未知和 478 个待归集合是对照基线，不能当真实台套验收指标；改进规则必须有来源证据和差异清单。

### 几何与交互

- 对固定代表案例核对完整表示覆盖、矩阵/单位、父子覆盖、跨 DEV/IFC 表示及独立箱柜选择。DEV/IFC 无可靠同一性证据时不强合并，也不凭同名删几何。
- 覆盖来源仅存、无几何整体、部分成员未加载、粗模型无法分离、LOD 切换及共享表示；显隐和拾取均有明确目标，不能泄漏成其他实体操作。
- 跨工程打开/关闭、快速连续选择、Worker 失败、缓存损坏时旧结果不能提交；取消不写完整标记。普通整体选择不自动升级到全体 L2。

### 执行方式与性能

- P0 在固定机器、旧版 Release、相同样本和操作路线补齐冷暖基线；P6 在新版本重复。九工程每样本各三次真冷、三次有效暖，独立数据库/profile，不并行运行。记录首个可浏览画面、导航可交互、基础几何完成、选择延迟及内存峰值；新版本另外记录来源、整体、投影就绪时间，旧版不存在的指标记不适用。
- 固定路线：打开 → 展开工程分组 → 搜索主变及内部件 → 选择本体/端子箱 → 跳转来源 → 仅看选中/恢复 → LOD 替换及显式精化 → 关闭/切换工程；大集合、未知 Proxy 和无几何整体另设固定点位。
- 复用[既有性能口径](../performance.md)：选择至高亮 p95 ≤100 ms、缓存属性概览 p95 ≤200 ms、暖基础表示 ≤20 s、冷基础表示 ≤60 s。它们是目标，旧版已有未达标和缺测项；P0 补测后逐样本冻结本次预算，建议同机打开/基础几何时间的中位数回退不超过 `max(基线×10%, 1 s)`，内存不新增超过 10% 的回退，交互尾延迟单独判断。既有未达标与本次回退分别报告，阻塞两视图/完整来源或造成漏绘、选择越界的缺陷必须解决。
- P6 不得只报树出现时间，或用减少来源、降低几何程度、扩大跳过范围换取未说明的性能通过。此前性能文档的九工程一次冷/七站三次暖不能代替本次完整矩阵。
- 领域/投影纯单测、表示集合集成测试、真实 SQLite 往返、九工程严格样本测试、生产构建的浏览器操作与原生 IPC/缓存检查分别执行；样本缺失/跳过不能算九工程通过。
- `desktop/` 内执行 `npm test`、`npm run test:sqlite`、`npm run test:sample`、`npm run test:substation:strict`、`npm run build`；Rust 变更执行 `cargo check --manifest-path src-tauri/Cargo.toml`。现有样本命令不保证已覆盖新九工程验收，P0/P2 必须补齐专用入口与缺失即失败的检查。
