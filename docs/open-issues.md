# 问题与已知限制

本页是未关闭缺陷、已明确口径与已接受限制的唯一权威来源，区分以下事项：

- **Open defects**：仍需修复、验收或决策的代码缺陷/实现风险；
- **已明确口径**：判定规则或产品边界已经确定、不再作为独立待办讨论的事项；
- **Known / accepted limitations**：当前版本明确接受的能力或性能边界。

样本研究与外部业务候选不在本页维护；格式与实现正文说明当前行为。移动端未完成验收项集中在[移动端验收与遗留问题](#移动端验收与遗留问题)，性能实测与验收证据以开发者本地 `tmp/gim-bench/` 私有报告为准，`output/` 默认为匿名派生视图（显式非匿名 survey 例外）。

当前以相对历史版本不回退为性能目标；正确性修复成本单列证据，绝对阈值不作为回退豁免。来源索引按需建立、可重建来源检查点与空闲 Worker 终止、识别字段单次筛选及基础表示优先调度已落实。导航、几何提交与可见实体绘制分别记录，可后置工作在首个模型帧后启动。历史提交时点不能直接冒充可见几何时间。测量缺口、来源 PARTIAL 和未验证边界继续保留；定向结果不替代全 L0 或人类基线批准。

优先级与状态：

- P0：正确性或核心流程阻断；
- P1：主要效率/可维护性问题，或拟交付核心需求；
- P2：增强项，或需场景确认的候选；
- 表中“优先级/状态”列描述代码缺陷的当前证据；性能与最终验收由开发者本地按固定路线手动执行，结果以 `tmp/gim-bench/` 报告为准，不在本页作为开放缺陷重复追踪。

## Open defects

当前没有已确认、尚未修复的桌面代码缺陷。来源局部失败、生命周期与功能路径继续由回归用例守护；性能和人工验收边界仍见下表。

0.2.3 已覆盖设备 52 项、材料 39 项、建构筑物及其他设施 30 项标准索引、表2部件词汇及常用 IFC 类型。宿主恢复、仅属性来源和标准投影具有独立证据，缺少证据或多候选仍待归。真实工程实例边界、恢复后的成员和性能仍需开发者核验；单测、工具对照或原生运行时 PASS 不构成人工真值或基线批准。几何/属性要求目录仍限已选字段，复杂 IFC 属性解释与标准 Validator 未实现。

## 已明确口径（不作为独立待办）

以下为已确定的判定边界，不再重复讨论：

- **连接归属**：多义候选不按距离、名称或模板相似自动归属；必须有可审计的端口/连接证据或明确业务规则。
- **IFC 终态与 SLO**：缓存落盘等待不计入模型加载 SLO。模型队列完成后状态栏保持“IFC 已结束”，迟到进度不再覆盖；缓存失败单独附加到终态汇总，会话切换拒绝旧回调。
- **整体搜索往返**：浏览器功能夹具保持整体搜索、来源揭示及返回整体的完整断言；该功能验证不替代真实工程、几何或性能验收。
- **测量分类**：输入损坏、环境/启动故障、产品不变量失败必须分列；不能把样本或基础设施问题写成产品 FAIL。短命/未执行 Worker 堆与自动完成缺失各自单列并保持 INCONCLUSIVE，不补零或伪造 PASS。
- **大装配失败**：不以文件大小/图元数推断容量或编译根因；需要受控 `capacity-exceeded` 或具体解析错误。
- **500 m 守卫**：它是默认损坏安全阀，不是通用 `source-invalid` 判据；单一标准二进制 STL 可凭独立源范围、三角形数和精度检查获得有界豁免，XML 与混合来源不适用。当前契约见 [DEV 几何](architecture/dev-geometry.md#stl-与-gl)。

这些口径本身不是开放缺陷；仍需代码修复的由上表追踪，验收与性能由开发者本地手动记录。

## Known / accepted limitations

| ID | 限制 | 当前证据/行为 | 边界与重新立项条件 |
|---|---|---|---|
| L-01 | 大 IFC 单对象精化成本高 | substation02 的完整原路径在 120 s 窗口内可能尚未提交钢结构 LOD0；单对象首请求仍要读入并 `OpenModel` 整个源文件，局部实验约 16 s，WASM heap 容量约 808 MB。 | 不宣称任意对象即时精化；跨表示位置/复杂开洞仍需逐对象证据。若现场要求单对象秒级精化，重新立项。 |
| L-02 | IFC 近景区域子集有类型边界 | 板件/杆件/紧固件和已识别小孔走区域子集；未缓存类型或回退路径仍可能重开整源。 | 以自动视域/30 m 和既有小孔策略交付；扩展前需证明单位、放置、外观和保留开洞等价。 |
| L-03 | DEV 单工作单元存在不可中断长尾 | L0/L1 已不执行 CSG；L2 的单次 CSG 和 DEV 导出仍不能在调用内部中断，循环间检查点覆盖不到；进程内存驻留较高，完整转换 Worker heap 尚无精确公开测量。 | 输入响应观测不覆盖全部后台工作；不能把“暖语义命中”表述为“全站几何就绪”。若长尾造成可见卡顿，需拆分工作单元或进程隔离。 |
| L-04 | 未准入 DEV 来源仍经主线程 RPC | 派生缺失时已知大小来源可进入受控不可变 File 工作集，由 Worker 直接读取；未知、过大、读取失败或压力下保留原生懒读。准备与已有任务并行，安装前已发起的 RPC 不会被取消。 | 首屏与提交目标仍未全部达到；按读取、排队、反序列化及放置阶段记录判断后续优化，不因局部 MOD 烘焙快而宣称整站就绪。 |
| L-05 | Spatial 未复用源 SHA | IFC Spatial 仍逐文件扫描 STEP，未从完整解析结果生成等价语义输入，也未跨阶段复用 SHA。2026-11-08 s03 首次暖出现 `spatialSemanticCacheRestore`（约 1.9 s），但仍对 1 个 IFC 做 STEP scan；暖恢复不等于 SHA 复用。 | substation04 真冷首屏约 9.3 s；`变电 IFC 空间索引` span 已与 finalize/写入分离。若 Spatial 重新成为主瓶颈，再立项。 |
| L-06 | 整站流畅度与历史相对回退仍待核对 | substation02 原生 30 秒真实路线单次 A/B：实例化关闭 p95/p99 为 76.4/97.3 ms、7191–7214 次绘制；开启为 48.6/69.5 ms、2622–2645 次绘制，但基础表示启动回退，因此默认关闭。2026-11-12 三次重复：`feae87e` 线路 36/36 PASS；当时工作区候选（build `efcc96bf…`）变电 18 PASS/6 PARTIAL。旧 v2 绝对目标报告保留，不改写成当前性能结论；后续来源/识别/调度修复须按各自构建重新对照。 | 优化开发须有可测的明显提升；功能和正确性修正应避免过大回退，具体成本与依据单列。每次实测保留逐样本及重复结果，同时报告百分比、节省秒数、绝对耗时和整批总和，不用中位数掩盖长尾；不设置统一时间、内存或增长比例验收线，是否接受由开发者判断。导航、提交与可见几何分别比较；正式基线由开发者显式决定，Agent 不自动批准。 |
| L-07 | IFC 跨表示等价性只有局部证据 | 小 IFC 验收包（575,414 bytes）在同一 GlobalId/ExpressId 下 LOD0/1/2 包围盒中心误差约 4.21 微米；只覆盖该对象/输入。 | 不证明全站跨表示等价；逐对象验收不能由整体偏移或拟合 T 替代。 |

| L-09 | Wire/Cable 中心线只是视觉辅助 | 管径使用源 `D`，另叠 1px 中心线保证所有 LOD 可见；中心线不参与拾取或尺寸测量。 | 电气连接判断以 Wire/Cable 是否存在、起止点与路径为准，不能用中心线/管径做工程测量。 |

## 维护规则

- Open defect 关闭后删除条目，在对应修复提交中保留判定与验证依据；性能验收记录由开发者本地 `tmp/gim-bench/` 私有报告保存，`output/` 默认匿名；显式非匿名 survey 只允许展示标准方案号和已匿名验证样本名；
- 移动端验收项（M-*）关闭后同样删除条目，并与 Open defect 使用相同的证据规则；
- limitation 状态变化时原地更新证据/边界，不按日期追加流水；
- 已明确口径单列在“已明确口径”节，不重复作为独立待办；对应实现/验收仍由 Open defect 追踪；
- 不把“已接受限制”改写成“没有风险”；每条 limitation 必须写明当前边界和重新立项条件。
