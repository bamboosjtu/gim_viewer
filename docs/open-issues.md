# 问题与已知限制

本文件区分两类事项：

- **Open defects**：仍需修复、验收或决策的代码缺陷/实现风险；
- **Known / accepted limitations**：当前版本明确接受的能力或性能边界，不是“问题不存在”，而是暂不阻塞发布。

样本研究、设备验收与外部业务候选不在本文件维护；格式与实现正文说明当前行为。关闭项的判定与验证依据保留在对应修复提交；性能验收口径与记录见 [性能](performance.md)。

优先级：P0 为正确性或核心流程阻断，P1 为主要效率/可维护性或拟交付核心需求，P2 为增强或需场景确认的候选。

## Known / accepted limitations

| ID | 限制 | 当前证据/行为 | 边界与重新立项条件 |
|---|---|---|---|
| L-01 | 大 IFC 单对象精化成本高 | 02 的完整原路径在 120 s 窗口内可能尚未提交钢结构 LOD0；单对象首请求仍要读入并 `OpenModel` 整个源文件，局部实验约 16 s，WASM heap 容量约 808 MB。 | 不宣称任意对象即时精化；跨表示位置/复杂开洞仍需逐对象证据。若现场要求单对象秒级精化，重新立项。 |
| L-02 | IFC 近景区域子集有类型边界 | 板件/杆件/紧固件和已识别小孔走区域子集；未缓存类型或回退路径仍可能重开整源。 | 以自动视域/30 m 和既有小孔策略交付；扩展前需证明单位、放置、外观和保留开洞等价。 |
| L-03 | DEV 单工作单元存在不可中断长尾 | L0/L1 已不执行 CSG；L2 的单次 CSG 和 DEV 导出仍不能在调用内部中断，循环间检查点覆盖不到；暖启动验证不代表完整几何命中；进程内存驻留较高，完整转换 Worker heap 尚无精确公开测量。 | 输入响应观测不覆盖全部后台工作；不能把“暖语义命中”表述为“全站几何就绪”。若长尾造成可见卡顿，需拆分工作单元或进程隔离。 |
| L-04 | 未准入 DEV 来源仍经主线程 RPC | 派生缺失时已知大小来源可进入受控不可变 File 工作集，由 Worker 直接读取；未知、过大、读取失败或压力下保留原生懒读。准备与已有任务并行，安装前已发起的 RPC 不会被取消，不能宣称所有场景零 RPC。 | 首屏与提交目标仍未全部达到；按读取、排队、反序列化及放置阶段记录判断后续优化，不因局部 MOD 烘焙快而宣称整站就绪。 |
| L-05 | Spatial 未复用源 SHA | IFC Spatial 仍逐文件扫描 STEP，未从完整解析结果生成等价语义输入，也未跨阶段复用 SHA。 | substation04 真冷首屏约 9.3 s；`变电 IFC 空间索引` span 已与 finalize/写入分离。若 Spatial 重新成为主瓶颈，再立项。 |
| L-06 | 整站流畅度未达目标，矩阵仍不完整 | substation02 原生 30 秒真实路线单次 A/B：实例化关闭 p95/p99 为 76.4/97.3 ms、7191–7214 次绘制；开启为 48.6/69.5 ms、2622–2645 次绘制，但基础表示启动回退，因此默认关闭。 | 两种路径均未达到 33/50 ms 帧间隔目标；该试点对照不替代全部样本三次冷暖、固定路线及稳定内存矩阵，详见性能基线。 |
| L-07 | IFC 跨表示等价性只有局部证据 | 小 IFC 验收包（575,414 bytes）在同一 GlobalId/ExpressId 下 LOD0/1/2 包围盒中心误差约 4.21 微米；只覆盖该对象/输入。 | 不证明全站跨表示等价；逐对象验收不能由整体偏移或拟合 T 替代。 |
| L-08 | 在线底图依赖网络 | OSM 官方瓦片在当前网络 10 s 超时；CARTO 同源栅格 200/0.25 s 可达。CSP 已允许 `basemaps.cartocdn.com` 作为 OSM 缺失时的垫底。 | 两者都不可达时仍无在线底图；Canvas overlay 可用，底图可用性不作为打开线路工程前置条件。 |
| L-09 | Wire/Cable 中心线只是视觉辅助 | 管径使用源 `D`，另叠 1px 中心线保证所有 LOD 可见；中心线不参与拾取或尺寸测量。 | 电气连接判断以 Wire/Cable 是否存在、起止点与路径为准，不能用中心线/管径做工程测量。 |
| L-10 | substation04 备用出线源数据无连接线 | `110kV1Y备用出线线路间隔` 与 `110kV4Y备用出线线路间隔` 各只有 HGIS、3×CVT、3×避雷器 7 个 F4，DEV/MOD/Wire 中没有任何连接线；同一样本 `110kV分段间隔1` 有 86 个独立 `FlexibleCircuitConductor` Wire。 | 浏览器不凭空生成电气连接；若现场要求补齐，必须由源模型新增导线 DEV/IFC，或在产品层定义可审计的自动连线规则。 |

## 维护规则

- Open defect 关闭后删除条目，在对应修复提交中保留判定与验证依据；原生性能验收记录维护在 [性能](performance.md)；
- limitation 状态变化时原地更新证据/边界，不按日期追加流水；
- 不把“已接受限制”改写成“没有风险”；每条 limitation 必须写明当前边界和重新立项条件。
