# 工程实体运行时

桌面宿主使用 [GIM SDK](../../packages/gim-sdk/README.md) 构建物理目录、来源、实体与导航。Worker 负责读取和计算，宿主负责缓存、会话与发布，界面消费投影及属性查询。分类与成员规则见[实体与来源模型](../engineering/entities.md)。

## 构建与发布

| 阶段 | 输入与产物 |
|---|---|
| 物理目录 | 按源身份恢复缓存，或沿真实 CBM/DEV 引用构建 `SourceGeometryOccurrence`。目录就绪即供几何使用 |
| 来源收集 | 汇总 CBM、DEV、识别所需的 FAM 和 IFC 外露对象。保留引用、赋值与原始字段证据 |
| 实体归一化 | 将来源适配为对象证据，建立整体、成员与待归集合 |
| 三视图投影 | 分别建立清册、工程组成与来源视图，以及各自的搜索索引 |

冷开的核心来源发布由 `substationColdCore` 先完成 IFC 发现、CBM/FileDevRelation 和 core navigation；空间/STD-SLD 调度仍由 Runtime 持有。物理目录和语义来源复用路径索引及 CBM/DEV 文档。物理目录只使用实际装配和逐边矩阵，未匹配物理部件的 PARTINDEX 留在语义来源。暖开可直接从物理缓存交付目录。FAM 物化、工程分类和导航各自在后续阶段完成。

引入 IFC 时，装配消费内存中的空间和外露对象索引，几何与缓存写入各自推进。来源不完整时发布可浏览的部分结果并标注缺口。归一化失败时仍可查看有效来源，单个投影失败也只影响对应视图。切换或关闭工程后，宿主按会话、构建和修订拒绝迟到结果。

[工程 Worker](../../desktop/src/services/engineeringWorker.ts)执行来源抽取、归一化、投影和编码。[工程服务](../../desktop/src/services/engineeringService.ts)协调会话和发布。来源图修订相同时，后续模型结果引用已发布的图，修订变化时传递完整图。

## 导航与空间细化

清册按目录类别与名称模板列整体，工程组成按建筑、系统和区域组织，来源视图按 CBM/DEV 引用关系与逐文件 IFC 结构浏览。清册与工程树以实体为叶子，部件通过属性和来源查看。待归原因与来源 ID 随导出元数据保留，质量提示显示待归数量。分组操作以去重的整体集合为准。

已加载的 IFC 区域索引可提供源坐标范围，供[空间细化](../engineering/spatial-inference.md)更新建筑、区域或房间路径。细化从语义投影重新计算，产物保留推断状态。IFC 范围缺失时发布部分组成，来源和已识别实体可继续浏览。

## 属性与缓存

识别阶段只物化相关字段。属性元数据与已物化的分页查询由 `ModelEvidenceProvider` 提供，显式请求可物化更多详情或读取原文。详情页上限为 1,000 条或 512 KiB，游标绑定当前修订。读取、解析和物化状态分别报告，适配器按在用的路径和文档索引处理请求。

有效的压缩来源检查点允许释放空闲证据 Worker。元数据与未驻留范围仍可直接查询。显式物化可恢复来源及索引，显式读取原文可按路径读取。补齐影响识别的属性后按当前来源修订更新实体与投影。

来源、实体、导航与物理目录按[缓存域](caches.md)独立恢复和保存。纯词汇或归属规则变更重建实体与导航。来源字段投影变化影响相应来源契约。导航缓存记录完整组成及细化结果，部分投影可浏览。物理缓存和工程缓存有各自的写入状态，构建发布与持久化结算分别跟踪。

软件契约使用单元测试、Worker 检查和 SDK 消费者测试验证。逐工程归属与冷暖性能分别采用[本地验证](../validation.md)和[Benchmark](../performance/benchmark.md)。
