# 几何资产与表示索引

工程实体、几何编译和模型树是三个不同粒度。几何资产按来源 DEV 模板复用，工程实体只拥有业务身份和来源成员；两者通过表示索引关联，不生成“实体 GLB”。

## 流水线

```text
来源/装配索引
  ├─ 工程语义：EngineeringEntity（业务身份、成员、待归集合）
  └─ 几何编译：GeometryAsset（来源 DEV 模板、PHM/MOD/STL、placement）
             │
      EngineeringRepresentationIndex
             │
         模型树/选择/属性
```

- 模板身份使用规范化 DEV 路径；同一模板的多个 occurrence 只改变 placement，不复制几何。
- 表示索引由 `engineeringRepresentationService.ts` 构建：DEV 使用 `sourceId/rootOccurrence/assemblyPath/devPath`，IFC 使用 `sourceId/modelId/expressId`。
- 模型树不反向改变模板键；切换三视图、搜索和选择不能触发几何重编译。
- 单 occurrence 与多 occurrence 使用同一条 DEV 模板路径。
- 暖启动成本由**唯一 DEV 模板数 + placement 数**驱动，不按工程实体数计价；同一模板的多个实例只增加 placement，不增加模板读取/解析。
- IFC 按模型文件 LOD 与逐对象 `modelId/expressId` 绑定，不按工程实体编译；IFC 外露产品可以参与实体成员和选择，但不存在“一个实体一个 IFC 表示包”。

## 缓存层级

| 层级 | 编译 | 持久化 |
|---|---|---|
| L0 | 优先编译、优先显示全站最低成本表示 | 生成即持久化 |
| L1 | 进入有效视域后按需构建 | 选中/提升或淘汰后再次请求才选择性持久化 |
| L2 | 用户显式精化 | 默认不持久化，只保留会话内存 |

全站最终都要生成全部设备的 L0，只是先生成视野内的设备；视野外 L0 仍留在请求集合中后台补齐。L1 只在视野内按投影大小生成，L2 只在用户请求时计算。远景 L0 与中景 L1 都跳过小构件和小布尔开孔，L1 增加可见分段，L2 才精确 CSG。

很小的 DEV 由 Worker 队列合批调度，不拆模板键；大 DEV 优先按真实装配子树划分，对过重的子树继续拆分，没有更深装配边时按 MOD/STL 引用划分。计划分别估计唯一源文件读取量和重复引用的实例工作量，最多四个 Part、同时最多两个 Part Worker。合并仍产出单个 DEV 模板，最后按 occurrence placement 组装；重复来源模板共享缓存，不能按工程实体复制。

Worker 池一次只准入一个分治父任务，名额覆盖 Part、合并及整体回退。等待中的计划不生成 Part GLB；准入前先排空已经运行的普通编译，已导出未消费结果达到 64 MiB 时等待消费。准入使用 192 MiB 管理预留，先扣除其他模板尚未消费的结果，再按剩余额度的三分之一计算输入预算（最多 64 MiB），各 Part 平分该预算。这样不能让多个父任务分别持有 64 MiB 后同时预留合并内存。只有当前父任务的子任务可以绕过结果后压；其他编译等待，bounds 仍可推进。父任务完成、取消或最终失败时释放名额，合并失败的整体回退继续使用同一名额。

合并阶段按实际输入字节预留三倍工作量；内存压力高或 Part 超额时回退整体编译。诊断的 `bytes` 是已管理结果/合并工作量，`splitReservationBytes` 是当前父任务的准入预留，`admittedBytes` 是未消费结果与该预留之和；存在分治名额时不超过 `splitPoolBudgetBytes`（192 MiB）。普通编译的 64 MiB 结果后压和单结果 128 MiB 检查仍为后验门禁，不是所有在途分配的硬上限。

L0/L1 的“全小构件保留一个真实轮廓”由整个 DEV 决定。Part 仅返回省略候选；任一 Part 已有主体时不补轮廓，全部 Part 无几何时才从全局候选选择一个最大的真实来源重编。64 MiB 约束的是暂存结果与合并输入，不是 Worker 总工作内存；输出额度在序列化后检查，进程树峰值仍需以原生采样衡量。

## 当前限制

- 原生 L0 基础表示已完成 substation01–04 冷/暖采集，结果见[性能基线](../performance.md)；L1/L2 的固定选择和显式精化路线仍待复测。
- 实体与几何的表示关联已存在，但属性面板的完整“表示/模板”展示仍可继续完善。
