# 工程组成、来源与设备材料清册

三种树都是来源图与工程实体快照的投影，不反向决定实体身份、组成成员或几何 seed。

| 视图 | 用途 | 输入与节点 |
|---|---|---|
| 工程组成 | 按施工、运维的工程单元浏览 | 已识别整体 + 系统、建筑、楼层、宿主及空间归属证据 |
| 来源 | 忠实查看交付组织与原始字段 | CBM 引用层级、DEV 装配、逐个 IFC 文件及其空间/外露对象 |
| 设备材料清册 | 核对类别、整体粒度和组成来源 | 目录类别 → 工程整体 → 实际 DEV/IFC 组成来源 |

## 工程组成模板

```text
工程组成
├─ 建筑工程
│  ├─ 建筑物1
│  │  ├─ 层1（xxm）
│  │  │  └─ 梁、柱、板、墙等（目录类别 → 整体）
│  │  └─ 层2（xxm）
│  ├─ 建筑物2
│  ├─ 构筑物1（如主变系统构支架、独立基础）
│  │  ├─ 构架
│  │  ├─ 设备支架
│  │  └─ 基础
│  ├─ 构筑物2（如 xx 千伏配电装置户外构支架、独立基础）
│  ├─ 电缆沟
│  ├─ 站区性建筑（围墙、道路、大门）
│  ├─ 照明
│  ├─ 采暖、通风、空调
│  ├─ 给排水
│  └─ 消防
├─ 安装工程
│  ├─ 主变压器系统
│  │  └─ 1/2/3号主变 → 类别 → 主变整体
│  ├─ xx千伏配电装置
│  │  ├─ 进线间隔1、进线间隔2
│  │  ├─ 出线间隔1
│  │  ├─ 母线设备间隔
│  │  ├─ 母联间隔
│  │  ├─ 分段间隔
│  │  └─ 其他间隔
│  ├─ xx千伏配电装置
│  ├─ 无功补偿系统
│  ├─ 站用电系统
│  ├─ 二次及直流系统
│  ├─ 电缆
│  └─ 接地系统
└─ 未分类
   ├─ DEV轨道 / IFC轨道 / DEV+IFC轨道
   │  └─ 设备 / 装置性材料 / 构件 / 其他 → 整体
   └─ 其他 → 整体归属待确认 → 待归集合（来源数）
```

模板按有证据的分组实例化，不生成全部示例间隔或虚构建筑。来源声明了单元但没有可靠成员时显示“归属待确认”。分组计数按唯一实体去重，多路径不重复生成实体或几何。

## 分配规则

- 安装系统与间隔使用显式系统/单元声明，接受 `36S` 等无“间隔”后缀的名称；不固定 F2/F3/F4 或 SYSTEMNAME 序号。额定电压不直接当作运行系统电压。
- 主变本体、嵌入本体的端子箱、对应中性点成套装置属于一个主变整体；测控/保护屏柜保持独立二次整体。来源中的“备用/预留”保留在整体名称与属性中，同一编号的工程单元使用统一的“n号主变”路径。
- 建筑优先用有效的 IFC 建筑、楼层名称及标高；占位 IfcBuilding 不阻断楼层中的建筑名。明确的建筑文件名称也可提供用途线索，文件路径始终保留为来源属性。
- 多建筑混在同一文件时，用实际 IFC 几何在**源 Z-up 米制坐标**下的建筑构件范围补充投影。有效建筑名优先；明确的配电系统区域可辅助推断配电装置楼，多个高压系统冲突时不任选。10kV 柜数量多不会覆盖同一建筑内已声明的高压 GIS 系统用途。
- 几何推断只改变组成路径，不合并实体、不建立电气连接、不依赖当前显示/隔离状态。证据包含 `spatial-building-footprint`；重叠、冲突或不足时保留待确认。
- 楼层用交付名称/标高，不根据构件高度制造正式层号。缺少可靠楼层时显示“楼层待确认”。
- 电缆沟、站区性建筑及照明/暖通/给排水/消防分别归类。支架、基础等优先归对应系统的构筑物；没有可靠系统/宿主关系时保留未分类。M07 只有明确电缆/桥架用途时归电缆，不再整体兜底。

## 来源树

```text
GIM来源
├─ DEV轨道
│  └─ F1 → F2 → F3 → F4 / PARTINDEX
│     └─ 实际 DEV 装配记录（真实 SUBDEVICE/PHM 引用）
└─ IFC轨道
   └─ 每个 IFC 文件
      └─ 该文件的空间容器 / 外露对象
```

CBM 节点显示级别和业务名称，IFC 文件显示可读名称；真实文件名/路径作为 `documentPath` 和属性保留。来源树不按业务归属重新排序引用关系。IFC 类型、门窗内部参数、材质、表示等内部定义不作为外露产品独立列项，仍可从所属产品属性追溯。

## 设备材料清册模板

```text
设备材料清册
├─ 设备
│  └─ 类别X
│     └─ 设备整体
│        ├─ 装置/组成来源A [DEV轨道]
│        │  └─ 内部组成来源 [DEV轨道]
│        └─ 组成来源B [IFC轨道]
├─ 装置性材料 → 类别 → 整体 → 组成来源
├─ 构件 → 类别 → 整体 → 组成来源
├─ 待识别（有来源边界，类别未确认）
└─ 待归整体（整体边界未确认）
```

独立设备不被嵌入上级整体的组成来源列表；每份来源最多一个主归属。清册计数不把内部件算成独立设备。内部件可搜索到所属整体，也能进入来源页查看原始字段。三页各自保留搜索、展开和滚动状态，共用虚拟树、选择与属性路由。

## JSON 导出与复制

三页均提供“导出 JSON”和“复制 JSON”，操作完整逻辑树，不依赖 DOM 已展开行。

- 桌面版使用后端原生保存对话框，保存成功返回路径；取消、写入失败分别反馈。
- 浏览器使用挂入 DOM 的下载链接，延迟释放 Blob URL，避免 WebView/浏览器提前释放导致下载中断。
- 复制调用剪贴板 API，成功或权限失败都有明确反馈。
- 导出 schema 为 `gim-engineering-tree-v1`，`mode` 为 `composition/source/inventory`。保留实体/来源 ID、文件路径、类别、来源数及投影证据。
- 来源/实体/导航缓存分域失效，几何不因分类规则变化重编。运行时几何细化只用于会话投影，不冒充纯语义缓存。

实体契约见[实体与来源模型](entities.md)，运行过程见[工程实体运行时](../architecture/engineering-runtime.md)，缓存版本见[缓存域](../architecture/caches.md)。
