# 工程组成、来源与设备材料清册

三种树都是来源图与工程实体快照的投影，不反向决定实体身份、组成成员或几何 seed。

| 视图 | 用途 | 输入与节点 |
|---|---|---|
| 设备材料清册 | 核对类别、整体粒度和组成来源 | 目录类别 → 子类 → 名称模板 → 工程整体 → 实际 DEV/IFC 组成来源 |
| 工程组成 | 按施工、运维的工程单元浏览 | 已识别整体 + 系统/区域、建筑、楼层、宿主及空间归属证据 |
| 来源 | 忠实查看交付组织与原始字段 | CBM 引用层级、DEV 装配、逐个 IFC 文件及其空间/外露对象 |

│  │  └─ 层2（xxm）
│  ├─ 建筑物2
│  ├─ 主变区域
│  │  ├─ 构架
│  │  ├─ 支架
│  │  └─ 基础
│  ├─ xx千伏配电装置区域
│  │  ├─ 构架
│  │  ├─ 支架
│  │  └─ 基础
│  ├─ 电缆沟
│  ├─ 站区性建筑（围墙、道路、大门）
│  ├─ 照明
│  ├─ 采暖、通风、空调
│  ├─ 给排水

│  │  ├─ 进线间隔1、进线间隔2
│  │  ├─ 出线间隔1
│  │  ├─ 母线设备间隔

模板按有证据的分组实例化，不生成全部示例间隔或虚构建筑。来源声明了单元但没有可靠成员时，最终工程组成隐藏空组，声明继续保存在来源视图；占位 IfcBuilding 名称可回退到交付文件名，房间/机电交付在存在项目楼栋时作为楼栋下级房间，不生成平级楼栋。分组计数按唯一实体去重，多路径不重复生成实体或几何。

## 分配规则

- 安装系统与间隔使用显式系统/单元声明，接受 `36S` 等无“间隔”后缀的名称；不固定 F2/F3/F4 或 SYSTEMNAME 序号。额定电压不直接当作运行系统电压。
- 主变本体、嵌入本体的端子箱、对应中性点成套装置属于一个主变整体；测控/保护屏柜保持独立二次整体。来源中的“备用/预留”保留在整体名称与属性中，同一编号的工程单元使用统一的“n号主变”路径。
- 建筑优先用有效的 IFC 建筑、楼层名称及标高；占位 IfcBuilding 不阻断楼层中的建筑名。明确的建筑文件名称也可提供用途线索，文件路径始终保留为来源属性。`总平面`/`Default Building` 等占位名不会覆盖可识别的交付建筑名。
- 多建筑混在同一文件时，用实际 IFC 几何在**源 Z-up 米制坐标**下的建筑构件范围补充投影。建筑轮廓、命名投票、房间/区域和防火墙的阈值与失败条件见[空间推断](spatial-inference.md)。
- 几何推断只改变组成路径，不合并实体、不建立电气连接、不依赖当前显示/隔离状态。保留推断状态，不保存投影依据列表；重叠、冲突或不足时保留待确认。
- 空间细化由 `services/projections/` 的投影插件执行，策略版本为 `composition-spatial-v4`；纯领域不接收场景 bounds。保留自动细化，树与属性中的推断归属标注“空间推断”，JSON 同时保留 `inferred` 和证据。完整空间投影连同推断证据写入导航缓存，缓存契约绑定空间策略版本；来源、实体和几何缓存不写入推断。
- 文件路径与位置坐标保留在来源投影证据中；来源适配先抽取带证据地址的建筑名称，再交给纯领域模板，模板本身不读取文件路径或坐标。明确的主变/电压区域交付名称同样由适配层提供，不用于改变对象类别。
- 每轮空间细化从语义投影重新计算，不累加上一轮路径或搜索文本。全部 IFC 尚未完成时模型树显示加载中；有 IFC 被跳过或加载失败时发布可浏览的部分视图并标明范围缺失，空间推断失败时回退语义视图。保留有效展开和选择，失效分组撤销隔离及高亮并提示重新选择，旧工程/旧快照/旧轮次结果不得提交。
- 楼层用交付名称/标高，不根据构件高度制造正式层号。缺少可靠楼层时显示“楼层待确认”。
- 电缆沟、站区性建筑及照明/暖通/给排水/消防分别归类。支架、基础等优先归对应系统的“xx区域”，主变系统的区域标题为“主变区域”；户外区域下再分构架（C-B7/构架）、支架（C-B1/支架）、基础与有证据的防火墙；户内土建归入实际建筑。没有直接系统/宿主关系时，可消费明确的区域交付名，或在空间投影中使用同坐标系的设备范围/位置作有界推断；相邻系统竞争时保留未分类。M08 槽盒/桥架归电缆设施，M07 套管不整体兜底为电缆。

### 来源声明边界

- 有序系统名称中的单元可使用 `36S`、`24S` 等编号，不要求带“间隔”；编号只用于视图归属，不用于合并设备身份。
- `主变进线间隔` 属于相应电压配电装置，不能只因名称含“主变”改归主变系统；主变系统下的中性点间隔仍归主变系统。
- `≥110kV且<220kV系统` 只表示电压范围，下一项明确声明的 `110kV…间隔` 才决定 110 千伏配电装置归属；范围名不按下限/上限猜运行电压。
- 设备型号中的额定电压不单独生成配电装置；`Default Building`、“无”等导出占位值不生成建筑物或楼层。
- 来源已声明但尚无构件关联的建筑/间隔仍可显示声明，标明整体归属待确认并可追溯原文；模板不制造台套数量。

## 来源树

```text
GIM来源
├─ DEV轨道
│  └─ F1 → F2 → F3 → F4 / PARTINDEX
│     └─ 实际 DEV 装配记录（真实 SUBDEVICE/PHM 引用）
└─ IFC轨道
   └─ 每个 IFC 文件
      └─ 该文件的空间容器 / 外露对象
```

CBM 节点显示级别和业务名称，IFC 文件显示可读名称；真实文件名/路径作为 `documentPath` 和属性保留。来源树不按业务归属重新排序引用关系。IFC 类型、门窗内部参数、材质、表示等内部定义不作为外露产品独立列项，仍可从所属产品属性追溯。

## 设备材料清册模板

清册采用独立的分类、子类与名称模板层级，保留工程实体及其实际组成来源。层级、计数、搜索、版本和与其他业务树的解耦契约见[设备材料清册模型树模板](inventory-template.md)。清册不消费工程组成路径，空间细化也不改写清册。

## JSON 导出与复制

三页均提供“导出 JSON”和“复制 JSON”，操作完整逻辑树，不依赖 DOM 已展开行。

- 桌面版使用后端原生保存对话框，保存成功返回路径；取消、写入失败分别反馈。
- 浏览器使用挂入 DOM 的下载链接，延迟释放 Blob URL，避免 WebView/浏览器提前释放导致下载中断。
- 复制调用剪贴板 API，成功或权限失败都有明确反馈。
- 导出 schema 为 `gim-engineering-tree-v1`，`mode` 为 `composition/source/inventory`。保留实体/来源 ID、文件路径、类别、来源数及投影证据。
- 来源/实体/导航缓存分域失效，几何不因分类规则变化重编。仅完整空间投影可写工程导航缓存；部分 IFC 范围缺失时保留来源/实体缓存与可浏览的部分树。

实体契约见[实体与来源模型](entities.md)，运行过程见[工程实体运行时](../architecture/engineering-runtime.md)，缓存版本见[缓存域](../architecture/caches.md)。

代理 IFC 对象的显式类别属性在来源阶段有选择地提取，原始名称和属性出处独立保留；其他详细属性继续按需加载。分类后的构件可参与建筑轮廓推断。匿名轮廓包含至少两个主变系统设备且没有屋面/大面积高位楼板覆盖时，可作为主变室外区域；此结果只影响组成投影。唯一配电室声明可由轮廓内的唯一配电系统投票关联，仍标为推断。房间存在多个候选楼栋时不按排序选第一栋。

混合主变基础/防火墙文件不把所有对象都判作防火墙。户外 `C-A1` 墙体只有在同一文件、同一平面足迹上形成连续的多层墙片，且累计高度足够时才投影到“主变区域 → 防火墙”。完整条件、阈值和证据见[空间推断](spatial-inference.md)。
