# 工程组成与两视图

本文件描述“工程组成 / 来源”两个投影如何组织已识别的整体和原始来源。实体契约见[实体与来源模型](entities.md)，运行时见[工程实体运行时](../architecture/engineering-runtime.md)。

## 1. 两视图边界

| 视图 | 输入 | 节点含义 |
|---|---|---|
| 工程组成 | 工程整体快照 + 声明的系统/建筑/宿主证据 | 工程分组、整体、待归集合 |
| 来源 | 来源图 + IFC 外露/空间容器 | CBM 引用、DEV 装配、IFC 文件、空间节点、原始记录 |

两页共用搜索、选择、属性路由和虚拟列表，但节点 ID 分离：

- 组成节点引用 `entityId`/`pendingId`，不生成新实体。
- 来源节点引用 `sourceId`/文档/空间 key，不把来源提升为整体。
- 一个整体可在多个组成路径出现（如多系统声明），`rowsByEntity` 保留多行；分组计数按实体去重。

## 2. 组成模板

一级固定为“建筑工程”“安装工程”。

```text
工程组成
├─ 建筑工程
│   ├─ 建筑物
│   │   └─ 楼层
│   ├─ 电缆沟
│   ├─ 站区性建筑
│   ├─ 照明 / 采暖通风空调 / 给排水 / 消防
│   ├─ [系统]构支架、独立基础
│   └─ 建筑物/构筑物归属待确认
└─ 安装工程
    ├─ 主变压器系统
    ├─ <电压>千伏配电装置
    │   └─ 间隔/单元
    ├─ 无功补偿系统
    ├─ 站用电系统
    ├─ 二次及直流系统
    ├─ 电缆
    └─ 接地系统
```

末端按目录类别分组，再列整体；不增加“设备/材料/构件”大层级。

### 安装系统顺序

| 系统 | 顺序 | 典型类别/证据 |
|---|---:|---|
| 主变压器系统 | 10 | E01、主变编号/名称 |
| 配电装置 | 20，按电压从高到低 | 显式 `<n>kV` 系统/间隔 |
| 无功补偿 | 30 | E02/E10/E11/E12 |
| 站用电 | 40 | E03、站用/所用电声明 |
| 二次及直流 | 50 | E16（端子箱除外）、保护/控制/直流声明 |
| 电缆 | 60 | M05/M07、电缆系统声明 |
| 接地 | 70 | M06、接地系统声明 |

电压只接受明确等级（0.4/6/10/20/35/66/110/220/330/500/750/1000 kV）；范围/不等式不当作单一运行电压。没有明确系统声明时，E/M 进入“系统归属待确认”，不按类别默认强塞。

### 建筑与设施

- 建筑优先来自 IFC 空间容器：`building` + 楼层链；过滤 `Building/Storey/Project/Site/Default`、图纸名和无效占位。
- 没有空间容器时，才从声明的 `NAME/PARTNAME` 中识别含“楼/栋/房/室/车间”的建筑名；不从类别或几何包围盒造建筑。
- 电缆沟 → `建筑工程/电缆沟`；围墙、道路、大门 → `站区性建筑`。
- 照明、暖通、给排水、消防按用途进入建筑工程设施分组；独立设备（E19 风机/泵等）仍按设备整体。
- 支架/基础/构架优先挂到其宿主设备所在系统的“构支架、独立基础”；无宿主时进入构筑物待确认。
- 其他 C-A 构件没有建筑/楼层证据时进入“建筑物归属待确认”。

## 3. 分配证据

`assignEngineeringComposition` 读取：

1. **声明的系统名**：CBM 的 `SYSTEMNAME<n>`（按序号）或 `NAME/PARTNAME` 中的系统/间隔/建筑关键词；从一般到具体，同一路径的重复声明不重复建组。
2. **间隔/单元**：紧跟系统声明后的名称可成为单元，例如 `36S`、`110kV1Y备用出线线路间隔`；不要求名称包含“间隔”。
3. **建筑/楼层**：IFC 空间包含链；只取真实性建筑节点。
4. **宿主关系**：真实 DEV/IFC 组合或独立对象关系；一个实体有多个宿主时不任选。
5. **目录角色**：固定类别到系统的映射（E01→主变、E02/E10/E11/E12→无功、E03→站用电、E16.protection→二次、M05/M07→电缆、M06→接地、C-D1→照明、C-D2→消防、C-C2→给排水）。
6. **对象自身用途**：设备名称中的系统/设施用途，仅在目录无固定映射时使用。

优先级：显式声明 + 目录固定角色 > 自身用途 > 单一宿主 > 待确认。多个声明上下文可生成多条路径；不把多个上下文合成一个平均位置。

## 4. 分组与计数

- 分组节点键由父键 + 类型 + 编码生成，避免同名不同层合并。
- `entityCount` 是组内唯一实体数；一个实体多路径时在各组各计一次，但同一组内去重。
- 待归集合单独显示“整体归属待确认”，标题含来源数；不显示为设备。
- 已有整体但没有任何组成路径时，归入“工程归属待确认”分组；它与“整体归属待确认”不同：前者整体身份已建立，只是业务位置未证。
- 声明了工程单元但没有可靠成员时，保留空组并标记“· 归属待确认”；组可查看来源声明，但不提供隔离。
- 多路径整体不重复生成几何或选择范围；选择取成员并集。

## 5. 来源视图

```text
GIM 来源
├─ CBM 引用与 DEV 装配
│   └─ CBM 节点 / DEV 记录（真实装配路径）
└─ IFC 交付文件
    ├─ IFC 文件
    └─ 空间容器（项目/场地/建筑/楼层/空间）
        └─ 外露对象记录
```

- CBM 行标题取 `SYSTEMNAME` 或 `NAME/PARTNAME`；文档路径保留。
- DEV 记录按真实 `SUBDEVICE`/PHM 路径组织；同一模板多引用分别出现。
- IFC 记录优先挂到空间容器；没有容器时挂到 IFC 文件；非物理特征保留为来源。
- 来源记录可显示原始字段、文件、身份；有唯一 owner 时提供“查看所属整体”。
- 未解析/歧义引用保留，不跳过；来源不完整时质量提示给出原因。

## 6. 搜索与虚拟列表

- 组成搜索覆盖整体名称、类别、系统/间隔上下文、来源名称/编码；命中后展开祖先并显露整体。
- 来源搜索覆盖节点标题、类型、文档路径；命中后展开对应分支。
- 内部件名称可以命中所属整体；来源树仍保留该内部件。
- 两页共用固定行高虚拟轮廓，只渲染可见/预取行；展开状态按各自稳定键保存，切换页保留搜索/滚动。
- 方向键/Home/End 在完整逻辑行集合移动；状态刷新不重建投影或抢焦点。

## 7. 版本与限制

- 组成/导航缓存绑定来源摘要和实体指纹；当前版本与失效范围见[缓存域](../architecture/caches.md)。
- 分组依据来自声明和真实关系；没有声明/宿主时保留待确认，不按设备名称猜系统。
- 两视图是同一实体的不同投影；来源视图不能反向决定工程类别或几何粒度。
- 当前不证明所有样本的建筑楼层关联、逐台套人工归属或原生交互完整；见[问题与限制](../open-issues.md)。
