# 空间推断

空间推断是**工程组成投影插件**，只补充建筑、房间和区域归属。它不改变工程整体身份、来源成员、目录类别或几何模板，不建立电气连接，也不读取当前显示/隔离状态。算法实现见 [`compositionSpatial.ts`](../../desktop/src/services/projections/compositionSpatial.ts)，策略版本为 `composition-spatial-v4`。

建筑名称和空间容器本身如何解析见[建筑推断](building-inference.md)；工程组成模板见[工程组成与三视图](composition.md)。

## 1. 输入与坐标

| 输入 | 来源 | 用途 |
|---|---|---|
| `CompositionBounds` | IFC 实际几何、DEV 范围 | 每个实体的 6 元包围盒，源 Z-up 米制坐标 |
| `SourceCompositionEvidence` | 来源适配 | 空间容器、交付建筑/区域名、位置、宿主 |
| 工程快照 | 实体归一化 | 实体类别、成员和语义组成路径 |
| 声明 | 来源声明的建筑/房间 | 只作命名候选，不直接建立成员 |

IFC 的 web-ifc/RegionalIndex 范围是绝对 Y-up 米制；进入投影前统一通过 `fromIfcYUpBounds()` 转为源 Z-up：

```text
[minX, -maxZ, minY, maxX, -minZ, maxY]
```

同一实体的多个范围先取并集。非有限值、下界大于上界、任一边长 ≥500 m 的范围丢弃。

推断只消费**源坐标的实体范围**，不消费场景可见性、Mesh 身份或 F 层级。

## 2. 阈值

`SPATIAL_PROJECTION_POLICY` 集中定义，版本变化必须同时失效导航缓存：

| 常量 | 值 | 用途 |
|---|---:|---|
| `maxExtent` | 500 m | 拒绝异常范围 |
| `gridSize` | 8 m | 建筑种子空间哈希 |
| `joinMargin` | 0.6 m | 建筑种子/包含判定外扩 |
| `voteMargin` | 0.5 m | 命名投票包含判定 |
| `containmentMargin` | 1 m | 建筑完整包含判定 |
| `minMembers` | 3 | 建筑轮廓最少构件 |
| `minArea` | 12 m² | 建筑轮廓最小面积 |
| `minWidth` | 2 m | 建筑轮廓最小短边 |
| `minTop` | 2 m | 建筑种子/屋面最小高度 |
| `minVotes` | 2 | 命名投票最少实体数 |
| `highVoltageKv` | 66 kV | 高压系统优先阈值 |
| `areaDistance` | 12 m | 设备/基础到区域锚点最大距离 |
| `areaSeparation` | 2 m | 两个区域候选的最小差距 |

## 3. 建筑轮廓

1. **种子**：类别为 `C-A1`–`C-A6`，有有效范围，来源提示命中 `建筑|配电.*楼|辅助用房|主控.*楼|警卫|门卫`，且顶面高度 `> minTop`。
2. **合并**：按 8 m 网格做空间哈希，种子包围盒在 XY 上相距不超过 `joinMargin` 时并查集合并。只比较同格及相邻格，避免大结构文件的全对全扫描。
3. **过滤**：合并后的轮廓必须同时满足成员数 ≥3、水平面积 ≥12 m²、短边 ≥2 m。
4. **命名**：
   - 轮廓内的 `C-A*` 构件若有唯一 `buildingPaths()` 建筑名，采用该名称；
   - 没有建筑名时，对中心落在轮廓内（外扩 `voteMargin`）的实体做配电系统投票，只统计唯一 `distribution:` 系统；
   - 高压（≥66 kV）与低压混合时，只有唯一高压系统且票数 ≥2 才采用；否则只有唯一系统且票数 ≥2 才采用；
   - 若声明中恰有一个 `配电室N`，优先使用声明建筑名；否则回退为 `<系统标题>楼`；
   - 同名声明建筑出现多次时，退回系统回退名，避免把多个轮廓并成同一栋；
   - 仍无名称时命名为 `建筑物N（用途待确认）`，不编造用途。
5. **多名称**：轮廓内出现多个建筑名时标记 `ambiguous`，不自动选择第一栋，也不把构件归入该轮廓。

匿名轮廓若同时满足“至少两个不同主变系统设备锚点”和“没有屋面/大面积高位楼板覆盖”，作为**主变室外区域**，不生成建筑。屋面判据为存在 `C-A6`，或 `C-A2` 面积 ≥轮廓面积 20% 且顶面 `> minTop`。

## 4. 构件与房间归属

### 4.1 建筑构件

对 `C-A*`/`C-B*` 构件，若中心点落在唯一非歧义轮廓内，且水平范围完整落在轮廓外扩 `containmentMargin` 内：

- 已有语义建筑路径的构件保持语义路径，不被空间覆盖；
- 否则归入该建筑；有唯一楼层时写该层，否则写 `楼层待确认`；
- 投影只保存路径及推断状态；不生成、展示或持久化命名/范围拼接的投影依据列表；
- 轮廓属于主变室外区域时，改为归入该区域，证据写 `spatial-equipment-area`。

### 4.2 房间/机电交付

仅暴露房间名的房间/机电文件，若没有“非房间建筑”的语义路径，且其范围完整落在唯一非室外、非歧义轮廓内，归入该建筑，并把房间作为楼层节点。证据写 `spatial-room-footprint`；该路径由空间证据驱动，但当前不额外标 `inferred`。

### 4.3 户外设备区域

未归类的 `C-B*`、`C-A1/C-A3/C-A4/C-A5`，按水平距离寻找主变/配电装置系统锚点：

- 锚点来自“恰好一个主变或配电装置系统”的 `E*` 实体，位置取范围中心或来源位置；
- 最近锚点距离 ≤`areaDistance`；
- 若最近的 second 候选与第一候选差距 <`areaSeparation`，保留未分类；
- 归入 `<系统>区域`，并按类别/名称分为构架、支架、基础或防火墙；
- 证据写 `spatial-equipment-area`。

### 4.4 防火墙墙片

混合“主变基础/防火墙”交付文件中的墙片，只有同时满足以下条件才合成防火墙：

- 类别 `C-A1`；
- 短边 ≤0.35 m、长边 ≥6 m、高度 ≥0.5 m；
- 来源文件命中 `主变.*基础.*防火墙`；
- 同一文件、同一 XY 足迹（按 0.25 m 取整）至少 3 片；
- 墙片在高度上连续（相邻间隙 ≤0.08 m），累计高度 ≥4 m。

满足后，该组只替换已经位于“主变区域”的墙片路径；不把整份文件的所有构件都判成防火墙。

## 5. 结果与失败

- 建筑轮廓/设备区域路径带 `inferred=true`，证据包含策略版本；房间归属写 `spatial-room-footprint`，当前不额外标 `inferred`。树和属性面板对带推断证据的路径标注“空间推断”。
- 任何不满足唯一性/包含性的对象保持原语义路径或未分类，不按“第一个候选”、排序或邻近强行归属。
- 空间投影失败时回退语义组成；部分 IFC 范围缺失时不写完整导航缓存。
- 诊断输出 `footprints`（范围、成员数、候选名、投票、最终名）和 `firewallStacks`（范围、成员、证据）。
- 导航缓存契约绑定 `SPATIAL_PROJECTION_POLICY.version`；策略变化只重建导航，不重编几何。

## 6. 验证

- `desktop/src/services/__tests__/compositionSpatial.test.ts`：Y-up→Z-up 转换、建筑轮廓、主变室外区域、房间/区域、防火墙、未分类保持、快照不变；
- `compositionProjection.test.ts`：静态/运行时投影一致性；
- `engineeringService.test.ts`：投影插件接入工程组成；
- 本地工程回归入口：`npm run test:local -- --build <原生构建清单>`，样本由开发者在私有注册表中登记。

当前不证明：建筑轮廓的完整 Site→Building→Storey→Space 语义图谱、同 GUID 多文件 footprint 拆分/合并、真实桌面空间推断性能；这些仍是[问题与限制](../open-issues.md)中的未关闭项。
