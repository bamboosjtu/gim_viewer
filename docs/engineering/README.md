## 基本原则

1. **先工程整体，后文件和几何。** 分类不使用 F2/F3/F4、展示树深度、数组顺序、Mesh 或包围盒；来源图只提供真实引用和装配边。
2. **目录是项目映射。** E/M/C 编码用于本项目归一化和浏览，不是国网标准编码；目录出处（2018/2025/研究）与最终类别分开保留。
3. **对象角色先于类别。** 先判断 `source_only/container/detail/part/fragment/neutral_set/object`，再用对象自身名称、类型、材料类型和独立功能判类别；上级名称不能覆盖当前组件身份。
4. **主归属唯一。** 每份来源只能归入一个整体、一个待归集合或仅来源；别名、候选和辅助证据另存，不重复计数。
5. **未知与歧义保留。** `U-OBJECT`、待归集合、`ambiguous`、来源不完整分别表达；不为了树整齐强行合并或补造实体。
6. **实体与表示解耦。** 整体 ID 不嵌入 CbmNode、Mesh、Fragments 或运行时模型；表示通过来源 ID 绑定，规则变化不重编几何。
7. **模型导航是投影。** 清册/工程/来源都是工程实体识别结果按不同业务规则生成的投影，不是原始 CBM/DEV/IFC 文件树；切换的是投影，不改变实体身份。

## 当前状态

- 桌面变电默认三视图：设备材料清册、工程组成、来源；独立设备仍使用装配来源树，线路使用线路树/地图。
- 来源、实体、导航缓存分别版本化；当前契约与失效范围只在[缓存域](../architecture/caches.md)维护。
- 九工程来源/实体/三视图投影已有自动与浏览器证据；原生完整操作、三次冷暖性能、逐台套人工真值仍未关闭，见[问题与限制](../open-issues.md) O-11、L-12。
- 本目录只描述当前规则，不把研究候选当成产品能力；新增类别先改目录和领域测试，再接 UI。
