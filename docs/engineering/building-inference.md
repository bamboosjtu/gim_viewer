# 建筑推断

工程组成中的建筑/楼层/房间来自 IFC 空间结构和交付证据，不由 F 层级、文件顺序或视图节点反推。当前实现只使用来源声明的空间关系、项目建筑名和明确的交付名称。

## 输入与优先级

1. IFC `Site → Building → Storey → Space` 的父级关系；
2. 非占位的 `IfcBuilding` 全局名；
3. 项目级 `availableBuildings`；
4. 交付目录/文件名，仅在名称缺失时作为 label。

`总平面`、`Default Building`、`IFC*`、`建筑/站区`、空名等占位值不作为建筑名。无法确定时保留 `unbound`/推断状态，不创建伪建筑。

## 规则

- `警传室`、`警卫室`、`门卫室`、`消防泵房` 是独立小型建筑，不按 `室` 自动当作房间。
- `配电室` 等房间/间隔默认挂在项目建筑下；只有来源明确说明它是独立建筑时才平级。
- 房间和各层不升格为建筑；建筑、楼层、房间层级固定为 `建筑 → 楼层 → 房间`。
- 同一 GUID 在多个 IFC 文件/足迹出现时不以文件名强行合并；无法证明同一建筑时保留冲突/推断状态。
- 零成员声明组标为 `unbound`，可查看声明和来源，但不进入 3D 空间选择。

## 当前限制

- 同 GUID 多文件的完整 footprint 拆分/合并仍未关闭。
- 完整的 `Site → Building → Storey → Space` 边界面仍需用更多真实样本验证。
- 建筑组选择只覆盖已绑定成员；未绑定成员保留提示。
