# 建筑推断

工程组成中的建筑/楼层/房间来自 IFC 空间结构、交付名称和项目声明，不由 F 层级、文件顺序或视图节点反推。当前实现只使用来源可追溯的空间关系和名称证据；算法入口见 [`compositionTemplate.ts`](../../desktop/src/engineering/compositionTemplate.ts)，几何轮廓补充见[空间推断](spatial-inference.md)。

## 1. 输入与优先级

`buildingPaths()` 按以下顺序选择一个建筑路径：

1. **房间 + 项目楼栋**：房间/机电交付名（`配电室` 等）存在，且项目级 `availableBuildings` 去重后恰有一个候选（有 `楼` 后缀时优先取楼栋）时，把房间作为该楼栋的楼层节点；
2. **有效 IFC 空间建筑**：`IfcBuilding → IfcBuildingStorey`，建筑名必须通过占位/总平面过滤，且不能是配电装置、开关场、构支架或电缆沟；
3. **楼层名回退**：IfcBuilding 名称是占位值，但楼层有可规范化名称时，用楼层名建立建筑；
4. **唯一交付建筑名**：仅当一个建筑文件名是唯一候选时，文件名作为 label；
5. **来源声明**：声明名同时满足有效建筑名、包含 `楼|栋|房|室|车间`、不含 `系统|区域` 时，建立声明建筑组；
6. 以上都不可用时不建立建筑路径，保留未分类或待确认。

房间路径优先于同名 IfcBuilding，是为了避免把 `配电室` 房间文件提升为与 `配电楼` 平级的楼栋；没有唯一项目楼栋时，房间名仍可来自空间/声明证据，但不伪造独立小建筑。

“占位 IfcBuilding 不阻断可识别楼层名/交付建筑名”是当前行为；占位名本身不会成为建筑。

## 2. 名称规范化

`canonicalBuildingName()` 只识别以下可读名称：

- `<n>kV配电装置楼` → `<n>千伏配电装置楼`；
- `警卫室`、`门卫室`、`警传室`、`消防泵房`；
- `主控楼`、`主控通信楼`、可带编号；
- `辅助用房`；
- `配电楼`、`配电装置楼`、`配电室`（可带编号）；
- `综合楼`、`生产楼`、`生产综合楼`、`控制楼`。

`配电室` 是房间类名称：`isRoomBuildingName()` 以 `室` 结尾且不是独立小建筑；`警卫室`、`门卫室`、`警传室`、`消防泵房` 是独立小建筑，不按“室”降为房间。

占位过滤拒绝 `无`、`未命名`、`默认`、`IFC*`、`Default Building`、`建筑`、`站区`、`总平面`、`总轴网`、`平面图`、`建筑s`、`新建模`、`模型n` 等。过滤是必要的，但过滤后只能继续使用后续名称/空间证据，不能凭正则猜楼栋。

## 3. 房间与楼层

- 有项目楼栋候选时，层级固定为 `建筑 → 楼层 → 房间`；房间不升格为建筑，房间/机电文件不与楼栋平级。只有房间名、没有楼栋证据时保留来源房间组，不伪造独立小建筑。
- 房间名只有在存在唯一项目楼栋候选时才挂到该楼栋；候选不唯一时保留待确认，不按排序选第一栋。
- 楼层使用 IFC 交付的楼层名和标高；缺少可靠楼层时写“楼层待确认”，不按构件高度制造层号。
- 最终工程组成隐藏零成员声明组；来源视图仍保留声明原文，3D 空间选择不把声明组伪造成可选整体。

## 4. 状态与选择

- 建筑轮廓/区域推断产生的路径带 `inferred=true` 和 `spatial-building-footprint` 等证据；房间归属写 `spatial-room-footprint`，不额外改实体身份。名称/声明路径保持语义来源，不标空间推断。
- 只有声明、没有成员关联的建筑组带 `unbound=true`，预览显示“归属待确认”；点击不进入 3D 高亮，不伪造整体范围。
- 同一建筑的多条路径按唯一实体去重；建筑组选择覆盖已绑定成员，未绑定来源保留提示。

## 5. 样本表现

| 样本 | 当前行为 | 边界 |
|---|---|---|
| substation02 | `总平面` 类 IfcBuilding 名被过滤；唯一交付楼名可回退；没有逐对象 `IFCGUID` 时 `spaces` 为空 | 建筑可见性依赖名称/交付证据，不能宣称 IFC 空间图完整 |
| substation03 | `Default Building`、楼层 `无` 被过滤；只剩来源声明时形成 `unbound` 组 | 声明不等于成员，点击不伪造 3D 范围 |
| substation04 | 建筑名为空，多文件可能共享同一 GUID；房间/机电文件按唯一项目楼栋嵌套 | 同 GUID footprint 拆分/合并仍未完成 |

这些是当前规则下的行为边界，不是九工程建筑识别已全部通过的证明。

## 6. 边界与限制

- 当前不建立完整 `Site → Building → Storey → Space` 图，也不按 `IfcRelContainedInSpatialStructure` 独立重建所有建筑；建筑主要通过构件已获得的 IFC 空间证据进入组成。
- 同一 GUID 在多个 IFC 文件/足迹出现时，不按文件名强行合并；尚未完成按 footprint 拆分/合并。
- 没有逐对象 `IFCGUID` 时，`spaces` 可能为空；这时只能使用楼层名、交付文件名或声明，不能宣称建筑已识别。
- 几何轮廓兜底只处理“没有语义建筑路径”的构件/房间，规则和阈值见[空间推断](spatial-inference.md)。
- 完整 Site/Building/Storey/Space 边界面、同 GUID footprint 边界和真实桌面验收仍未关闭，见[问题与限制](../open-issues.md)。
