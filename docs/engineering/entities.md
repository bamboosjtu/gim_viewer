# 实体与来源模型

SDK 将 CBM、DEV、FAM 和 IFC 中的对象证据归一化为工程整体、成员和待归集合。归一化结果供[清册、工程组成和来源视图](composition.md)使用，几何继续按物理来源地址绑定。

## 来源与身份

来源实例指对象在当前源包中的一次实际引用。同一 DEV 模板被重复引用时，每次引用各有身份。实体 ID 由源包的 `scope` 和稳定来源证据构成，通常使用来源 ID。单相主变组和由明确宿主声明建立的候选整体，使用各自的编号或宿主证据。源包有 SHA 时以 SHA 为 scope，无 SHA 时使用会话标识。

| 数据 | 保存内容 |
|---|---|
| `EngineeringSourceGraph` | 原始文档、CBM 引用实例、来源记录、别名、引用解析结果和诊断 |
| `SourceRecord` | 对象自身字段、名称证据和原始父级。DEV 保存根来源、CBM occurrence 和装配路径。IFC 保存模型 ID、expressId 和 globalId |
| `ObjectEvidence` | 用于归一化的类别、角色、用途、宿主声明和组成候选，附原始证据位置 |
| `EngineeringSnapshot` | 工程整体、成员、待归集合、独立整体之间的关系和诊断。以 `evidenceBinding` 记录所消费的 scope 与来源图修订 |

路径解析依次查找引用方相对路径、包内路径和唯一文件名，分别记录解析成功、缺失和歧义。CBM 与 DEV 的真实引用决定 FAM 字段适用的对象。未匹配物理部件的 PARTINDEX 可保留为属性来源，沿已确认的 CBM 组成边参与归属。它没有 DEV occurrence 地址。

## 分类证据

类型、模型分类名称和装置名称等结构化字段优先。有可识别的中文分类声明时先用中文，再用英文补足。名称可提供候选类型。分类、用途、部件类型、整体边界和成员状态分别保存证据。跨分节或 Pset 的不同值保留各自上下文，同一上下文中的明确冲突保留待确认。具体词汇、默认值和例外见[目录识别规则](catalogs/reference-gaps.md)。

适配器按识别所需字段建立对象内索引，保留原始文件、行号和键名。IFC 按相同字段范围投影识别证据，完整属性和原文可按需查询。查询和来源缓存见[工程实体运行时](../architecture/engineering-runtime.md)。

## 组成与归属

1. 按来源 ID 稳定排序，检查唯一性和组成环，解释对象类别与角色。
2. 使用对象自身一致的主变编号和单相属性确定单相主变组。相别、设备编码或父级冲突时保留待归，成组之后仍单独记录相别完整性状态。
3. 按有效的 DEV 物理装配或 CBM `SUBDEVICE` 语义组成划分整体。已声明设备下的设备型成员可保留原类别并随宿主计入组成。属性不足的子件可保留为候选部件。明确独立角色建立自己的整体边界。CBM `SUBSYSTEM` 提供组织上下文，IFC 对象分解依其自身证据解释。
4. 用所属设备编码、名称或明确来源声明解析宿主。唯一且兼容的宿主可确认归属。已确认组成与宿主声明冲突时记录 `composition_host_conflict`，将受影响的成员保留待归。
5. 发布整体、成员、别名和诊断，检查每份来源的唯一主归属。独立整体之间的关联使用 `associated_with` 表示。

`memberships.parentPartId` 表示直接组成父级，`ownerId` 指向整个工程实体或待归集合。原始来源父级与物理表示地址仍由来源图保存。中性点附件优先使用实际组成或明确宿主证据，SDK 也可用对象自身带编号的工程名唯一匹配主变。祖先系统名仅供浏览。灯具端子板的候选归属需要 LED 声明和直接 DEV 装配证据。

## 未知、待归与来源诊断

| 情况 | 表达 |
|---|---|
| 类别证据不足 | `U-OBJECT`，保留对象及其来源 |
| 中性点附件宿主未知或部件无法找到整体 | `PendingWhole`，记录原因与来源 ID |
| 来源别名有多个可能对象 | 保留候选及解析状态，候选对象继续按各自身份计数 |
| 来源引用缺失、歧义或 IFC 无法解析 | 报告来源覆盖缺口，已解析部分仍可浏览 |

清册与工程树显示整体实例。待归信息出现在质量提示和模型树 JSON 元数据中，部件在所选实体的属性和来源视图中查看。实体计数、候选归属和人工签认分别处理，验证方法见[验证指南](../validation.md)。
