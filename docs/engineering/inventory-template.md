# 清册模型树

清册目录由独立 JSON 配置提供，工作簿仅作参考。实际层级为：

```text
设备 / 材料 / 构件
  → 目录类别
    → 模型名称（与类别相同时合并一层）
      → 名称模板（同名时并入目录层）
        → 实体实例
```

设备、部件、材料和构件分别使用独立 JSON 目录；工作簿中的对应索引表仅作参考。构件的梁、柱、钢梁、钢柱、钢结构等归“建筑物”，保护装置归设备部件“二次屏柜柜内装置”。未知类型、待归宿主和来源异常明确保留，不为了凑目录猜材质或归属。

清册只投影已存在的实体，不生成身份或物理引用。每个实体只有一个可选择的实例行，实例是叶子节点。部件、紧固件和来源记录在来源视图中保留，选中实体后在属性面板显示部件清单；它们不在清册或工程树中生成子节点，也不重复计设备台数。来源选择可通过成员归属映射揭示所属实体行，不生成替代来源行。

二次屏柜下按柜子的名称模板平级排列，保护柜、测控柜和网关机柜采用相同层级。已确认的功能细分仍显示在实体属性中，不用功能子类再包住部分柜子。空子类不生成“本体”占位层。待归集合不列为实体，数量保留在导航质量提示中，原因和来源 ID 保存在模型树 JSON 导出的 `metadata.pendingWholes`；实体快照与原始来源关系保持完整。

内部用途/边界码不决定清册目录。主变和站用用途保留在属性中；同名、同模板、树排序或目录更新都不合并实体、不修改几何根、矩阵或模板键。标准条目细分仍保留 candidate / confirmed 状态，类别确认不扩大成模型符合性判断。

生成数据和全部条目见[目录](catalogs/README.md)。

用户属性面板显示目录分类、名称、加载状态及中文部件清单，不显示实体 ID、规则版本、识别判据、边界算法和模板统计。部件名称不携带 JSON 或证据串；详细属性分页显示实际属性键值，内部证据仍供日志/导出与独立来源查询使用。
