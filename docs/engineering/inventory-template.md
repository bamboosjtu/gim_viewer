# 设备材料清册模型树模板

清册是工程实体的分类盘点投影，用于核对“有哪些整体、具体子类是什么、包含哪些实际来源”。它消费实体快照和中立来源摘要，不决定分类、整体边界、宿主关系或几何。`tools/gim_element` 提供目录和盘点表达参考；产品保留逐 occurrence 身份，不用同名模板桶合并实例。

## 树结构

```text
设备材料清册
├─ 设备
│  ├─ 主变压器
│  │  ├─ （本体） → 工程主变 → 实际组成来源
│  │  └─ 附件（并入本体） → 中性点成套装置 → 宿主待确认集合 → 来源
│  ├─ 二次设备 → 端子箱 / 屏柜 / 控制柜 / 蓄电池组 → 独立实例 → 来源
│  └─ 其他设备类别 → 可读子类 → 实例 → 来源
├─ 装置性材料 → 材料类别 → 子类或本体待细分 → 实例 → 组成来源
├─ 构件 → 四大类 → C 类别 → 可选角色 → 实例 → 组成来源
└─ 其他
   ├─ 待识别对象 → 未知整体候选 → 来源
   ├─ 待归整体 → 其他待归集合 → 来源
   └─ 仅来源（不计整体）→ 接口、无宿主紧固件等来源
```

没有证据的子类显示待确认，不根据形状补类别。E16 子码归入 E16 主类再按已识别子类分组；只有 E16 粗类、具体类型未知的整体直接挂在二次设备节点下，属性中仍保留子类未确认事实，不生成“具体类型待确认”树分组；E17/E19 保留具体类型；材料的本体、串/支柱、套管/桥架等子类来自实体元数据。构件子类的目录码与沟盖板等组件角色分别表达。不增加名称模板分组，同名实例仍有各自的工程实体行。

一级分组固定且仅有设备、装置性材料、构件、其他；未知、一般待归和仅来源状态是其他的子分组，不再成为一级业务类别。

中性点成套装置的类型识别与具体主变宿主绑定分开。类型已明确而具体宿主未知时，在主变目录的附件分支可见，保留待归集合与来源，不按全站存在主变、共同 F 层级或名称自动配给某台主变。宿主已由实际装配或明确编号确认的中性点装置保留在该主变的组成来源中。`attachmentCount` 单独统计中性点成套来源，不增加独立主变/设备数。

主变装配内端子箱、相本体和散热器列于主变的实际组成来源，不产生独立端子箱/主变台数。GIS、电容器等功能设备实际装配内的附属端子箱和操动机构箱归入宿主整体，不再在 E16/E17 下重复创建实体；图上邻近位置不作为依据。独立端子箱有自己的实体行。舱与内部独立柜分别保持实体，不将两级汇总相加成设备总台数。

## 身份、计数与选择

- 行 key 与实体 ID 分开；组 key 来自当前模板，实例行绑定实体 ID，来源行绑定来源 ID。
- `entityCount` 是分组内去重整体候选数，包含边界/分类未确认候选；`confirmedCount` 只计分类与边界都 confirmed 的整体。待归集合、内部来源与仅来源行不增加整体数。
- `sourceCount` 表示组成来源记录数，不是实物件数、长度、重量或供货数量。缺失工程量保持未知，来源字段保留原值和单位。
- 每个实体/待归集合恰有一个清册行；每份来源恰有一个来源行。中性点成套来源行带独立的附件标识和识别证据；附件的分类确认状态与宿主待确认状态分开。来源实际装配父与本来源属于同一 owner 时保留内部层级；关联的独立实体不会嵌成宿主内部来源。
- 选整体取来源成员的表示并集；选分类/子类组取去重实体范围；选来源进入该 occurrence。缺失、歧义和不可分离表示保持原有状态，不因为清册分组而增加或删除几何。

## 与其他树的模板解耦

| 投影 | 独立入口与规则 | 搜索上下文 |
|---|---|---|
| 工程组成 | `engineering/compositionTemplate.ts`、组成树构建器；空间细化为独立插件 | 系统、工程单元、建筑、楼层路径 |
| 来源 | `gim/engineering/sourceProjection.ts`；原 CBM/DEV/IFC 组织与引用 | 来源类型、文件与原组织 |
| 清册 | `engineering/inventoryTemplate.ts`；来源适配在 `gim/engineering/inventory.ts` | 类别、子类、实体及成员名称 |

三者只共享来源/实体身份、标准目录和通用 UI，不读取对方树节点来决定分组。清册搜索不复用工程组成的路径索引；自动空间细化仅替换组成树和组成搜索，来源与清册结果不变。

每个模板有独立版本，导航编排只组合结果；自动边界检查禁止模板直接依赖另一业务树的模板或导航编排。JSON 导出记录当前投影的 `templateVersion`，清册实例同时保留类别、子类、分类/边界状态、未知原因、默认粒度和确认计数；导航缓存目前仍是统一容器，校验三个模板版本与实体/来源依赖，不能将它描述成三个独立持久化文件。模板变化重建导航，不重识别实体或重编几何；分类规则变化重建实体及其依赖投影。版本索引见[缓存域](../architecture/caches.md)。

## 验证

分类矩阵覆盖属性优先、目录编码、子类与冲突；模板测试覆盖同名多实例、内部件不计整体、仅来源守恒、独立搜索、替换组成路径不影响清册/来源。真实四包入口为 `npm run test:engineering:classification`，输出位于 `output/v020-stage2`，不覆盖阶段 1 资产；缺样本即失败。该检查不替代完整九工程实体金标准、原生操作或性能验收。
