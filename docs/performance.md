## 当前优化实施状态

浏览器性能与可用性改造已完成第一批可回退运行时改动：普通选择/搜索只请求 DEV L0/L1，IFC/DEV L2 由属性面板的“查看精细模型”显式触发；精细请求与选择身份绑定，切换或取消选择会释放旧的 L2。共享计算 gate 释放后主动唤醒等待池，DEV 单任务 120 秒超时后终止所属 Worker、记录失败且不自动重试来源；池最多自动替换一次 Worker。等待超过 10 秒输出诊断快照，不将长计算直接判为死锁。

DEV 诊断新增 `workerScheduling`（会话、Worker 忙闲、排队数量与最老年龄、活动任务、gate 和结果预算）、`workerStages`（各阶段 count/totalMs/maxMs）、`workerTimedOutTasks`、`workerStallSnapshots`、`workerSourceAffinityHits` 与 `workerSourceAffinityDeferrals`。`viewIndex` 记录 entries/rebuilds/visitedNodes/testedBoxes/candidates，用于核对空间筛选覆盖及成本。显式 L2 失败另记入有界 `fineFailures`，不会覆盖已经可浏览的 L0/L1 失败状态。同一来源的后续 LOD 会优先回到拥有其解析缓存的 Worker，但不阻塞其他来源。阶段耗时是聚合执行信息，不能相加作为并行管线墙钟；快照不包含原始模型数据。

运行时还记录可用的 JS heap 压力、结果队列和渲染器 draw calls。JS heap 达到 80% 时停止自动 L1 细化并主动淘汰未保护模板，达到 90% 时拒绝新的主动 L2；这不是对 Tauri 进程树或 GPU 驻留的硬上限。状态栏明确区分“工程可浏览”“当前视图完成”“基础表示完成”和“部分失败”，并提供只暂停自动后台细化的按钮；L0、目录范围和连接线来源任务不因该按钮停止。

当前已取得一组具有源码/二进制/运行时指纹及原生缓存路径校验的 Release 单次冷暖记录，三次冷暖矩阵尚未完成，不能宣称整站加速或达标。连接线已接入真实源三角网格优先提取与分块传输，使用独立可选完整凭据缓存，旧远景缓存仍有效，并记录 `IFC connection preview first batch` 与 `IFC connection preview settled` 阶段。连接线跨样本的完整时间、对象/坐标集合一致性及缺少 IFCGUID 时的 CBM/DEV 电气归属仍未验收。DEV 实例化试点、树虚拟列表固定路线、6 GiB 峰值及 10 次工程切换也仍需原生验收。当前会话内最多 20 步的视角/可见性历史、变电站总览、仅看选中/恢复全站、失败设备局部重试及暂停自动细化入口已实现；这些入口不替代路线验收。下列历史整站测量不作为本轮改造的验收结果。

## 4. 当前实现的性能相关事实

- **DEV Worker 池**：按逻辑核 60% 创建，2–8 个；IFC 期间最多 2 个编译，IFC 完成后放开到全池。实测把池提高到 90% 会使 sub01 从 225/285 掉到 81/285，已回退。
- **目录任务**：catalog 按 DEV 流式消费（并发 32），单个慢 DEV 不再阻塞下一批；compile gate 满时，空闲 Worker 继续跑 bounds。
- **缓存**：
  - TS/Rust 统一 `geometry-cache-v14-outline-lod01`；
  - 并发创建同一缓存目录时 `AlreadyExists` 视为成功；
  - catalog 命中预取每批 64，模板/catalog 批读 16→64。
- **LOD**：
  - L0 覆盖全部 DEV，不隐藏整台设备；
  - L0/L1 省略浏览级紧固件、小环及圆形垫片（最大尺寸 ≤100 mm）和 ≤50 mm 的 Cuboid；装配缩放参与尺寸计算，整台 DEV 全部被过滤时保留最大有效轮廓；
  - L0/L1 不执行 CSG：差集与交集显示第一操作数，并集组合操作数轮廓；简化属于该 LOD 的正常结果，精确布尔保留在 L2；
  - Wire/Cable 永不省略；
  - L2 保留精确 CSG。
- **连接线**：substation01/03 的设备连接线主要来自 IFC `IfcBuildingElementProxy`（“导线/软导体”），不在 DEV/MOD 中。Worker 以导线/软导体实体名称及电缆/导线段实体类型作为保守源证据，优先分块显示真实源网格，随后由 Fragments 接管；文件名只影响调度优先级，不参与对象分类。substation04 的部分备用出线间隔在源数据中没有任何连接线 DEV。见 [open issues](open-issues.md)。

## 6. 复现

1. Release 构建：`desktop/` 下 `npm run build`，再执行 Tauri release 构建。
2. 按测试指南核实独立验收缓存的实际路径，冷启动只清理该目录；不删除用户日常缓存。
3. 使用 SLO harness 记录 First usable、Current view、Full fidelity 和阶段 DEV 计数。
4. 完整暖启动必须在冷启动基础表示 settled 且对应缓存写入完成后仅重启进程；此前的再次打开只能标为部分缓存恢复。


## 7. DEV 轮廓策略的验证边界

substation02 的 8 个含至少 300 个布尔节点的 MOD，L0/L1 共 16 次局部烘焙检查均未调用 CSG，耗时约 5–20 ms。该检查只覆盖解析后的 MOD 烘焙，不含全站 IFC、GLB 序列化、缓存读写与场景提交，不能代替桌面整站验收。

独立验收包从 Windows 临时目录运行已验证原生启动和专用缓存路径；仓库输出目录的启动故障仍单独记录。当前版本的三次冷启动及对应暖启动尚未验收。浏览器补充检查与原生口径分开；已有源几何异常仍保留失败诊断，不能用 processed 总数作为完整显示成功的证明。


生产前端的无头 Chromium 补充运行已到达基础表示 settled：3326 个实例中显示 2731、合法空源 561、失败 34，模板 pending 和场景提交等待均归零，IFC 最终 17/17。该运行的 First usable 约 22.2 s，Current view/base settled 约 458.2 s；运行时存在其它检查并行，不能作为独占性能基线，也没有达到 60 s 目标。34 个几何范围超限实例仍保留失败诊断；该结果不等同于全站完整显示成功。
