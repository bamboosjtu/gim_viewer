# 性能基线

本文件维护桌面原生与浏览器开发模式的性能基线、测量口径和未达标项。方法见[测量指南](meassurement.md)，缺陷与限制见[问题清单](open-issues.md)，未采用的性能路线见[探索记录](impl/explorations.md)。

桌面 0.1.2 修正拉伸体方向基矢、补齐 PHM SOLIDS 引用组并更新 DEV 几何与范围派生键，受影响产物首次打开需要重建；合法语义、IFC 与 Spatial 缓存独立保留。下表数字来自该版本之前最后一次完整的指定提交对照，不能直接充当 0.1.2 的性能验收。设备冷开、缓存重开和工程切换仅作功能回归，没有新的性能达标结论。普通笔记本诊断及本轮候选对照见第 7 节。

## 3. 视口选择与 DEV 拾取

substation01 暖恢复完成后，十个固定 canvas 点重复两遍；页面实际收到 click 的捕获回调为起点，当前请求高亮标记被观察并进入下一次 RAF 回调为终点。剔除旧 request、空点击和无结果；三组各 20 次尝试、18 次有效 IFC 命中，命中身份序列相同。不是 20 个独立来源的验收，也不是 GPU 呈现时间。

| 构建 | 尝试/有效 | p50 ms | p95 ms | max ms |
| --- | --- | --- | --- | --- |
| b414a59 | 20/18 | 373.2 | 487.1 | 487.1 |
| 7b4d0fc | 20/18 | 375.0 | 491.9 | 491.9 |
| 最终基线 | 20/18 | 321.7 | 427.0 | 427.0 |

最终基线没有出现明显选择回退，但 p95 仍远高于 100 ms；小样本的 p95 等于最大值，不能宣称已稳定改善整体延迟。已缓存属性概览 DOM p95 没有单独采集，O-07 不关闭。IFC 拾取始终通过公开 getVisible 核对命中；自动 L1 也会隐藏被替换的远景对象，不能仅以选择隔离或 L2 状态判断是否需要核对。

普通 DEV 拾取使用已提交表示的包围盒筛选候选，直接遍历 occurrence 行并排除隐藏祖先和子组，不逐点击构建全量网格数组。对四站真实 L0 子集的交替对照，CPU p95 为 1.9/3.0/1.1/2.7 ms → 0.7/2.1/0.4/2.2 ms，命中身份和距离一致；隐藏父图层后 Mesh 射线为 0。该实验只覆盖列出的几何子集，不代表整站端到端响应，也不是整站 BVH。

## 6. 验证与复现

正式包通过 TypeScript、Vite 与 Rust Release 构建；完整单元测试为 128 个文件、1117 项通过、3 项既有跳过，严格四站 SQLite/浏览链全部通过、必需样本零跳过。

开发服务：在 desktop/ 执行 `npm run dev -- --host 127.0.0.1 --port 14317 --strictPort`。正式原生构建使用 `acceptance:build` / `acceptance:stage`；核实 EXE、实际提交标记、固定运行时及 `get_db_path` 的隔离数据根，再通过最近工程打开，Ctrl+Shift+B/D 导出。

正式构建/源码审计与同运行时证明位于 `output/review-open-issues/formal-builds.json`、`formal-environment.json`；原始逐轮数据和点击观测在 `native/`，浏览器 JSON/截图在 `browser/`。临时脚本和产物位于 Git 忽略目录，不进入发布构建。验收步骤以[测量指南](meassurement.md)为准。

## 7. 普通笔记本诊断与部分缓存恢复

用户提供的是流程重新运行后的诊断，未包含最初停滞瞬间或硬件/EXE manifest，因此不能认定最初暖开发生永久死锁，不能作为上一提交引起性能回退的 A/B 证明。三份导出在采集时没有 Worker 超时或活动计算队列。

| 输入 | First usable s | 全 IFC s | 基础 DEV s | 当前视图 s | 导出时缓存待写 |
|---|---:|---:|---:|---:|---:|
| s01-cold | 15.22 | 20.31（12/12） | 45.12 | 45.33 | 235 |
| s01-warm | 4.43 | 10.31（12/12） | 12.48 | 12.71 | 0 |
| s02-cold | 14.49 | 24.52（17/17） | 46.68 | 未达 ready | 1041 |

s01-warm 命中全部 285 个 L0，但另编译 4 个 L1，不是全 L1 命中。s02 的 3326 occurrence 中显示 2731、空源 561、失败 34；失败均来自同一异常坐标 DEV 的重复实例，不能把准备/显示差全部算作提交积压。模型显示和缓存落盘分别计量，待写未归零时退出后再次打开可能需要重新编译。

运行时保留每轮 4 ms 的提交预算；L0 不再被持续相机更新推迟，精化提交最多因运动延后 1 秒，避免队首精化挡住基础表示。该活性修复有针对性回归，不代表四站冷暖与持续路线 SLO 已通过。源准备候选、失败探索、构建指纹和原始记录边界见 [本轮报告](impl/test-laptop-regression-and-2018-equipment.md)；本轮不关闭 O-01/O-02/O-07。

同 EXE、Fixed WebView2、1600×900、4 核提示/2 Worker、主线程 CPU rate=4 的部分暖缓存对照，只缺失同一个 L1 模板：A1→B1→B2→A2 当前视图为 **72.99→58.07→58.85→76.21 s**，两对改善 20.4%/22.8%。新增源准备仅读取缺失 DEV 可达的 33 文件/42,766 B，Worker 源 RPC 33→0；四次 L0 均命中 285、只编译 1 个 L1、IFC 全命中 12/12，显示数量一致且无失败/超时。因此保留该有界补偿；第一版逐边异步 Blob 文本读取出现长尾，已撤回。该主机限速实验不是普通笔记本仿真；L0、IFC 与内存没有已证明的稳定收益，不改写既有整站 SLO。

本轮功能检查为快速套件 130 文件/1137 项通过、3 项既有跳过；四站真实 SQLite/浏览链全部通过、必需样本零跳过。原生抽查覆盖 CT 冷暖、裸 ZIP、部分支持设备和设备↔变电进程内切换。均不替代四站三轮性能矩阵。
