# 性能基线

本文件维护桌面原生 Release 的当前性能基线、测量口径和未达标项。方法见[测量指南](meassurement.md)，缺陷与限制见[问题清单](open-issues.md)，未采用的性能路线见[探索记录](impl/explorations.md)。

本轮基线为提交 `745e1363ba6bff9d9241b9961c0e6fa89d3c6e19` 的验收 Release：源码指纹 `bc239d67fb93fc7617fc83cc633ed3958c38cbd95c9d3e798ab364e9441a1169`，EXE SHA-256 `5e05ea2aecb29a174513d100475a58cdc23e8a5bee3c17e03b1e7570cb9782f1`，Fixed WebView2 目录 SHA-256 `1bc71a6d464da1cd3f63ac1ff0d1b748f528aa8b3957b5e3a7f9ae28d6df7071`（257 个文件、705,180,410 B）。测量在 2026-10-31 完成，使用九个变电工程样本各一次冷启动，其中七站完成三次暖启动；B1-3/B1-4 因冷缓存未完整发布未形成有效暖矩阵。数据库、页面缓存和 WebView profile 按样本隔离，不读取日常缓存。

本轮不是完整验收：缺少每样本三次真冷、线路六包、固定路线持续交互、工程切换和低配矩阵。默认 12 逻辑核下实际 DEV Worker 为 7–8 个；旧基线的“4 核提示/2 Worker”条件不同，不能直接比较。本文只覆盖该构建、主机和下列样本。测量后删除未引用的空间推断入口及其测试，并修复来源树的 `aria-expanded` 展开恢复；后者不改变本次测量的打开、几何或缓存路径，源码指纹仍对应测量时的干净提交。

## 1. 构建、环境与口径

| 项目 | 值 |
|---|---|
| 主机 | Windows 11 26300，Intel i7-8700（6 核 / 12 逻辑核），63.8 GiB，NVIDIA Quadro P4000 |
| 运行时 | 随包 Fixed WebView2 155.0.4283.62；验收 identifier 的独立数据根 |
| 窗口 | 原生外框 1600×900，移出屏幕但不最小化；未做 CPU 限速 |
| 并发 | 逐次运行；矩阵期间不同时构建或跑测试 |
| 缓存 | 每样本独立 WebView profile；冷启动删除工程记录、提取目录、派生缓存和 profile，暖启动复用 |

时间单位为打开动作后的秒数，不含 exe 启动。First usable 沿用 `productMoments.interactive`，即首个 IFC 可浏览；导航 DOM 另有 `navigationUiReady`，不能当作输入延迟通过。Current view 使用 `devCurrentViewSettled`，基础表示使用 `devBaseRepresentationsSettled`，IFC 结束使用 `allIfcReady` 并同时列出失败。Spatial 使用 `spatialSemanticReady`；没有该时刻表示空间索引未在测量窗口内就绪。

冷启动有效要求语义未命中、L0 冷编译、IFC 全部冷转换。暖启动有效要求语义命中、L0 冷编译为 0、IFC 全部 LOD 命中；`严格暖` 还要求所需 L1 冷编译为 0。只命中 L0/IFC 但重新编译 L1 的运行标为普通暖，不写成严格全命中。完成判断读取应用状态和性能标记，不只依赖可能被迟到回调改写的状态文字。

- 所有冷运行的 IFC 失败数为 0；失败 occurrence 只出现在 substation02 的 34 项，保留在表中。B1-4 的未显示 occurrence 不是失败，而是窗口结束前尚未提交。

## 6. 交互

在 `substation01` 暖恢复后执行固定十点、两轮共 20 次点击，记录点击、当前请求高亮、下一帧和属性文本更新时间。该次打开的当前视图为 8.92 s，20 次选择期间新增 82 个 L1 冷编译、1 项缓存待写，因此不是严格全命中暖启动。

| 点击次数 | 有效请求 | 点击至高亮 p50 / p95 / max ms | 点击至下一帧 p50 / p95 ms | 属性文本 p50 / p95 ms |
|---:|---:|---|---|---|
| 20 | 20 | 433.2 / 566.9 / 656.9 | 455.7 / 596.2 | 25.1 / 35.2 |

选择触发的 L1 工作集是延迟主因，不能把该结果写成纯高亮提交成本。p95 566.9 ms 高于 100 ms 目标；本轮未采集独立 GPU 呈现或“已缓存属性概览 DOM”的完整 p95，属性文本时间也不能替代面板 DOM。旧固定路线 p95 427 ms 与本次点位、L1 计数和默认线程条件不同，不作前后回退结论。

## 6.1 交互边界

- 选择点击使用当前相机和固定页面坐标，不代表任意对象、任意视角或触摸输入。
- 高亮集合非空只证明当前请求已提交，不证明 GPU 已呈现；下一帧标记是页面 RAF，不是显示器扫描时间。
- 区域/间隔聚合、隔离恢复、L2 精化和工程切换的端到端时间不在本节范围内，仍需独立固定路线验收。

## 8. 失败、异常与边界

- `substation02` 有 561 个空源和 34 个失败 occurrence；它们保留在状态和诊断中，不因本次打开成功而消失。
- `A3-1` 与 `B1-1` 的 `allIfcReady` 分别约 90 s 和 117 s，基础表示分别约 86 s 和 235 s；大站冷启动仍远高于 60 s。
- `B1-3` 冷启动在 130.62 s 完成基础表示、202.16 s 完成全部 IFC，但辅助窗口内 Spatial 未就绪、业务快照仍在构建；该状态不能标记为完整冷启动成功后的暖缓存。
- `B1-4` 的 1,500 s 窗口内基础表示未完成，15,161/15,526 个 occurrence 已显示，L0 冷编译 4,188 个模板，仍有 2 项缓存待写；private 峰值约 6.89 GiB，长任务累计阻塞约 937 s。该样本不能写成“慢但完成”。
- 暖运行中 `substation01`、`substation03`、`substation04`、`B1-2` 出现 1–5 个 L1 冷编译；只有部分轮次满足严格暖。不能用中位数掩盖这些轮次。
- 本轮所有已测样本 IFC 失败数为 0；没有把超时或空源计为通过。

## 9. 复现与证据

1. 在 `desktop/` 执行 `npm run acceptance:build`，再执行 `npm run acceptance:stage -- <acceptance-build.json>`；只用暂存副本运行，避免验收 exe 继承仓库目录 ACL。
2. 每个样本使用独立 WebView profile；冷启动前删除该工程的数据库记录、提取目录、派生缓存和 profile，暖启动复用同一 profile。
3. 最近工程列表只显示 6 项；批量矩阵必须在打开前确认目标工程在列表内，或按数据库 ID 打开，不能把“列表里没有”误判成缓存 miss。打开样本后等待 First usable、当前视图、基础表示、全部 IFC 和 Spatial 各自的产品时刻；冷启动额外等待缓存待写归零，空间/业务快照在辅助窗口内结算。
4. 记录构建身份、源 SHA、缓存状态、冷/暖标记、L0/L1 编译与命中、失败数、private 采样和长任务；不要把不同构建、不同 worker 条件或不同缓存状态混在一张表。
5. 原始 JSON、日志和截图保存在 `output/` 或临时目录，不提交真实工程属性、坐标或构建指纹；正文只保留可复核的统计与边界。

本轮使用的验收 manifest 位于 `output/acceptance/builds/2026-10-31T00-16-23.633Z-bc239d67fb93/acceptance-build.json`。矩阵原始记录位于 `output/perf-2026-10/`，不进入 Git。
