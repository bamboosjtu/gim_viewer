> 状态：设计规范，供 UI、解析适配器和验收测试共同使用
> 日期：2026-08-29
> 适用范围：GIMPKGS 变电工程、GIMPKGT 线路工程桌面端
> 关联文档：[变电导航选型分析](./substation_navigation_strategy_analysis.md)、[设计系统](./design_system.md)、[变电菜单简报](./substation_menu_brief.md)、[线路菜单简报](./powerline_menu_brief.md)、[组件简报](./component_brief.md)

## 0. 决策摘要

变电和线路不使用同一棵“万能 CBM 树”。两类工程的可理解单位不同：

| 工程 | 左树主策略 | 主树最小语义单元 | 分类视图的角色 | 缺失数据时的默认策略 |
| --- | --- | --- | --- | --- |
| 变电 | **空间—功能双轴联合导航** | 空间容器；功能系统域 → 系统/间隔 → 设备或构件 | 专业为过滤面，类别为设备工作区投影 | 没有可靠空间关系时自动打开功能系统，不伪造场地区域 |
| 线路 | **组成关系优先、拓扑顺序约束** | 区段 → 耐张段 → 塔位/档距 → 导线/跨越物 | 资产工作区中的平行投影 | 无法分段时保留顺序和“未分段对象”，不虚构耐张段 |

一句话原则：**树回答“对象在工程中属于哪里”，资产表回答“有哪些对象”，来源页回答“它来自哪个文件”。**

本文的业务树是原始 CBM/DEV/PHM/MOD/IFC 图的投影，不是对压缩包目录的重新命名。原始节点始终可从“来源”页追溯，但不污染默认树。

## 1. 真实样本证据与设计边界

### 1.1 变电样本证据

本规范采用四个匿名变电样本的全量复核，以及其中一个样本的 F2/F3/F4 深度统计。数字用于验证设计压力，不得在产品中写死。空间实体和空间包含关系的逐样本快照见[变电工程空间信息模型审查与补齐方案](./substation_spatial_model_review.md)：

| 事实 | 观察 | 对导航的影响 |
| --- | --- | --- |
| 单样本原始层级 | F1=1、F2=14、F3=145、F4=4,645、PARTINDEX=3,894 | 不能把每个原始节点一次性展开；必须惰性生成和虚拟滚动 |
| 专业与功能域 | 变电站01有 U/A/S/G；变电站02、03 的 F2 码分别为 `1/2/3/4/Y/导线布置/02`、`1/Y`，不能直接映射专业；但四样本 F3 均能形成 2–5 个主要功能域 | F2 文件数不等于业务重要性；F3 功能域作为首层，已知专业成为徽标/过滤面，未知 F2 保留为来源码 |
| F4 角色 | 约 93.9% 为 IFC 构件入口，约 6.1% 为 DEV 设备入口 | F4 不能统称“设备”；树中分成“构件”和“设备”两个业务角色 |
| IFC 归属 | F4 的 IFCFILE 可能与父级专业不同 | IFC 文件只能作为来源/构件证据，不能反向改写专业归属 |
| 设备类型 | DEV 中约 93% 为 `OTHERS` | `DEV TYPE` 只能做次级筛选；默认分类使用业务名称和对象角色，不显示 `OTHERS` |
| F3 名称 | `-`、`其它`、`其他`、编码和重复名称很多 | 过滤占位符；重复时以子对象/模型证据消歧，原始编码退到来源页 |
| PARTINDEX | 与 DEV `SUBDEVICE` 按索引一一对应，是语义节点，不是第二个几何实例 | 只显示一个部件节点；保留 PARTINDEX 与 DEV_SUBDEVICE 双来源标签，禁止重复几何 seed |
| 空间实体 | 四个样本均有 `IFCPROJECT/IFCSITE/IFCBUILDING` 和 `IFCBUILDINGSTOREY`；变电站04另有 5 个 `IFCSPACE` | IFC 空间容器可以作为主树；是否能把 CBM 资产挂到容器要另算关联覆盖率 |
| 空间包含关系 | 四个样本均有 `IFCRELCONTAINEDINSPATIALSTRUCTURE`；直接包含对象为 3,111 / 51,767 / 9,572 / 7,182，连同分解和宿主关系继承后，空间树可达对象为 4,714 / 62,176 / 9,572 / 7,720 | 不因 CBM→IFC 关联不完整而隐藏空间树；楼层/空间下的 IFC 构件仍应可浏览，并区分直接、分解继承和宿主继承 |
| CBM 空间关联 | 变电站01有 4,360 个 F4 IFCGUID，命中 3,244 个，落到楼层/空间 2,253 个；变电站02–04 的 F4 未提供 IFCGUID | 将“空间主树可用”和“资产直接关联可用”拆成两个质量指标，未关联资产进入明确的质量分组 |
| 设备位置证据 | 变电站02–04 的 F4 变换矩阵覆盖率为 100%，非单位矩阵分别为 2,436 / 150 / 428 个 | 矩阵可支撑“坐标定位对象”视图；没有 IFCGUID 时不能冒充已确认的 IFC 空间归属 |
| 导出差异 | F2/F3 比例、PHM 嵌套、`.gl`、STL 角色和 SCH/STD/SLD 均随工具变化 | 所有入口能力和字段必须能力驱动；不能把某个导出工具的结构当成 GIM 通用规则 |

依据：[19a 变电层级研究](../schema/19a-substation-hierarchy.md)、[20 PARTINDEX 更正](../schema/20-substation-partindex-alias-correction.md)、[22 十样本复核](../schema/22-ten-sample-verification-0824.md)。

### 1.2 线路样本证据

一个线路样本的回归结果为 CBM 总节点 9,276、杆塔 129、导线段 2,232、跨越物 44；六个线路样本均复现了 WIRE/TOWER/CROSS 的业务映射。该数量级说明线路树必须按拓扑节点分层，而不是显示全部 CBM 行。

- `WIRETYPE` 通过 `WIRE → DEV → FAM` 链获得；不能只读 WIRE 节点的空壳名称。
- `KVALUE` 是弧垂相关字段；`KVALUE=0` 或挂点重合可作为跳线候选标记，但它们不是树层级。
- 跨越物应挂在所属档距下；无法建立关系时进入“待关联跨越物”，不能丢失。
- 坐标缺失只影响地图定位，不得从路线树和属性中删除塔位或跨越物。

依据：[线路菜单简报](./powerline_menu_brief.md)、[十样本复核](../schema/22-ten-sample-verification-0824.md)和[导线悬链线证据](../schema/15-wire-catenary-evidence.md)。

### 1.3 非目标

- 不在本规范中改变 GIM 解析格式、几何矩阵或数据库表结构。
- 不把“空间”“系统”“资产”复制成三份对象数据；它们必须共享同一个 `selectionId` 和规范化对象图。
- 不把效果图中的 M1/M2 工具误认为 M0 已实现能力。

## 2. 统一导航外壳

### 2.1 工作区轨道

左侧 52 px 工作区轨道根据工程类型注册入口；入口的显隐由工程类型和能力标记决定：

| 工程 | 工作区 | 作用 | 默认展开内容 |
| --- | --- | --- | --- |
| 变电 | 模型 | 空间结构 / 功能系统两个同级视角 | 空间来源模型行；切到功能视角时显示功能系统域行 |
| 变电 | 设备 | 分类树、资产表、选择集 | 设备分类行 |
| 变电 | 图纸 | SCH/STD/SLD 及其关系 | 仅在实际存在时注册 |
| 线路 | 路线 | 线性组成和拓扑顺序 | 工程根 + 线路 + 区段 |
| 线路 | 资产 | 杆塔、档距、导地线、跨越物 | 资产类型行 |
| 线路 | 图层 | 线路叠加层、标签、底图 | 业务图层组 |
| 线路 | 质量 | 坐标、属性、引用、底图问题 | 问题分组行 |

“来源”不是高频工作区，而是所有对象检查器中的固定页签；需要工程级诊断时，从项目菜单进入来源摘要。

### 2.2 树行统一契约

树行从左到右固定为：展开箭头 → 对象类型图标 → 业务名称 → 可选的紧凑计数/状态徽标。默认名称不得包含扩展名、完整 UUID、长路径或原始 `ENTITYNAME`；可见性和更多操作只在支持该操作的工作区中按需出现。

行内只显示能帮助定位层级的短信息：

- 数量：域、系统、角色组或部件组的去重对象数；
- 质量：仅在“未关联/待关联/无法定位”等质量分组中显示短状态；
- 推断：名称或分段由规则推导时保留“推断”标记。

塔型、坐标质量、长度、分裂数、来源码、文件路径和 IFC 类型等技术字段不放在树行中，统一保留在行标题（tooltip）、搜索索引和右侧属性面板，避免业务名称被省略。

质量不能只用颜色表达；必须同时有图标、文字和可筛选计数。

### 2.3 展开、搜索和选择

1. 首次打开只展开工程根和第一层业务聚合；系统、资产和构件明细默认折叠。
2. 子项超过 100 个时惰性生成；可见行超过 1,000 时启用虚拟滚动。
3. 搜索命中后只展开当前视角的“工程根 → 命中对象”祖先链，不展开兄弟节点；结果同时提供空间路径和功能路径，另一视角通过显式动作进入。
4. 单击选择，双击定位；点击箭头只展开，点击眼睛只改变可见性。树、3D、地图、图纸和资产表共享 `selectionId`。
5. 技术字段可搜索，但命中行仍显示业务名；来源页显示匹配的 GUID、文件名或原始键。
6. 普通选择不自动切换空间/功能视角；对象在当前视角无路径时，显示原因和“在另一视角查看”动作。

## 3. 变电工程：空间—功能双轴联合导航

### 3.1 选择理由

变电站的用户任务同时依赖站区位置、功能系统和资产类别。四样本方案评分与逐样本展示量见[变电模型导航方案选型分析](./substation_navigation_strategy_analysis.md)。真实样本已经普遍提供 IFC 空间实体和包含关系，但 CBM→IFC 的直接关联随导出工具变化，因此采用“一个对象图、空间与功能两个一等投影”的策略：

- 只要存在可验证的 IFC 空间实体和包含关系，模型工作区就注册并优先显示空间结构；
- 资产关联覆盖率低只影响关联徽标和“坐标定位/未关联”分组，不整体隐藏空间结构；未落入空间的 IFC 产品另设质量分组；
- 功能系统始终作为同级可切换视角，保证没有 IFCGUID 的 CBM 设备仍可访问；只有在空间实体或包含关系确实缺失时，才把功能系统作为默认视角，并在树头显示缺失原因；
- 不允许仅凭 U/A/S/G 或 IFC 文件名创建“场地、生产区、主变区”等看似真实的空间节点。

### 3.2 模型工作区的两个一等视角

#### A. 空间结构（`hasSpatialEntities && hasSpatialContainment` 时注册）

空间树只放样本明确提供的空间关系；空间主树的可用不代表每个 CBM 资产都已关联。通用形状如下，方括号表示运行时实际名称，不是固定文案：

```text
变电工程
├─ IFC 模型 · n
│  ├─ [来源模型] · IFC 构件 n · 属性 n
│  │  └─ [有业务名称的站区/建筑] → 楼层（按 IFC 原始关系）
│  │     ├─ [实际建筑或构筑物] · IFC 构件 n · CBM 关联 n
│  │     │  ├─ [实际楼层/标高] · IFC 构件 n · CBM 关联 n
│  │     │  │  ├─ [实际空间/区域]（有 IFCSPACE 时）
│  │     │  │  ├─ IFC 构件（直接 + 分解继承）
│  │     │  │  └─ 关联设备
│  │     │  └─ 未命名楼层 / 无空间名称
│  │     └─ 无楼层的 IFC 构件
├─ 关联状态（折叠）
│  ├─ 坐标定位对象（位置推断）
│  ├─ 已关联 IFC · 无空间容器
│  ├─ 未关联 IFC 对象
│  └─ 未落入空间的 IFC 构件
└─ 模型资源（属性集 / 几何拓扑 / 关系统计，折叠）
```

“坐标定位对象”“未关联 IFC 对象”“未落入空间的 IFC 构件”和“无楼层的 IFC 构件”都是合法的质量降级节点；它们在首层收拢到一个“关联状态”组，必须保留来源、坐标和原因，不能被改名为“辅助区”或其他猜测出来的区域。属性值、几何拓扑和关系记录只在“模型资源”中按模型/类型统计，不计入业务构件数。“功能系统”通过树头分段切换器进入，不能作为空间树的子节点。

空间树的 Project、Site、Building 仅在名称能区分真实业务空间时显示；`项目编号`、`Default`、`Project`、`Site`、`Building`、`IFCBUILDING #...` 等导出器包装层在模型分组内扁平化，后代楼层/空间/构件直接提升显示。原始节点仍保留在索引、搜索和属性来源中，不改变空间关系事实。

空间索引至少计算六个去重计数：`IFC 构件`（空间树可达的 IFC 实体）、`直接`（IFCREL*SPATIAL* 直接包含）、`分解继承`（沿 IFCRELAGGREGATES/DECOMPOSES/NESTS 继承）、`宿主继承`（沿 IFCRELVOIDSELEMENT/IFCRELCONNECTSPORTTOELEMENT 继承）、`CBM 关联`（IFCFILE+IFCGUID 直接命中的业务对象）和 `位置推断`（仅有 CBM/DEV 变换矩阵）。树行只展示紧凑对象数，完整计数和“已确认/分解继承/宿主继承/位置推断/未关联”证据放在 tooltip、检查器和质量分组；不能用一个“空间可用”布尔值掩盖资产关联缺失。

关联证据的优先级固定为：

1. `IFCFILE + IFCGUID` 命中 IFC 实体，并沿 `IFCRELCONTAINEDINSPATIALSTRUCTURE` 到达楼层/空间：已确认；
2. IFC 实体沿 `IFCRELAGGREGATES`、`IFCRELNESTS`、`IFCRELDECOMPOSES` 继承到空间，或通过 `IFCRELVOIDSELEMENT` / `IFCRELCONNECTSPORTTOELEMENT` 从宿主构件继承到空间：已确认但分别标记“分解继承/宿主继承”；
3. 只有 CBM/DEV/PHM/MOD 变换矩阵：显示在“坐标定位对象”，标记为位置推断；
4. 无法唯一判定时进入“未关联 IFC 对象/未定位对象”，并显示 `no-ifc-guid`、`ifc-guid-not-found`、`no-transform` 等原因；可识别但没有空间容器的 IFC 产品进入“未落入空间的 IFC 构件”。

多个 IFC 文件都使用 `Default`、`Default Project`、`Default Site`、`$` 或空名称时，运行时在空间根下生成稳定的“IFC 模型”虚拟分组，再展开各自的原始容器；只有名称、父容器和几何范围都一致时才合并，避免把不同模型误合并为一个建筑。搜索定位会自动展开该模型分组。

#### B. 功能系统（所有变电工程可用的平行视角）

```text
变电工程
├─ 交流电气系统 · 131 个系统 · 专业 A
│  ├─ 跨电压等级系统 / 调度数据网（折叠）
│  │  ├─ 设备（仅在同一系统兼有构件和设备时插入角色组）
│  │  │  └─ 调度数据网设备柜 · 部件 35
│  │  └─ 构件
│  └─ 防雷接地系统 / 接地系统 · ...
├─ 建筑物 · 5 个系统 · 专业 U
├─ 构筑物 · 7 个系统 · 专业 U
├─ 空调系统 · 1 个系统 · 专业 S
├─ 排水系统 · 1 个系统 · 专业 G
└─ 未归类系统（全树最多一个）
```

示例中的数量来自变电站01压力测试，实际界面必须动态计算。功能系统域取 F3 `SYSTEMNAME1..4` 中第一个可靠业务名称；U/A/S/G 作为专业徽标和过滤条件，不再固定占据第一层。功能域默认折叠，展开后才生成 F3 系统行。

#### C. 功能系统域归一化与专业降级

四个样本证明功能系统域比专业首层更稳定。变电站02、03 的 F2 无法直接映射专业；变电站04虽然为 A，但只有一个专业行，仍缺乏区分力。统一从 F3 业务名称生成首层：

```text
变电站02
├─ 电气系统（推断） · 49 个系统 · 3,242 个 F4 · 来源码 1/2/3/4/Y
└─ 未归类系统 · 2 个系统 · 84 个 F4 · 来源码 02/导线布置

变电站03
├─ 电气系统（推断） · 29 个系统 · 160 个 F4 · 来源码 1/Y
├─ 建筑物系统（推断） · 2 个系统 · 0 个 F4 · 来源码 Y
└─ 未归类系统 · 1 个系统 · 2 个 F4 · 来源码 Y

变电站04
├─ 交流电气系统 · 12 个系统 · 511 个 F4 · 专业 A
└─ 未归类系统 · 2 个系统 · 21 个 F4 · 专业 A
```

降级规则：

1. 取 F3 `SYSTEMNAME1..4` 中第一个非空、非 `-/$/NULL/其它/其他/&其他`、非纯数字的业务名称，做同义归一化后形成域。
2. F3 名称无效时，读取可验证的 `SYSCLASSIFYNAME` 前缀；由前缀得到的域必须标记“推断”。
3. 两者均无可靠证据时，所有剩余对象只进入**一个**“未归类系统”行；原始 F2/F3 值以来源 chips 展示。
4. F2 为 U/A/S/G 时保存为已确认专业徽标和过滤字段；其他 F2 仅保存来源值，不生成多个“未分类专业”。
5. 若整个工程没有任何可用 F3 语义，首层使用“系统总览”，其下直接列 F3 行；这是可用性兜底，不是业务分类。

首层排序优先采用来源顺序稳定的有效功能域；同序时按“电气 → 建筑物/构筑物 → 暖通 → 给排水 → 其他有效域 → 未归类系统”。专业筛选内部仍可按 U→A→S→G 排序。这一步只改变导航投影，不改变 F2/F3 原始归属。

### 3.3 设备工作区的分类投影

设备工作区不是系统树的复制，而是面向清单和筛选的资产投影：

```text
设备
├─ 一次设备
│  ├─ 变压器
│  ├─ 断路器/隔离开关
│  └─ 其他一次设备
├─ 二次设备
│  ├─ 保护测控
│  ├─ 通信/调度
│  └─ 柜体及屏柜
├─ 建筑与结构构件
├─ 暖通、给排水与消防
├─ 未分类设备（类型未提供）
└─ 选择集（用户临时保存）
```

分类规则按“对象角色 + 业务名称别名 + FAM/IFC 辅助字段”计算。`DEV TYPE=OTHERS` 不作为用户可见分类；无法可靠归类时显示“类型未提供”，并在来源页保留原始值。

### 3.4 变电原始层级到业务树的映射

| 原始节点/字段 | 业务节点 | 默认显示位置 | 规则 |
| --- | --- | --- | --- |
| F1System、GIM 头部 | `project` | 每个工作区根 | 使用工程名称；工程类型由 GIMPKGS 映射，不显示 F1System |
| F2System、`SYSCLASSIFYNAME` | `discipline-facet` / `sourceRef` | 过滤 chip、对象徽标、来源页 | U/A/S/G 归一化为确认专业；未知 F2 不生成首层，只保留来源证据 |
| F3System、SYSTEMNAME1..4 | `system-domain` + `system` | 功能系统域下 | 第一个有效 SYSTEMNAME 生成域；去掉空值、纯数字、`-/$/NULL/其它/其他/&其他`；重复系统名用子对象/模型证据消歧 |
| F4System + IFCFILE/IFCGUID | `component-group` / `component` | 系统下“构件”组 | 不能因 IFCFILE 跨专业而移动专业；同 IFCFILE+IFCGUID 可去重显示并保留多重关系 |
| F4System + OBJECTMODELPOINTER | `asset` | 系统下“设备”组 | 优先 DEV `SYMBOLNAME`；`DEV TYPE` 为次级字段 |
| PARTINDEX + DEV SUBDEVICE | `subdevice` | 设备或部件下 | 按父 DEV + 子索引/路径合并成一个节点；显示“部件”，来源徽标同时列出 PARTINDEX、DEV_SUBDEVICE |
| DEV_SUBDEVICE 的递归子设备 | 嵌套 `subdevice` | 上一部件下 | 可展示、可点击定位；不作为全量几何 seed，不重复加载几何 |
| LOGICALMODEL 空壳 | 不进入主树 | 来源/质量页 | 无几何且无业务子项时隐藏；有可追踪子项时挂到“未关联对象”并标记占位 |
| PHM、MOD、STL、`.gl`、变换矩阵 | `sourceRef`、几何状态 | 检查器“来源” | 不创造新的业务层级；`.gl` 是否可视化由样本能力决定 |

#### 名称生成优先级

1. 工程根：GIM 头部工程名。
2. 功能系统域：取 F3 `SYSTEMNAME1..4` 的第一个有效业务名称并做同义归一化；其次使用可验证的 `SYSCLASSIFYNAME` 前缀并标记“推断”；无可靠证据时进入唯一的“未归类系统”。
3. 系统：SYSTEMNAME1..4 去占位符后的完整有效路径；为空时使用“未命名系统 01”，原始 SYSCLASSIFYNAME 仅作辅助。
4. 设备/部件：DEV 或 SUBDEVICE 的 `SYMBOLNAME`；其次是非占位的 IFC Name；最后生成“设备/部件 n”。
5. 重名：先追加“含××、××等”的子对象或模型证据；仍重名才追加稳定序号，不使用随机 UUID 截断作为业务名。

### 3.5 变电默认展开和排序

- 空间视角展开工程根和“IFC 空间模型”组，各来源模型、关联状态和模型资源默认折叠。
- 功能视角展开工程根，只生成 2–5 个功能系统域行且默认折叠；展开一个域后才生成其 F3 系统行。
- 系统下同时存在设备和构件时，先显示两个角色组，再按需进入实例；只有一种角色时可省略中间组。
- 功能域优先使用源序，归一化同序时为“电气 → 建筑物/构筑物 → 暖通 → 给排水 → 其他有效域 → 未归类系统”；系统顺序优先使用源序号，其次使用规范化名称；设备/构件名称按本地化排序。
- `PARTINDEX`/`DEV_SUBDEVICE` 节点只有在用户展开设备或搜索命中时生成，避免把数千部件一次性画入左树。
- 选择对象时，当前视角面包屑显示“工程 / 空间路径 / 对象”或“工程 / 功能系统域 / 系统 / 对象”；专业显示为徽标，来源页显示原始 F2/F3/F4 路径。

### 3.6 变电能力和异常退化

| 情况 | 左树行为 | 视口/检查器行为 |
| --- | --- | --- |
| 没有 IFC 空间实体或包含关系 | 不注册空间主树，默认使用功能系统并显示缺失原因 | 不创建假区域 |
| 有 IFC 空间树但 CBM 关联覆盖率低 | 保留空间主树；资产按“关联设备/坐标定位对象/未关联”分组 | 检查器显示证据和覆盖率，不把推断当确认 |
| 有空间实体但没有楼层/空间名称 | 以“未命名建筑/未命名楼层”保留层级，并显示来源模型 | 不使用文件名臆造业务区域 |
| 没有 IFC | 保留设备、MOD/STL 和属性；构件组不显示空入口 | 来源页说明 IFC 未提供 |
| 没有 MOD/STL | 设备仍在树和属性中，几何徽标为“无几何” | 不因无几何清除选择 |
| 没有 SCH/STD/SLD | 隐藏图纸工作区 | 工程资源摘要说明未提供 |
| F3/F4 引用断链 | 原节点保留并加“引用异常” | 可打开来源链和导出质量问题 |
| 几何仍在后台编译 | 眼睛为空心、显示已处理/总数 | 已加载对象仍可旋转、选择和定位 |

### 3.7 空间能力口径（必须拆分）

`hasReliableSpatialHierarchy` 只回答“IFC 空间主树能否建立”，不回答“CBM 资产是否都已关联”。实现和诊断至少分别记录：

| 能力 | 判定 | 用途 |
| --- | --- | --- |
| `hasSpatialEntities` | 至少存在 Project/Site/Building/Storey 中两级 | 显示空间容器摘要 |
| `hasSpatialContainment` | 存在 `IFCRELCONTAINEDINSPATIALSTRUCTURE` 且覆盖对象数大于 0 | 注册 IFC 空间主树 |
| `hasSpaces` | 存在 `IFCSPACE` | 楼层下增加空间/区域层 |
| `hasDirectCbmIfcLinks` | 至少一个 F4 的 IFCFILE+IFCGUID 在同一 IFC 中命中 | 显示关联设备计数 |
| `hasPlacementCoordinates` | F4/DEV 或 IFC placement 有合法坐标 | 显示坐标定位对象 |
| `directContainedIfcObjects` | IFCREL*SPATIAL* 直接包含的构件数 | 显示原始包含证据 |
| `decompositionInheritedIfcObjects` / `hostInheritedIfcObjects` | 分别通过 IFC 对象分解关系、开洞/端口宿主关系继承到空间的构件数 | 显示“分解继承/宿主继承”徽标 |
| `boundaryContainedIfcObjects` | 通过 IFCRELSPACEBOUNDARY 关联到空间的构件数 | 显示“空间边界”徽标 |
| `inheritedContainedIfcObjects` | 分解关系 + 宿主关系继承总数；对象级 `spatialInheritanceKind` 再拆分两类 | 兼容旧调用方的总计 |
| `spatialObjectCount` | 直接 + 分解继承 + 宿主关系继承 + 空间边界的空间可达构件数 | 计算空间树构件总量 |
| `uncontainedIfcObjects` | IFC 产品/构件总数减去已有空间容器关系的构件数 | 显示未落入空间的 IFC 构件 |

覆盖率要分别计算 `directCbmIfcLinkCoverage`、`spatiallyContainedCbmCoverage` 和 `placementCoverage`。变电站02–04 即使直接 IFCGUID 覆盖率为 0，只要 IFC 空间实体和包含关系存在，仍应显示空间主树，同时把对象放入“坐标定位/未关联”质量分组；未落入空间的 IFC 产品不能只靠搜索发现，必须在空间树中有计数和分页入口。多个 IFC 来源必须先按模型分组，避免 `Default Project/Site` 形成不可辨认的重复首层。

## 4. 线路工程：组成关系和拓扑顺序优先

### 4.1 选择理由

线路对象的意义来自前后顺序、里程和空间关系。把线路按 CBM 文件夹、专业码或 DEV 类型分类，会破坏“从哪座塔到哪座塔”的阅读路径。因此主树只表达路线组成；资产分类、图层和质量必须是平行工作区。

### 4.2 路线工作区主树

```text
线路工程
└─ [线路名称/编号]
   ├─ 区段 01（起点—终点）
   │  ├─ 耐张段 01（N001—N012）
   │  │  ├─ N001 杆塔
   │  │  ├─ 档距 N001—N002
   │  │  │  ├─ 导线
   │  │  │  ├─ 地线
   │  │  │  ├─ OPGW
   │  │  │  └─ 跨越物 · 道路/河流/其他
   │  │  ├─ N002 杆塔 · ...
   │  │  └─ ...（按线路顺序交替显示塔位和档距）
   │  └─ 耐张段 02（...）
   └─ 未分段对象 / 待关联跨越物（仅在需要时出现）
```

“杆塔—档距—杆塔”的交替顺序是主树的核心；同一档距的多条导线、地线和 OPGW 作为档距子节点。跨越物有明确关联时挂在档距下，无法关联时保留在“待关联跨越物”并带质量徽标。塔型/坐标状态、长度、分裂数和来源路径通过 tooltip 与右侧属性面板查看，不占用导航标签宽度。

如果样本没有显式区段或耐张段：

- 只有在塔号/坐标/顺序足以推断时，才生成“区段 01（顺序推断）”或“耐张段 01（推断）”；
- 推断节点必须有“推断”徽标，并在来源页列出规则；
- 无法推断时使用“未分段对象”，不凭文件目录制造层级。

### 4.3 线路资产工作区

```text
资产
├─ 杆塔（n）
├─ 档距（n）
├─ 导线与地线（n）
│  ├─ CONDUCTOR
│  ├─ GROUNDWIRE
│  ├─ OPGW
│  └─ 线型未识别
├─ 金具与绝缘子（n）
├─ 跨越物（n）
└─ 未分类资产（n）
```

资产树适合批量筛选和 CSV，不改变路线树的顺序。类别名称由 `TOWER/WIRE/CROSS` 及 `WIRETYPE` 规范化生成；原始 ENTITYNAME 只在来源页出现。

### 4.4 线路原始层级到业务树的映射

| 原始节点/字段 | 业务节点 | 默认显示位置 | 规则 |
| --- | --- | --- | --- |
| F1/F2/F3/F4System | `project`、`route`、`section` 的来源关系 | 路线树的来源页 | 不把 F1–F4 直接渲染为用户层级；按可验证的拓扑关系投影 |
| TOWER | `tower` | 耐张段的有序序列 | 名称优先塔号，其次为稳定编号；坐标状态作为徽标 |
| WIRE | `span` 下的 `wire` | 档距子节点 | 由端点顺序生成档距标签；WIRETYPE 从 WIRE→DEV→FAM 解析 |
| CROSS | `crossing` | 所属档距下 | CODE 做业务类型辅助映射；未知值显示“其他跨越物”并保留原码 |
| DEV/FAM | 类型、参数和来源补充 | 检查器/资产表 | 不单独创建“DEV 文件”层 |
| MOD/STL/PHM | 几何状态和来源 | 检查器“来源” | 不改变路线顺序；共享几何引用只计一次业务对象 |

### 4.5 线路默认展开、排序和数据语义

- 工程根、线路和区段可见；耐张段默认折叠，避免一次展开数千塔位/档距。
- 路线顺序以起点、终点和里程为主；无法计算里程时保持源序并标记“顺序来自源文件”。
- 搜索塔号、设备名、跨越物或坐标时，自动展开到目标，并在地图聚焦；定位失败仍保留检查器属性。
- `KVALUE`、跳线候选、分裂数和端点是档距/导线的属性或过滤条件，不增加虚构的树层级。
- 坐标缺失、FAM/DEV 未命中、断链和底图回退分别计入质量工作区；底图状态不能覆盖线路叠加层状态。

### 4.6 线路能力和异常退化

| 情况 | 左树行为 | 地图/检查器行为 |
| --- | --- | --- |
| 无坐标 | 塔位/跨越物保留，徽标为“无法定位” | 地图不聚焦，但属性可查看和导出 |
| 无法建立跨越物关系 | 放入“待关联跨越物” | 允许按原始坐标或来源定位 |
| WIRETYPE 未解析 | 放入“线型未识别” | 显示原始 WIRE/DEV/FAM 链 |
| 在线底图不可用 | 路线、资产、质量树不变 | 保留 Canvas/线路叠加层，单独提示底图回退 |
| 纵断面/线路三维尚未实现 | 不注册禁用按钮 | 帮助文档预告，不在生产导航中放空入口 |

## 5. 通用视角、来源和质量模型

### 5.1 业务节点与来源节点分离

每个业务节点都可携带一个或多个来源引用，但来源引用不是子树：

```text
业务对象
├─ 概览（名称、类型、位置、状态）
├─ 参数（FAM/DEV/IFC/几何）
├─ 关系（父子、相邻、图纸、模型）
└─ 来源（CBM/DEV/FAM/PHM/MOD/STL/IFC、GUID、原始键、矩阵）
```

这样既保留审计能力，也避免用户在默认树中看到“CBM → DEV → PHM → MOD”造成的文件夹式迷路。

### 5.2 计数口径

- `objectCount`：去重后的业务对象数，不是文件引用次数。
- `directCount`：当前节点的直接业务子项数。
- `geometryReady/geometryTotal`：可识别几何入口中已完成/可处理的数量；不把 PARTINDEX 额外计为几何入口。
- `sourceCount`：来源组或原始引用数量，单独显示，不能与业务对象数混用。
- 共享 MOD/STL/IFC 资源只计一次几何对象，但关系页显示所有引用方。

### 5.3 数据质量状态

| 状态 | 判定 | 树上文案 |
| --- | --- | --- |
| complete | 业务名称、关键关系和所需几何/坐标齐全 | 数据完整 |
| partial | 可浏览但部分 FAM/DEV/IFC/属性缺失 | 部分属性 |
| coords-only | 线路只有坐标，缺少资产属性 | 仅坐标 |
| no-geometry | 有业务对象但没有可显示几何 | 无可显示几何 |
| unresolved | 引用链或空间关系无法建立 | 引用异常/未关联 |
| inferred | 名称、分段或类型由规则推断 | 推断 |

质量状态可作为筛选条件；筛选不改变对象 ID，也不从模型中永久删除对象。

## 6. 实施优先级与验收

### M0：业务投影适配

1. 在 `gim/` 与 `ui/` 之间增加只读导航适配器，生成 `system-domain/system/asset/subdevice`、专业过滤面或 `route/section/strain-section/tower/span/crossing` 节点。
2. 复用现有解析结果、3D、地图、搜索、属性和导出能力，不在 UI 组件中复制解析逻辑。
3. 实现 F3 功能域归一化、F2 专业过滤面、F4 角色分组、PARTINDEX/DEV_SUBDEVICE 合并、能力驱动入口显隐。
4. 先保证树、视口、检查器和表格共享稳定 `selectionId`。

### M1：规模和质量

- 虚拟滚动、惰性子树、质量工作区、资产筛选和项目级展开状态；
- 可靠空间字段索引（若样本提供），否则明确降级；
- 失败引用和无几何对象可重试、可导出。

### M2：跨视图协同

- 变电 3D—单线图分屏；
- 线路纵断面和三维线路；
- 质量问题批注、比较和变更追踪。

### 6.1 必须通过的真实样本验收

**变电：**

- 默认树不出现 `F1System/F2System/F3System/F4System/PARTINDEX`、`&其他` 或单独的 `DEV_SUBDEVICE` 作为业务名称；这些值仍可在来源页查到。
- 功能视角以 F3 的第一个有效 SYSTEMNAME 生成 2–5 个功能系统域；F2 专业只显示为徽标和过滤项，不固定占据第一层。
- 未知 F2 不按原始码拆成多个“未分类”首层行：有 F3 语义证据时显示功能域；无证据的对象全部进入一个“未归类系统”行，原始码以来源 chip 展示。
- 对真实样本，变电站02 首层必须为“电气系统（推断）+ 未归类系统”两行，变电站03 必须为“电气系统（推断）+ 建筑物系统（推断）+ 未归类系统”三行，变电站04必须为“交流电气系统 + 未归类系统”两行；不得出现两个同名“未分类”首层行。
- F4 的 IFC 构件和 DEV 设备在树中分开；跨专业 IFCFILE 不会把对象移动到错误专业。
- PARTINDEX 与 DEV_SUBDEVICE 不重复；点击部件可定位到正确父设备和局部变换，且全量几何不会重复加载。
- 没有可靠空间字段时不出现伪造的“场地/生产区”；空间与功能通过同级切换器进入，不把功能视图塞进空间树；没有 SLD 时不显示空图纸入口。

**线路：**

- 路线树按区段/耐张段/塔位/档距顺序组织；一个样本的 129 个塔位、2,232 个导线段和 44 个跨越物可被筛选和定位，但不以 9,276 个原始 CBM 行铺满左树。
- 同一档距的导线、地线、OPGW 和跨越物关系可追溯；WIRETYPE 未解析时不会被默认为普通导线。
- 坐标缺失、未关联跨越物和底图失败均为非阻断降级；路线树和属性仍可用。

**共同：**

- 搜索命中自动展开祖先链，树/视口/检查器/资产表选择一致。
- 计数区分业务对象数、几何数和来源引用数；切换工作区不复制或篡改对象。
- 在 1600×900、1366×768、1024×768 下无横向滚动；大树滚动和展开不阻塞 3D/地图交互。
