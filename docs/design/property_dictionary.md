# 属性字典与右侧检查器规范

> 目标：让 GIM 的右侧面板首先回答“这是什么、处于哪里、与什么关联、来自哪里”，而不是把 GUID、路径和导出器内部键直接堆给用户。本文与 `desktop/src/ui/propertyDictionary.ts` 保持同步；未知字段保留原值，但不臆造中文含义。

## 1. 展示契约

### 1.1 四个页签

| 页签 | 用户问题 | 默认内容 | 展示策略 |
|---|---|---|---|
| 概览 | 这是什么？ | 工程身份、类型、名称、位置/数量、关键业务字段 | P0/P1 字段直接显示；字段名使用中文标签；单位由字典追加 |
| 参数 | 它有哪些工程参数？ | FAM、DEV、IFC Pset/工程量、线路 MOD 解析结果 | 按关联对象和属性组分节；空值隐藏；未确认字段进入技术字段折叠区；线路螺栓使用表格 |
| 关系 | 它连接了什么？ | 父子节点、空间容器、导线端点、CBM/IFC 关联 | 线路塔位按“杆塔/基础/导线/导线挂点”分组，只显示业务对象和计数，不铺文件链接 |
| 来源 | 如何追溯原始数据？ | CBM、DEV、FAM、PHM、MOD、STL、IFC、SLD | 所有文件入口统一收敛到本页；正文不显示 GUID 文件名或完整路径；使用“定位/查看/切换”按钮触发路由 |

### 1.2 优先级

| 优先级 | 含义 | UI 行为 | 例子 |
|---|---|---|---|
| P0 | 直接影响识别、定位或工程判断 | 概览/参数默认可见 | 名称、类型、坐标、导线类型、档距、导线型号 |
| P1 | 有助于核查和追溯，但不是第一眼决策 | 普通分节可见或关系页显示 | 系统分类、计数、FAM/DEV 业务参数、空间关联状态 |
| P2 | 导出器/解析器技术细节，阅读成本高 | 默认折叠为“技术字段” | 矩阵、ExpressId、稳定键、未确认键、原始数组 |

未知键的默认优先级为 P2，值仍保留；字典中没有的含义统一标注“来源文件属性；具体工程含义待规范确认”，不得根据键名猜测业务语义。带序号的引用键（如 `BASEFAMILY1`、`SOLIDMODEL0`、`STRING2.STRING`）按字段族归一到基础定义；文件引用不在参数/关系页重复出现，统一收敛到来源区域。

### 1.3 值与单位

- 数字只在字典确认单位时追加单位；不确定单位的数字保持原值。
- 坐标按来源语义显示：线路 `BLHA` 使用“纬度、经度、高程、方位角”；IFC placement 保留模型原始单位并显示单位提示。
- 矩阵使用等宽字体并放入技术字段；列主序 4×4 的平移分量说明写入字段提示，而不是把 16 个数字放进概览。
- `A=0` 的 PHM/XML 颜色按样本确认的不透明哨兵处理；文件级 `max(A)>100` 时按字节制 `/255`，否则按百分制 `/100`。

## 4. 文件引用与路由

### 4.1 可读按钮

属性值使用以下可读按钮，而不是显示 GUID 文件名：

| 引用类型 | 默认按钮文案 | 点击结果 |
|---|---|---|
| CBM | 定位 CBM | 展开/选中对应业务节点 |
| DEV | 查看 DEV | 定位引用该 DEV 的节点 |
| FAM | 查看属性族 | 定位引用该 FAM 的节点 |
| PHM | 查看 PHM | 定位装配引用节点 |
| MOD | 查看 MOD | 定位线路来源节点或显示 MOD 解析结果 |
| STL | 查看 STL | 定位 STL 来源节点 |
| IFC | 切换 IFC 模型 | 选中/加载对应 IFC |
| SLD | 打开电气图纸 | 打开白名单净化后的 SLD 视图 |

完整路径只保存在按钮的事件数据中，由工程路由匹配；正文、按钮可见文本和标题不输出路径。找不到可见业务节点时，状态栏提示“该来源文件未映射到可见……节点”，不将其当作解析失败。

线路来源较多时按 CBM/DEV/FAM/PHM/MOD/STL/WIRE/IFC 类型折叠显示；每类首批最多预览 120 条，超出部分显示数量提示并引导用户下钻到更具体的业务对象，避免工程根节点一次性生成数千行链接。

### 4.2 失败与安全边界

- 来源文件缺失：显示“源文件不在当前工程缓存中”，保留“查看来源”按钮。
- 未知 MOD 键集合：显示原键值和警告“未纳入属性字典”，不推断含义。
- IFC GUID、ExpressId、稳定键：仅在来源/技术区域出现，避免污染概览。
- CSV 导出遍历普通分节和折叠技术分节；引用按钮导出可读文案，不导出隐藏路径。
