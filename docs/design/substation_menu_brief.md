# 变电工程菜单设计简报

> 适用工程：GIMPKGS  
> 主要视图：3D 模型、主接线图、资产表  
> 核心目标：让用户沿“空间位置”或“功能系统”理解同一模型，再用专业/类别筛选，而不是浏览压缩包文件

> **V3 信息模型基准**：本简报的树状层级、计数口径和缺失数据退化以[左侧导航信息架构 V3](./navigation_information_architecture.md)和[变电导航选型分析](./substation_navigation_strategy_analysis.md)为准；本文件补充页面编排和交互细节。

## 1. 用户任务

1. 快速理解全站组成、专业分布和模型完整度。
2. 从空间或功能系统定位到具体设备，并在 3D 中聚焦。
3. 从 3D 构件回查 GIM 设备、设计参数、IFC 属性和来源文件。
4. 控制专业、系统、模型文件或设备类型的可见性。
5. 在存在 SCH/STD/SLD 时浏览主接线图并与设备关系对照。
6. 观察后台几何加载状态，识别无法渲染或引用断链的对象。

## 2. 业务对象模型

变电左树采用“空间—功能双轴联合导航 + 专业/类别双面筛选”：

~~~text
工程
├─ 模型：空间结构 / 功能系统（同级可切换）
│  ├─ 空间：来源模型 → Site → Building → Storey → Space → 构件/关联对象
│  └─ 功能：功能系统域 → 系统/间隔 → 构件或设备 → 部件
├─ 设备：分类 → 类型 → 实例（资产投影，不复制对象）
├─ 图纸：SCH / STD / SLD（仅能力存在时）
└─ 来源：CBM、DEV/FAM、PHM、MOD/STL、IFC（检查器页签）
~~~

F1/F2/F3/F4、PARTINDEX、UUID 等是来源层概念，不作为默认菜单名称。单样本曾出现 F2=14、F3=145、F4=4,645、PARTINDEX=3,894，且约 93.9% 的 F4 是 IFC 构件入口；因此 F3 要按功能域聚合、F2 专业退为过滤面、F4 要区分“构件/设备”角色，PARTINDEX 只作为部件语义节点，不作为额外几何入口。

## 3. 顶部项目栏

从左到右：

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 产品身份 | GIM BIM 浏览器 | 点击回到项目起始页 |
| 项目选择器 | 变电站01 + 下拉箭头 | 最近项目、打开 GIM、关闭工程 |
| 工程类型 | 变电工程徽标 | 只读，避免误判当前模式 |
| 当前视图 | 3D / 单线图 / 分屏 | 按能力显示 |

打开 IFC 放入“打开”菜单中的“附加 IFC”，不再与打开 GIM 并列成同等主按钮。

## 4. 左侧工作区导航

### 4.1 模型

默认工作区。顶部提供“空间结构 / 功能系统”同级分段切换器；只要 IFC 空间实体和包含关系存在，就把空间结构设为默认。资产是否能通过 IFCGUID 直接挂到楼层是独立的覆盖率指标，不再因为关联不完整而整体隐藏空间视图。功能系统不另占工作区入口，也不能作为空间树的最后一个子节点。

#### 空间结构

空间树只使用样本明确提供的空间关系，不能用专业名称猜测区域。四个样本均已观察到 Site/Building/BuildingStorey 和 `IFCREL*SPATIAL*` 关系；变电站04还提供 `IFCSPACE`。因此“空间树可用”与“设备关联完整”必须分开显示：

~~~text
变电工程
├─ IFC 模型 · n
│  ├─ [来源模型] · IFC 构件 n · 属性 n
│  │  └─ 站区 / 建筑 / 楼层（按 IFC 原始关系）
│  │     ├─ [实际建筑或构筑物] · IFC 构件 n · CBM 关联 n
│  │     │  ├─ [实际楼层/标高] · IFC 构件 n · CBM 关联 n
│  │     │  │  ├─ [实际空间/区域]（有 IFCSPACE 时）
│  │     │  │  ├─ IFC 构件（直接 + 分解继承）
│  │     │  │  └─ 关联设备
│  │     │  └─ 未命名楼层 / 无空间名称
│  │     └─ 无楼层的 IFC 构件
├─ 关联状态（折叠）
│  ├─ 坐标定位对象（位置推断）
│  ├─ 已关联 IFC · 无空间容器
│  ├─ 未关联 IFC 对象
│  └─ 未落入空间的 IFC 构件
└─ 模型资源（属性集 / 几何拓扑 / 关系统计，折叠）
~~~

空间行至少显示 `IFC 构件 / 直接包含 / 分解继承 / 宿主继承 / CBM 关联 / 位置推断` 六类计数。关联异常收拢到一个“关联状态”首层组：其中“已关联 IFC · 无空间容器”承接 GUID 已命中但未落入 IFC 空间的对象，未落入空间的 IFC 产品也保留独立子项。`IFCFILE+IFCGUID` 命中并能沿 `IFCRELCONTAINEDINSPATIALSTRUCTURE` 到达楼层/空间时标记“已确认”；沿对象分解关系或开洞/端口宿主关系继承时分别标记“分解继承/宿主继承”；只有 CBM/DEV 变换矩阵时标记“位置推断”；没有证据时进入“未关联 IFC 对象”。不得显示“场地、生产区、主变区”等推测层级。

只有在没有 IFC 空间实体或没有任何空间包含关系时，才将空间视角降级为“空间关系未提供”，默认切到功能系统；此时仍保留“对象坐标/未关联”质量统计。

空间树的建筑/楼层/空间行只显示名称和紧凑的对象数徽标；`IFC 构件 / 直接包含 / 分解继承 / 宿主继承 / CBM 关联 / 位置推断` 六类完整计数放在行 tooltip 与右侧检查器，避免长技术串遮挡空间名称。质量分组仍显示 `位置推断 / 未关联`，超过首批行数的对象使用“加载更多”分页：

- `IFC 构件`：空间树可达的 IFC 实体（直接包含 + 分解关系继承）；
- `直接` / `分解继承`：分别对应 IFCREL*SPATIAL* 与 IFCRELAGGREGATES/DECOMPOSES/NESTS 证据；
- `宿主继承`：开洞/端口等对象沿 `IFCRELVOIDSELEMENT` / `IFCRELCONNECTSPORTTOELEMENT` 继承宿主空间；
- `CBM 关联`：`IFCFILE+IFCGUID` 精确命中并能到达该空间容器的 CBM 对象；
- `位置推断`：只有 CBM/DEV/PHM 变换矩阵的对象；
- `未关联`：GUID 未命中、没有空间容器或没有有效矩阵的对象。
- `未落入空间的 IFC 构件`：可识别的 IFC 产品没有空间包含关系，仍可搜索并打开基础属性；
- `模型资源`：属性值、几何拓扑和关系记录只按模型/类型统计，不计入业务构件数。

右侧检查器的“空间关系”卡片必须同时显示空间路径、楼层标高、关联证据（IFC 包含 / IFCGUID / CBM 变换）、置信度和未关联原因。功能系统仍显示同一个对象，切换视角不能复制几何实例。

#### 功能系统

~~~text
变电工程
├─ 交流电气系统 · 系统数 · 专业 A
│  ├─ 跨电压等级系统 / 调度数据网（折叠）
│  │  ├─ 设备（DEV n）
│  │  └─ 构件（IFC n）
│  └─ 防雷接地系统 / 接地系统 · ...
├─ 建筑物 · 系统数 · 专业 U
├─ 构筑物 · 系统数 · 专业 U
├─ 空调系统 · 系统数 · 专业 S
├─ 排水系统 · 系统数 · 专业 G
└─ 未归类系统（全树最多一个）
~~~

首层按 F3 的第一个有效 `SYSTEMNAME1..4` 形成 2–5 个功能系统域；F2 的 U/A/S/G 显示为专业徽标和过滤 chip。F3 名称过滤空值、纯数字、`-/$/NULL/其它/其他/&其他`，重名时使用子对象或 IFC 证据消歧。树行只显示可读业务名称和短对象数徽标；实体类型、IFC/DEV 路径、来源码、几何进度和质量状态放入 tooltip/右侧检查器。单击选择，双击在 3D 中定位，右键提供隔离/隐藏/显示同类/来源。

#### 功能域清洗和专业降级

真实工程中 F2 的 `SYSCLASSIFYNAME` 可能是 `1/2/3/4/Y/导线布置/02` 等导出工具码，不能把每个原始码直接命名为“未分类专业”。首层按以下顺序生成：

1. 读取 F3 `SYSTEMNAME1..4` 的第一个有效业务名称，做同义归一化后形成域。
2. 名称无效时才读取可验证的 `SYSCLASSIFYNAME` 前缀；由前缀得到的域显示“推断”徽标。
3. F3 没有可靠语义的剩余对象统一进入一个“未归类系统”行；原始 F2/F3 值显示为来源 chips。
4. `U/A/S/G` 只形成专业徽标和筛选项；未知 F2 不生成“未分类专业”。
5. 若工程完全没有 F3 语义，使用“系统总览”作为可用性兜底。

样本投影示例：

```text
变电站02
├─ 电气系统（推断） · 49 个系统 · 3,242 个 F4 · 来源码 1/2/3/4/Y
└─ 未归类系统 · 2 个系统 · 84 个 F4 · 来源码 02/导线布置

变电站03
├─ 电气系统（推断） · 29 个系统 · 160 个 F4 · 来源码 1/Y
├─ 建筑物系统（推断） · 2 个系统 · 0 个 F4 · 来源码 Y
└─ 未归类系统 · 1 个系统 · 2 个 F4 · 来源码 Y

变电站04
├─ 交流电气系统 · 12 个系统 · 511 个 F4 · 专业 A
└─ 未归类系统 · 2 个系统 · 21 个 F4 · 专业 A
```

这里的“推断”只改变左树的业务投影，不改写 CBM 原始 F2/F3 归属；来源页仍须展示完整原始路径。

### 4.2 功能系统视角

这是“模型”工作区中的第二个视角，不重复设置工作区入口。用于从功能系统而非空间查看设备和构件。F4 的 IFC 入口和 DEV 入口必须分组；不能把所有 F4 都叫作设备，也不能按 IFC 文件名重新归类专业。

| 可选快捷过滤 | 示例 |
| --- | --- |
| 电气一次 | 主变压器、母线、断路器、隔离开关、互感器、避雷器 |
| 电气二次 | 保护测控、调度数据网、通信、电源 |
| 建筑结构 | 建筑、基础、结构、围护 |
| 机电系统 | 暖通、给排水、消防、动力照明 |

系统节点显示所属专业、设备数、已加载几何数和告警数。系统选择应在 3D 中形成临时选择集，而不是修改模型永久分类。

设备入口的名称优先取 DEV `SYMBOLNAME`，构件入口优先取非占位 IFC Name；`PARTINDEX` 与同索引 DEV SUBDEVICE 合并成一个“部件”行。部件可点击定位，但不作为全量几何 seed，避免重复加载和错误矩阵链。

### 4.3 设备

设备工作区代替当前“文件设备”与部分“模型”页签。

顶部视图：

- **分类树**：类别 → 类型 → 实例。
- **资产表**：名称、分类、系统、模型状态、参数状态、来源。
- **选择集**：用户临时保存的对象集合。

资产表支持排序、筛选、列显示和 CSV 导出。选择表格行必须同步 3D 和右侧检查器。

分类由对象角色、业务名称别名和 FAM/IFC 辅助字段计算。`DEV TYPE=OTHERS` 不直接显示为分类；无法归类时使用“类型未提供”，原始值仅在来源页显示。

### 4.4 图纸

仅当工程实际存在 SCH/STD/SLD 时显示。

内容：

- 主接线图；
- 逻辑拓扑列表；
- 电压等级和间隔筛选；
- 图元选择与右侧属性；
- “在 3D 中查找”动作。

选择“图纸”工作区后，主接线图以主视口叠加层显示在三维模型之上；三维场景、模型索引和当前相机保持不变。叠加层可关闭，切回模型/设备工作区时自动隐藏；拓扑列表仍在左侧图纸面板中使用。

当前样本并非都包含电气图资源，因此工作区必须能力驱动显隐。不存在时，不显示空页签；在工程概览的资源清单中说明“未提供主接线图”。

SCH/STD/SLD 的版本和文件关系可能随导出工具变化；页面只承诺“可用图纸资源”，不在导航中暴露固定的三件套假设。

## 5. 导航器头部

模型、系统和设备工作区共享：

1. 工作区标题；
2. 搜索框；
3. 过滤按钮；
4. 树/表切换；
5. 结果数量；
6. 当前过滤条件 chips。

搜索范围默认包含业务名称、设备编号、分类、系统名、IFC GUID 和 CBM/DEV 文件名。技术标识可搜索，但结果标题仍显示业务名称。

## 7. 右侧对象检查器

### 7.1 头部

- 对象图标；
- 业务名称；
- 对象类型徽标；
- 数据质量状态；
- 聚焦、隔离、更多操作。

### 7.2 页签

#### 概览

优先显示用户最关心的字段：类型、系统、位置、标高、型号、额定容量、额定电压、安装状态。

#### 参数

按来源分组但保持业务命名：

- 设计参数；
- 设备参数；
- IFC 属性集；
- 几何参数。

#### 关系

展示：

- 上级系统；
- 子设备；
- 关联 IFC 构件；
- 所属模型文件；
- 相关单线图节点。

关系以可点击卡片显示，点击即切换选择，不展示长 UUID 列表。

#### 来源

显示 CBM、DEV、FAM、PHM、MOD/STL、IFC 路径，原始键值和变换矩阵。提供复制标识与打开诊断摘要，默认折叠。

## 8. 模型与图层管理

“模型”不再是独立的文件列表页签，而是视口中的图层管理器：

| 层级 | 例子 | 操作 |
| --- | --- | --- |
| 专业 | 建筑、安装、暖通、给排水 | 显示/隐藏、透明度 |
| 模型 | 电气一次 IFC、结构 IFC | 显示/隐藏、聚焦 |
| 几何来源 | IFC、MOD、STL | 显示/隐藏、状态 |
| 临时选择集 | 当前隔离、搜索结果 | 清除、保存 |

模型加载中使用空心眼睛与进度；失败使用告警图标并允许按对象重试。

## 9. 加载与异常状态

### 工程打开

1. 顶栏显示工程身份和“正在建立索引”。
2. 导航树首先可用。
3. IFC 优先进入 3D。
4. DEV 几何在后台逐步显示。
5. 状态栏展示“正在构建几何 173 / 285”，不使用遮挡模型的大 Toast。

### 数据差异

- 无 IFC：继续显示 MOD/STL 能力，不出现“尚未加载 IFC”误导。
- 无 SLD：隐藏图纸工作区。
- 空几何：对象仍可选择和查看属性，标记“无可显示几何”。
- 断链：在树行和来源页显示告警，保留其他可用内容。

## 11. M0 验收标准

- 打开任一变电样本后，用户无需理解扩展名即可定位到设备。
- 选择树节点、3D 构件、资产表行时，三处选中对象一致。
- 右侧检查器能区分业务属性与技术来源。
- IFC、SLD 等能力按样本实际显隐。
- F4 的 IFC 构件与 DEV 设备分组显示；`PARTINDEX`/`DEV_SUBDEVICE` 不重复且不产生额外几何 seed。
- 功能视角首层来自 F3 有效业务名称；F2 专业只作为徽标/筛选；F3 占位符被过滤，重名系统可由子对象或模型证据区分。
- 有 IFC 空间实体但 CBM 关联缺失时，空间主树仍可用；缺失对象进入“坐标定位对象/未关联 IFC 对象”，并在检查器中展示原因和来源。
- IFC GUID 命中但没有空间容器的对象进入独立质量分组；空间容器、未直接关联的 IFC 构件均可点击查看基础属性。
- IFC 产品没有空间容器时进入“未落入空间的 IFC 构件”，并保留模型、类型、ExpressId、GUID（若有）和 CBM 多重关联。
- IFC 装配体子构件沿分解关系进入父空间，行和检查器显示“分解继承”，不冒充直接空间包含。
- 多 IFC 文件的 `Default Project/Site` 不再重复占据首层；首层显示稳定的“IFC 模型”来源分组，搜索命中会自动展开模型和空间祖先。
- IFC 构件检查器显示 PropertySet/ElementQuantity、材质、分类、类型、关系类型、Representation 状态和原生坐标；低层 STEP 资源仅按模型/类型统计。
- 所有当前已有功能可在新菜单找到，不保留孤立的“文件设备”页签。
- 1600 × 900 下主视口宽度不低于 850 px，左右面板可调整。
