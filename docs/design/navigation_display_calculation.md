> 状态：基于真实样本的展示量测算；空间主树、IFC 详情、分解/宿主关系继承和多模型分组已接入运行时
> 日期：2026-08-29

> 关联规范：[左侧导航信息架构 V3](./navigation_information_architecture.md)、[变电导航选型分析](./substation_navigation_strategy_analysis.md)

> **实现边界**：本文同时记录真实样本测算口径与运行时实现。变电空间视图与功能系统域视图均已接入；功能视图使用原始 CBM path 的平行投影，不复制对象或几何。

本报告把样本中的原始 CBM/DEV/PHM/MOD/IFC 关系投影为用户可见的业务树，回答三个问题：

1. 首次打开左侧导航实际需要渲染多少行；
2. 展开一个高密度节点后是否需要惰性生成和虚拟滚动；
3. 哪些原始数量必须合并为业务数量，哪些异常必须以徽标保留而不能删除对象。

样本名已匿名化为“变电站01–04、线路01–06”。报告中的 `demo-substation`、`line02` 等仅出现在证据链接和复核命令中。

## 1. 计算口径

### 1.1 投影层级

变电同时提供“空间 → 建筑/构筑物 → 楼层/空间 → IFC 构件/关联设备”与“功能系统域 → 系统/间隔 → 构件/设备 → 部件”两个投影；专业是筛选面，类别是资产查询投影。线路采用“区段 → 耐张段 → 塔位/档距 → 导线/跨越物”投影。原始实体名（F1System、F2System、F3System、F4System、PARTINDEX、Tower_Device、Wire_Device、CROSS）只作为来源或质量证据，不直接成为默认菜单名称。

### 1.2 行数定义

| 符号 | 含义 |
| --- | --- |
| `sourceRows` | 可达的原始结构行；变电另列 DEV_SUBDEVICE 虚拟行，避免把它误计成 CBM 源行 |
| `businessRows` | 去重后的业务节点行；共享来源不重复计数 |
| `S1/S2/S3` | 旧“专业行默认展开”评估口径；保留用于对比，不再作为目标默认态 |
| `FN0` | 功能系统首屏：工程根 + 清洗后的功能系统域行；域默认折叠 |
| `FN1` | 展开一个最大功能域后的行数：`FN0 + 该域 F3 系统数` |
| `FN2` | 所有功能域展开到 F3：`FN0 + F3 数`；F4 仍折叠 |
| `FN3` | 所有功能域展开到 F4：`FN2 + F4 数`；部件仍按需生成 |
| `SP0` | 空间首屏：工程根 + IFC 空间模型组 + 来源模型行 + 折叠的关联状态组 + 折叠的模型资源组；空间容器和实例按展开生成 |
| `SP1` | 变电展开一个楼层/空间：`SP0 + 该容器的 IFC 构件和关联设备业务行`；子构件仍按需生成 |
| `SP2` | 变电所有空间容器展开到 IFC 构件/设备：`SP0 + 去重后的空间对象数`；未关联对象仍单列 |
| `directSpatialObjects` | IFCREL*SPATIAL* 直接包含的构件数；保留为原始关系证据 |
| `inheritedSpatialObjects` | 沿 IFCRELAGGREGATES/DECOMPOSES/NESTS 或 IFCRELVOIDSELEMENT/IFCRELCONNECTSPORTTOELEMENT 继承到父空间的构件数；分解与宿主关系分别计数 |
| `boundarySpatialObjects` | 通过 IFCRELSPACEBOUNDARY 关联到 IFCSPACE 的构件数；不冒充直接包含 |
| `spatialObjectCount` | `union(directSpatialObjects, inheritedSpatialObjects, boundarySpatialObjects)`；空间树实际可达构件数，重复关系不重复计数 |
| `L0` | 线路首屏只生成 F1 工程根和 F2 区段行 |
| `L1` | 线路建议默认：`L0 + F3 耐张段折叠行` |
| `L2` | 线路打开一个最大耐张段：`L1 + 该耐张段 F4 业务组数` |
| `L3` | 线路所有耐张段展开到塔位/档距/跨越物业务组：`L1 + F4 业务组数` |

线路的 F4 业务组数按 `GROUPTYPE=TOWER/WIRE/CROSS` 计数；不把塔身 `Tower_Device`、金具 `Wire_Device` 和 CROSS 叶节点再次铺到路线主树。它们进入对象检查器或资产工作区。

### 1.3 归一化和保守规则

- `ENTITYNAME` 按大小写不敏感规则归一化；例如 `F4SYSTEM`、`F4System` 均计为 F4System。
- 变电首层功能域读取 F3 `SYSTEMNAME1..4` 的第一个有效业务名称；空值、纯数字、`-/$/NULL/其它/其他/&其他` 无效，再以可验证的 `SYSCLASSIFYNAME` 前缀保守推断。F2 只有 U/A/S/G 能直接映射确认专业，但专业只作为徽标/过滤面；其他 F2 只作为来源 chip。
- 变电 F3 行数按实际 F3 节点计数；名称去占位符后再检查重名，不能因为重名而静默合并对象。
- `PARTINDEX` 和 `DEV_SUBDEVICE` 是部件语义的两个来源，不相加为几何实例；它们按父设备、子索引和来源路径合并。
- 线路跨越物的业务行数采用 F4 `GROUPTYPE=CROSS`；原始 `CROSS` 叶节点另列为来源/质量计数。
- 空间树的 `IFC 构件`、`CBM 关联`、`位置推断`、`未关联` 四类数量分开计算，且 IFC 构件再拆分直接、分解继承、宿主继承和空间边界证据；未落位 IFC 构件和属性/几何/关系资源另计，不把 IFC 实体数当成设备数，也不把同一对象在系统/空间两个视角的出现次数相加。

空间首屏 `SP0` 不应展开空间容器或数千个 IFC 构件，只生成来源模型和两个折叠摘要组：

```text
变电站01  [SP0 = 16 行]
├─ IFC 空间模型 · 12
│  ├─ 来源模型 01 · IFC 构件 n（折叠）
│  └─ …共 12 个来源模型
├─ 关联状态（折叠）
│  ├─ 坐标定位对象 / 无空间容器 / 未关联 / 未落位 IFC 构件
└─ 模型资源（折叠）
```

计算公式为 `SP0 = 工程根 1 + IFC 空间模型组 1 + 来源模型 N + 关联状态 1 + 模型资源 1 = N + 4`。四个样本的 `SP0` 分别为 **16 / 21 / 12 / 23** 行；若展开全部空间容器但不展开实例，则分别为 **74 / 66 / 36 / 95** 行。变电站02–04 的空间树必须照常出现，且首屏显式提示“IFC 空间已确认；CBM 资产未提供直接 IFCGUID”，避免用户误以为工程没有空间模型。

#### 2.5.1 IFC 记录去噪与未落位对象（实现快照）

以变电站01为例，原始 IFC STEP 记录不能直接等同于业务构件：

| 指标 | 数量 | 导航处理 |
| --- | ---: | --- |
| 可识别 IFC 产品/构件 | 4,714 | 进入空间容器或“未落入空间的 IFC 构件”分组 |
| IFC 直接包含的构件 | 3,111 | 按 Project/Site/Building/Storey/Space 展开，标记“直接” |
| 分解关系继承到空间的构件 | 74 | 同样进入空间树，行上标记“分解继承” |
| 宿主关系继承到空间的构件 | 1,529 | 开洞/端口沿 `IFCRELVOIDSELEMENT`、`IFCRELCONNECTSPORTTOELEMENT` 继承，标记“宿主继承” |
| 空间树可达的 IFC 构件 | 4,714 | `direct + decomposition + host-relation`，不重复计数 |
| 无空间容器的 IFC 构件 | 0 | 独立质量分组仍保留；本样本没有未落入空间的产品 |
| 属性值、几何拓扑、关系等低层资源 | 1,469,778 | 不生成伪构件行，按 IFC 模型/类型显示资源统计 |

这一步解决了两个相反的问题：`IFCPROPERTYSINGLEVALUE` 等低层记录不会污染构件计数；真实 IFC 产品即使没有空间父级，也不会再只靠搜索才能发现。开洞、端口等宿主关系不再被误报为未落位。数量是样本快照，运行时按实际 IFC 动态计算。

## 3. 变电可见行数计算

### 3.1 结果

| 匿名样本 | `sourceRows`（工程根 + F1–F4 + PARTINDEX） | `FN0` 默认 | 最大域 F3 | `FN1` | `FN2` 全域到 F3 | 最大 F4/F3 | `FN3` 全部到 F4 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 变电站01 | 8,700 | **6** | 131 | 137 | 151 | 972 | 4,796 |
| 变电站02 | 4,735 | **3** | 49 | 52 | 54 | 1,237 | 3,380 |
| 变电站03 | 422 | **4** | 29 | 33 | 36 | 36 | 198 |
| 变电站04 | 686 | **3** | 12 | 15 | 17 | 260 | 549 |

计算示例：

```text
变电站01 FN0 = 1 个工程根 + 5 个功能系统域 = 6
变电站01 FN1 = 6 + 最大功能域的 131 个 F3 = 137
变电站01 FN2 = 6 + 145 个 F3 = 151
变电站01 FN3 = 151 + 4,645 个 F4 = 4,796

变电站02 FN0 = 1 个工程根 + 2 个功能系统域 = 3
变电站02 FN1 = 3 + 最大功能域的 49 个 F3 = 52
变电站02 FN3 = 54 + 3,326 个 F4 = 3,380

变电站04 FN0 = 1 个工程根 + 2 个功能系统域 = 3
变电站04 FN1 = 3 + 最大功能域的 12 个 F3 = 15
```

默认功能首屏从旧口径的 150 / 54 / 36 / 16 行降到 6 / 3 / 4 / 3 行。展开一个功能域仍最多出现 137 行；继续展开某个 F3 时，变电站01、02 的最大 F4 分支会分别出现 972、1,237 个对象，变电站04也有 260 个，因此 F4 分支必须分页/窗口化。

### 3.2 直接 UI 结论

1. 默认只实例化 `FN0`；展开功能域后生成 F3，展开系统或搜索命中后才生成 F4 和部件。
2. F4 子项超过 100 个的系统使用分页/窗口化子树；变电站01、02 的最大系统必须启用虚拟滚动。
3. F3 名称的唯一率为 137/145、45/51、32/32、11/14；非唯一标签必须追加子对象或模型证据，不能用随机 UUID 截断充当名称。
4. 角色组只在同一系统同时存在 IFC 和 DEV 时插入；否则省略空组，避免额外行。
5. `PARTINDEX` 和 `DEV_SUBDEVICE` 永远只产生一个可见“部件”节点，不产生第二份几何 seed。
6. F2 只影响专业徽标和来源 chips；四样本功能域分别固定为 5 / 2 / 3 / 2 行，“未归类系统”每个工程最多出现 1 行。

### 3.3 空间视角的直接 UI 结论

1. `hasSpatialEntities && hasSpatialContainment` 为真时，`SP0` 作为模型工作区默认态；这只表示 IFC 空间容器可建立，不代表 CBM 资产关联完整。
2. `SP0` 只生成 IFC 来源模型行、折叠的“关联状态”和“模型资源”；来源模型展开后才生成空间容器。多个来源模型先挂在“IFC 空间模型”分组下，避免 `Default Project/Site` 重复占满首层。IFC 构件、未落位构件、设备和部件按展开或搜索惰性生成，超过首批行数用“加载更多”分页。
3. 空间容器行同时显示 `IFC 构件 n · 直接 n · 分解继承 n · 宿主继承 n · CBM 关联 n`，五个数不互相替代；GUID 命中但没有空间容器的对象在独立质量组计数。
4. 变电站01的 `3,244` 个 GUID 命中和 `2,253` 个楼层/空间关联必须可从空间树追溯；变电站02–04 的直接关联为 0，但不能因此隐藏已有 IFC 空间树。
5. 只有矩阵坐标的 F4 进入“坐标定位对象（位置推断）”；GUID 命中但没有空间容器的对象进入“已关联 IFC · 无空间容器”；没有矩阵或候选空间不唯一的对象进入“未关联 IFC 对象/未定位对象”；IFC 产品无空间关系时进入“未落入空间的 IFC 构件”。
6. 搜索结果同时提供空间路径和功能路径，但只在当前视角展开对应祖先链；用户显式选择“在另一视角查看”后才切换。两条链共享 `canonicalKey/selectionId`，不得创建第二份对象或几何实例。

## 9. 对 UI 实现的直接建议

### 9.1 默认展开和窗口化

| 规则 | 依据 | 实现要求 |
| --- | --- | --- |
| 功能域/区段聚合先显示 | 变电 `FN0=3–6`；线路 `L1=7–51` | 首屏同步渲染，不预读全部几何 |
| 子分支超过 100 项惰性生成 | 变电最大 F4=260–1,237；线路最大 F4=120–137 | 点击展开或搜索命中时生成子节点 |
| 可见行超过 1,000 启用虚拟滚动 | 变电站01/02 的 `S2`，以及变电站01/02/线路01/02/03/05 的全展开 | 树滚动不阻塞 3D/地图 |
| 部件/金具不进入路线主树 | `DEV_SUBDEVICE`、`Wire_Device` 数量远高于业务对象 | 放资产表和检查器，保留关系链接 |

### 9.2 计数徽标

树行只并列显示业务名称和必要的短计数/状态，避免把不同口径相加；完整技术数据放入 tooltip/右侧检查器：

```text
交流电气系统   131 个系统
系统 01         342 个对象
楼层 +0000      438 个对象
档距 N001—N002
```

建议字段（在 tooltip/检查器呈现，树行只选必要的短徽标）：

- `objectCount`：去重业务对象；
- `sourceCount`：F2/F3/文件来源组；
- `geometryReady/geometryTotal`：可识别几何的处理进度；
- `qualityCount`：无法定位、部分属性、引用异常等问题数。
- `spatialCount`：空间容器下的 IFC 构件、CBM 直接关联、位置推断和未关联对象四项计数；不得用一个总数替代。

### 9.3 选择和搜索

- 搜索结果只展开“工程根 → 功能系统域/区段 → 系统/耐张段 → 命中对象”的当前视角祖先链，不展开兄弟节点；另一投影以显式路径动作提供。
- 技术字段命中（GUID、文件名、原始码）时，行标题仍使用业务名称，来源页显示命中字段。
- `PARTINDEX`、`DEV_SUBDEVICE`、F4 IFC/DEV 入口和线路 F4 业务组必须共享稳定 `selectionId/canonicalKey`，切换“模型/设备/资产/质量”视图不复制对象。
