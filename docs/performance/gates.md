# 性能门禁

本页规定性能相关改动的开发门禁，适用于功能、正确性修正和性能优化。它接入现有审查、CI 与本地 Benchmark，不引入新的测量系统、运行时校验或远程工程矩阵。各方向的细则和现有测试从[索引](README.md)进入。

## 门禁层次

| 层次 | 要求 | 通过不代表什么 |
|---|---|---|
| 开发审查 | 说明改变了哪些真实计算、读取、等待和驻留；核对相关方向约束 | 不能凭合理推断宣称实测提速 |
| 轻量自动检查 | 复用现有分层、类型、lint、协议/计数/纯数据测试；仅补新变化或失败涉及的检查 | 不证明原生 I/O、完整真实工程或跨机器收益 |
| 开发者本地复核 | 同条件原生报告，正确性、测量完整性、耗时及内存代价分别评估 | PASS/PARTIAL、无回退或单点变快都不是自动批准 |

远程 CI 不运行真实或合成工程包、模型样本池及性能矩阵。小型值、协议、内存 DTO 和单个几何操作的契约测试用于检查行为，不作为工程样本或性能验收。不得在 CI 加入机器相关的毫秒/峰值阈值。

## 必须成立的开发约束

1. **减少真实工作。** 优化开发必须在至少一方面取得可测的明显提升；没有收益不能称优化成功。不得减少设备/来源覆盖、隐藏失败、跳过要求的任务或移动计时终点来制造收益。功能/正确性修正应控制回退，逐项说明必要成本，不用“数据更多了”自动豁免。
2. **先定位再改。** 使用已有阶段、队列、读取计数及 Profile 选择瓶颈。区分等待、CPU、原生 I/O、解码、提交和落盘；并发阶段总和不能当作墙钟耗时。一个优化方向的收益不能冒领同时发生的其他链路波动。
3. **浏览器不默认做重校核。** 新增或扩大 hash、顶点/三角形复核、全图/全表扫描，先满足[校验成本门禁](validation-cost.md)。无明确理由及代价说明不通过审查；不能为落实本门禁再添加一遍生产校验。
4. **保护已建立的结构与计数约束。** 共享路径索引、单次读取/解析、按需范围、任务合并、独立完成状态、失败隔离、源身份和旧结果拒绝均须保留。具体测试入口见下表。
5. **单独报告代价。** 软预算、缓冲区配额、线程数和采样完整性阈值是实现或证据约束，不是统一的性能总目标。不能把管理字节上限称为进程/Worker 堆硬上限。
6. **保留失败证据并收口。** 无收益/回退试验应撤回或经开发者明确接受，清理相关开关和死分支；不删原始报告来美化结果。已撤回试验不作为新基线。

## 现有自动保护与按改动选择

在 `desktop/` 使用现有入口选择对应测试文件或测试名；完整命令见[验证](../validation.md)。以下不是每轮必须全部执行的清单。

| 改动 | 保护行为 | 现有落点 |
|---|---|---|
| 包路径/引用 | 查询或 occurrence 增多，不增加全包枚举；文档与在途读取复用 | `entryResolver.test.ts`、`cbmParser.test.ts`、`check:engineering-boundaries` |
| 来源准备 | 慢根不挡快根；共享依赖读/解析一次；未引用文档不提前发送 | `devSourcePipeline.test.ts`、`engineeringService.test.ts` |
| 首批目录 | 后续缓存批次挂起时，首批 bounds 仍可消费，完整标记不提前 | `devLodRuntime.test.ts` |
| 普通模板命中 | 不重 hash 缓存、不回读原始来源、不再次扫描已有 bounds 的顶点 | `devLodRuntime.test.ts`、`devGlbTemplateRuntime.test.ts` |
| 几何/表示 | 模板复用、多实例矩阵、小构件兜底、局部失败与过期结果拒绝 | `glbCacheService.test.ts`、`sourceGeometryService.test.ts`、几何矩阵对应测试 |
| IFC | 单源解析、近景范围、可见性、连接分块和 WASM 所有权 | `test:ifc-critical`；真实引擎证据另由开发者选择 |
| 传输/缓存 | 有界输入、独占最终缓冲、按域保存、先发布后写、修订一致 | `engineeringSourceBatches.test.ts`、`engineeringTableJson.test.ts`、缓存/Worker 对应测试 |
| 绘制/交互 | 无变化不重绘；静态矩阵不重算；显隐、选择和相机可唤醒 | `demandRendering.test.ts`、`staticContainer.test.ts`、选择对应测试 |
| 生命周期/测量 | 输入回复不建伪任务；尾批确认；未完成/不可用不补零 | `hostWorker.test.ts`、`test:measurement-tools` |
| 线路/地图 | 合法暖包不重解析；缓存失败隔离；地图/树监听可释放 | `lineSemanticWarmFastPath.test.ts`、线路 parser/map 对应测试 |

这些测试已由现有 Windows CI 的单元/覆盖率、边界和测量协议步骤运行。测试名或代码迁移时同步维护对应关系；不要以测试总数代替行为覆盖。

## 本地性能决定

开发者选择样本、路线和重复次数，不默认追加完整 L0/L1/L2、独立复测或探针开销矩阵。先复用仍适用的构建和证据；新变化、失败或证据缺口才补相应复核。

比较须核对构建/EXE、样本 SHA、固定运行时、视口/动作路线、冷暖准备和计时策略。报告百分比、节省秒数、绝对耗时与整批耗时之和，不擅自加权。轮内保留增长与跨版本峰值增长分列；覆盖、PARTIAL 缺口、正确性和测量完整性独立报告。缺少条件的结果只作观察，不自动修补旧报告或批准基线。

**没有统一的时间、内存消耗总目标或增长比例自动验收线。** `gate`/`compare` 的结果是证据与人工审查提示，`optimizationAccepted` 不能自动变成 true。最终接受仅由开发者显式决定，不能要求默认重跑整个矩阵才能继续正常开发。

## 提交说明最小内容

- 改动方向、实际消除的工作和保持的正确性边界。
- 对应结构/计数检查、已有证据的复用范围，以及未验收项。
- 有本地实测时写清可比条件、每项收益/回退和内存代价；没有则明确待开发者复核。
- 涉及校验时，写清保护目标、失效依据、范围、频率、复杂度、复用选择和成本。

不要为了填表编造性能数字、真实样本真值或校验必要性；普通 UI 不展示这些开发实现细节。
