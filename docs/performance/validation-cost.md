# 浏览器校验成本

本页执行 [AGENTS.md](../../AGENTS.md#浏览器定位与校验成本) 的约束：没有明确理由，不新增或扩大高成本运行时校验。它是开发审查门禁，不是给 Viewer 新加一个 Validator。

## 校验变更的必要说明

| 问题 | 需要给出的内容 |
|---|---|
| 保护什么 | 具体失效模式、实际缺陷/可信威胁或现行契约；“可能坏”“更安全”不充分 |
| 在哪里做 | 输入身份、缓存边界、引擎句柄/内存边界、发布、离线验收中的哪一层 |
| 付多少次 | 每源/每修订/每键/每会话/每次查询；输入规模和时间/分配复杂度 |
| 能否复用 | 已知源 SHA、来源绑定、生产者结果、完成凭据、loader bounds、已有解析/检查是否足够 |
| 为什么在热路径 | 能否便宜局部检查、局部失败隔离，或移到明确需要完整复核的诊断/验收模式 |
| 代价证据 | 扫描/读取/hash 次数、处理字节/顶点数、驻留、相关本地阶段；不能只写“开销很小” |

无说明或不能解释重复校验的改动，不通过开发审查。门禁不要求额外向用户反复申请权限，也不在普通产品里增加确认或开发信息面板。

## 有具体用途与默认不应增加的工作

| 场景 | 边界 |
|---|---|
| GIM 源 SHA / magic | 用于输入类型、同名替换和缓存身份。复用已经建立的会话身份，不在每个模板/属性层再读源 hash |
| 外部可执行文件、冻结 Benchmark 构建身份 | 防止执行错误/被替换程序或比较错二进制；限定执行/验收边界，复用结果，不扩散为模型数据审计 |
| 长度/索引/引用、必要有限数值和资源边界 | 保护实际读取、WASM/数组边界、可表示坐标和失败隔离；检查实际使用的数据，不另扫未引用顶点 |
| 源/会话/修订/请求绑定、原子完成凭据 | 防止旧结果提交和半成品暖命中；不是标准符合性检查，也不是重新解析整个工程 |
| 普通暖模板命中重 hash | 默认不增加；已有键/源绑定和解码边界不能成为逐层重复全字节验证的借口 |
| 回读 STL，逐三角比较 GLB、法线/绕序 | 不属于普通浏览必经步骤；已移除的反向审计不能以“首次也应该校验”恢复 |
| 逐顶点 finite 审计、重复全场景 bounds/资源遍历 | 复用 loader bounds 和同一次检查结果；缺少 bounds 时的必要计算与已有 bounds 后再次审计分开 |
| 内部 Worker prepared 结果 stringify/parse/摘要重做 | 说明信任边界和数量/身份凭据；不因跨模块就再次序列化全图自证 |
| 工程交付标准完整校核 | 不进入普通 Parser/Core/编译器/首屏；独立能力需另行明确范围，目前不实现 Validator |

现有域摘要不构成任意叠加 hash 的许可，也不能不分析就全部删除。涉及现有身份/持久化检查的优化，要保留等价的保护，不把错误缓存当源事实。

## 自动与人工门禁

- `devLodRuntime.test.ts` 用有效暖命中确认额外 digest、源读取和编译调用为零。
- `devGlbTemplateRuntime.test.ts` 提供已有 bounds，阻止读取位置分量，确认检查与模板构造复用一次场景遍历。
- 来源计数、旧结果拒绝、坏条目隔离和 WASM 索引边界由对应现有测试守护；不能为了“少校验”破坏它们。
- 计数检查不推导毫秒收益；改变边界后仍由开发者选择本地复核。禁止为检查“有没有多 hash”在产品运行中再 hash 一遍。
